# 社区发现第一条链路：真实作品与人工精选

本批落实 [社区发现规格](community-discovery-spec.md) 的发现与导航部分。收藏、单层评论仍在后续链路，不提供占位按钮，也不把本批宣称为完整互动闭环。官网保留品牌视觉，并增加进入 `/community` 的主入口。

## 信息与接口

`GET /api/community?tag=&cursor=` 返回最新作品、人工精选、实际公开作品的标签计数。三个部分使用同一 MySQL repeatable-read 只读事务；页面与 API 均不缓存。卡片只取当前展示正式版的标题、作者填写的简介、标签、笔名及首次发布时间，不返回正文或历史版本元数据。

公开条件与现有作品入口一致：未作者隐藏、未作品级限制、当前展示版未受限。待后审的正式版不额外封禁。每次点击稳定作品链接仍重新判权；列表出现过不是授权。已加载的卡片可能随时间过时，不承诺跨请求原子快照，更不能用旧卡片绕过阅读权限。

最新按 V1 的 `published_at` 与作品 UUID 倒序，固定每页 12 条。修订、切换和恢复不更新排序时间。游标包含时间、ID、标签并校验格式、长度与标签归属；不以游标作为访问授权。标签计数只统计当前可公开内容；没有对应作品不捏造标签计数。

## 精选编排

首版最多六个手动位置，不填充假卡片，不宣称推荐效果。`GET /api/ops/curation` 返回当前编排及全组修订；`GET /api/ops/curation/{id}` 检查候选并取得作品状态号；`POST /api/ops/curation` 选入、移动或清空。

同作品最多占一个位置，放入已占位置替换原作品，提交前明确说明目标与替换结果。全组修订防止两个运营旧页面互相覆盖；候选状态号防止作品经过隐藏/恢复、发布或其他状态变化后仍凭旧预览选入。读写接口使用现有会话及服务端运营白名单，不让客户端自报身份取得权限。

迁移 11 添加：

- `works.discovery_revision`：公开资格代次；首次为 1。实际作者隐藏、作品限制、当前展示版限制在原业务事务中递增。
- 六个 `community_curations` 位置：记录作品、选入时的资格代次、操作者及时间。资格代次不一致时永久撤出该次选择；恢复公开、换健康旧版或撤销处置都不回退代次，需人工重新选入。
- `community_curation_state`：全组编排修订。其行锁只串行化这六个运营位置，不阻塞普通阅读。
- `community_curation_mutations`：会话操作者＋请求 UUID 的唯一确认及输入审计。编排、修订、审计确认同事务提交；丢响应重放先取原确认，不重新施加选择，不复活已撤出的精选。

历史非展示版本被限制不会撤出仍正常公开的当前精选。已有后审、作者状态变更仍遵循自己的行锁顺序；隐藏/限制只改作品代次，不再反向锁精选总表。精选写先锁总表，再锁候选作品，检查当下状态；与隐藏竞争时，不能留下隐藏后仍有效的选入结果。

## 界面与导航

桌面采用风格侧栏、精选区、下方最新作品多行区；手机用标签入口及双列文字卡片流。当前无封面上传，直接使用文字卡片，不拼接虚构图片或排行。空态、失败与重试独立，未能取数不当作“暂无作品”。标签筛选作用于最新列表，精选明确标记不限风格。

`AppHeader` 接入官网、社区、工作区、作品管理、发布、阅读、账号设置与治理页面。公共锚点宽度一致，阅读正文保持窄版；手机用可展开菜单，不把桌面导航硬挤成横向滚动。运营入口来自 `GET /api/me/access` 的服务端能力查询，实际运营 API 仍各自授权。页面内刷新留在对应标题区域，不让公共导航随页面动作变化。

## 验收与退出条件

工程验收覆盖真实 MySQL 的同时间分页、当前展示卡片、无正文泄露、隐藏/限制与恢复、非展示版限制、全组竞争、过时候选、重复请求、审计失败回滚、隐藏事件失败不误撤精选，以及 HTTP 请求/响应契约与角色边界。

浏览器在隔离 writing_test 服务验证官网进入社区、真实编排、丢响应重试、精选撤出、匿名 SSR、标签请求失败与重试、阅读返回社区、各工作区导航坐标和手机菜单。截图使用合成测试内容，不能当作真实社区运营数据。

本机升级先加密备份，再迁移、更新并检查网关实际入口。本批不部署 ECS、不推送远程、不造真实用户样本。通过后需用户本人操作社区与精选；完整“发现 → 收藏/评论”结果要等后续互动交付和非开发者真实任务验收。
