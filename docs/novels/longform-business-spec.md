# 长文／连载小说业务规格

日期：2026-11-03。状态：N0 规格基线。用户已授权规划长文业务；本文件不表示完整长文功能已经上线。N1-A 私密资料链路已接入，证据见[阶段复盘](../reviews/private-novels-review.md)；章节及后续能力仍未实现。执行阶段见[交付与验收](delivery-and-acceptance.md)。

## 1. 背景与业务目标

Tako 面向有表达和创作意愿的年轻用户。短内容、中篇、长文是独立入口，题材可以是幻想、冒险、日常、情绪、悬疑等，不以篇幅替代质量。长文解决持续创作、逐章阅读、追更和跨设备续读的问题，不能把整本小说塞进现有中篇正文，再用前端模拟目录。

首轮做免费连载闭环：作者建立作品并写章，读者发现作品并逐章阅读，加入书架追更、续读和按章交流；作者能隐藏内容、处理问题，运营能对明确对象限制和纠错。原先十万／二十万字是未来推荐申请的讨论示例，不是本轮章发布或开书门槛。

本轮不做付费、打赏、签约、推荐算法、榜单、广告、定时或批量发布、分卷、多人协作、自动拆书导入、跨书搬章、封面上传、周边、完整离线下载和系统推送。短帖关联自己小说仍是后续短内容链路，不能冒充已有功能。

## 2. 用户确认的决策账本

| 编号 | 已确认规则 | 直接约束 |
|---|---|---|
| N-D01 | 正式章节顺序固定，只能追加 | 不插章、不重排；隐藏不腾出序号 |
| N-D02 | 可隐藏单章，保留不可读占位 | 不泄露标题正文；恢复仍是原章，不自动跳转进度 |
| N-D03 | 按章两级评论，暂不做全书书评 | 不记录评论对应修订版本 |
| N-D04 | 明确“加入书架并追更”，可单独关闭追更 | 只做站内新章提醒，不发邮件或手机系统推送 |
| N-D05 | 登录后保存私密跨设备续读位置 | 游客不上传；仅本人可见，不向作者展示个人轨迹 |
| N-D06 | 完结不可恢复，后续另开作品 | 没有运营恢复连载的普通后门 |
| N-D07 | 完结后旧章也不可修订，但仍可隐藏 | 普通错字修改、标题修改和旧版回滚同样禁止；原有恢复隐藏权利不因此消失 |
| N-D08 | 整书隐藏期间的新章，恢复时补一条汇总提醒 | 仅涵盖尚未提醒且现在可读的新章，恢复旧章不提醒 |
| N-D09 | 仅平台要求整改可授权修订 | 指定章节一次受控提交，人工审核后替换；保持完结、不新增章、不发新章提醒 |

沿用既有权利：正式作品不由作者物理删除；作者可看和导出自己的受限内容；读者只保护当前已加载阅读，后续请求重新判权。两级评论删除与屏蔽按既有规则。未来付费章节永久书库承诺不等于当前免费书架获得永久访问权。

## 3. 对象与身份边界

| 对象 | 含义 |
|---|---|
| 书／Novel | 稳定书 ID、作者、书籍资料、连载状态、公开范围与目录状态 |
| 章节／Chapter | 稳定章 ID、所属书、正式序号；草稿阶段无正式序号 |
| 工作稿 | 作者持续编辑的私密内容，不是公开版本 |
| 发布预览 | 固定标题正文、来源修订和目标；后续工作稿修改不能暗改预览 |
| 正式版本 | 单章一次实际发布的内容，可追溯；不是整书快照 |
| 发布回执 | 原请求对应结果，处理响应丢失与重试 |
| 书架与追更 | 同账号与作品的关系、追更开关和订阅代次 |
| 续读位置 | 本人的章、内容版本、段落与偏移、位置修订号 |
| 新章事件／提醒 | 一次真正新增正式章节事件及其站内投递状态 |
| 处置／整改授权 | 明确书、章、版本或评论对象，保留原因与操作证据 |

所有私密查询、保存、恢复、导出和授权都从会话身份校验归属；客户端 owner_id、书名、章名和目录序号不能替代授权。书和章使用稳定 ID，改标题不能改变归属。

## 4. 状态与目录

书籍生命周期、作者隐藏、平台限制是不同维度。未正式发布的书仅作者可见；连载与完结是互斥生命周期。整书隐藏优先阻断读者入口，恢复不能清除平台限制；章节隐藏与平台限制也分别记录，撤销某一措施不能自动撤销另一措施。

正式序号只在首发事务成功时分配。失败回滚不消耗序号，已有正式章不移动、不复用。两台设备同时预览“下一章 N”：一个成功，另一个得到目录冲突，保留预览和输入，重新确认后再预览，不能静默改成 N+1 发出。

目录只含正式章节，不暴露草稿和未通过的首次待审提交。隐藏或受限章保留序号与“暂不可读”占位，不返回标题、正文、字数、私人处置原因。目录可分页，正文按章取，禁止返回整书正文后让客户端过滤权限。

发现页至少要求一章当前可读。全部章节不可读时撤出发现；既有书架记录保留不可用状态，不泄露旧标题正文。阅读位置仍指向原章，不擅自移到下一章。

## 5. 开书、资料与草稿

工程默认：书名最多 200 字符、简介最多 300 字符，标签 1～3 个，初始复用现有可维护的幻想、冒险、日常、情感、悬疑、科幻。标签不是已拥有内容的分类承诺。具体 Unicode 计数和字节上限在 N1 契约固化，客户端服务端一致。

开书先创建私密书，首次正式章节发布时同时确认公开资料。后续资料有独立编辑和明确发布，不因修改私密草稿自动公开。完结不阻止资料管理，但不能通过资料接口修改章节标题、正文或恢复连载；资料变化不顶最近更新、不发新章提醒。

复用 C1 的加密本机暂存、账号隔离、明确同步、版本竞争另存及未知结果恢复原则。单章正文暂按现有草稿 1 MiB UTF-8 上限作为工程候选，N1 必须实测和契约化，不在本轮虚构百万字单章支持。

新章离线可暂存，联网确认目标书和身份后同步。服务器旧格式中篇稿、章节稿必须可区分；不能把一个中篇稿误投成章节，或通过旧中篇发布接口绕过章状态。加密存储结构变化必须有兼容迁移，不能以生成新密钥、清本地库解决不兼容。

另一设备完结或限制作品，不应导致当前输入丢失。允许保留私密工作内容供导出、复制到新作品，不等于允许修改正式章；不会自动搬运追更者、评论和续读记录。

## 6. 固定预览与发布

预览绑定账号、目标书／章、服务端已确认的工作稿修订、预期目录状态；首次发书还绑定待确认资料。未提交预览有效 24 小时，到期重新预览，不能清理已提交、待审或正式版本。

首发事务校验身份、书未完结、当前目录状态与请求幂等，分配正式序号并写入版本、回执、所需审核任务与新章事件。首章同时完成书的首次公开；书处于作者隐藏时，即使允许发布也维持隐藏。

连载中的旧章可修订，仍是同一个章 ID 和序号；不产生新章事件，不顶最新发布／最近新章更新。长文首版读者只读取当前展示正文，作者可追溯自己的正式版本；不顺带引入长文历史正文开放开关和完整读者时间线。这是本轮范围裁剪，不改变已有中篇历史阅读权利。

未知发布结果沿用原请求标识查询，不能生成新 ID 再 POST；请求标识必须按业务类型、账号、目标隔离，中篇、章首发与整改不能串回执。确认发布成功后，当前状态 GET 失败应显示“发布已确认，状态暂不可取”，不能诱导重复发布。

## 7. 完结与唯一整改例外

完结前明确展示章数、最后正式章、隐藏／受限情况和私密未发布内容，强调不可恢复、禁止新章和旧章修改。零正式章不能完结；未完成的首次待审发布或普通待审修订必须先处理或取消，不能先完结后由迟到审核新增章或替换旧章。审核落正式版本的事务也必须重验完结状态；完结后仅指定整改授权可替换。已经形成正式版本的后审检查任务不因此自动阻止完结。

完结与追加、普通修订都以书状态／目录修订作并发条件：先提交者生效，另一方明确冲突，保留私稿。已落库的发布回执仍可查询。禁止通过后台普通操作或另一路由绕过锁定。灾难恢复是单独授权的运维过程，不宣称备份可消除恢复点损失。

完结仍可隐藏和恢复原章，恢复受其他限制约束。后续故事另开书，不自动迁移关系。

唯一修订例外是平台明确要求整改：运营记录处置、指定书／章／当前正式版本、原因和一次提交授权。作者准备私密整改稿，固定预览后提交；只能替换指定章，不能新增章、修改其他章或改变完结状态。必须人工审核通过才生成新的正式章版本。

授权一次提交被驳回后，保留驳回记录，旧正式内容不被替换；再改再交需重新授权。取消授权、目标已变化、跨账号或重复提交不得绕过；同一原请求重试仍返回同一结果。审核通过事务重新核对授权、目标、待审提交和处置，是否解除该整改对应限制必须明确记录，不能顺带解除其他限制或作者隐藏。

误判仍可走原文复核，撤销限制不强迫改文。普通错字不能借整改入口修改。整改成功不产生新章提醒或最近新章更新。完结入口须等这条纠错链路完成后开放。

## 8. 阅读、发现与搜索

长文有独立频道和作品卡片。新书按首次正式公开时间；最近更新只按真正追加正式章。隐藏恢复、旧章修订、资料修改、完结和整改不顶帖。首页沿已有原型延伸，不把未来榜单、搜索筛选、关注能力假装接通。

元数据搜索仅当前公开书名、作者笔名和简介；不搜章正文、私稿、历史版本或评论。保持既有中篇搜索语义，不能旧客户端一夜混入不兼容的小说对象。

读者打开一章后不因作者修订强行替换已加载内容；下一次请求重新判权。不可读章不自动跳过，提供返回目录和选择其他章的动作。目录工程默认每页 50 条，书列表 12 条，最终上限在 N1 冻结。

## 9. 私密跨设备续读

登录用户记录书、章、已加载内容版本、段落与偏移、位置修订。游客不上传，也不静默合并到登录账号；作者不能查看单个读者轨迹。位置不代表读完，不生成虚假的完读率。

只有实际阅读操作产生位置，预取不更新。合并频繁写入，页面离开或后台切换尽力提交；系统杀进程不承诺最后一瞬已同步。不要用滚动像素作为跨设备语义。

跨设备竞争使用修订条件；不能简单取最大章节号，因为用户可能重读前章。冲突保留本机位置与云端位置并明确让用户选择，不阻断正文阅读、不静默覆盖。正文修订导致段落定位失效时提示并从同章可用起点继续，不能套旧偏移或擅自读取受限旧版。

位置所指章不可读时保留私人指针，显示不可用并由读者选择；移出书架不默认删位置。离线只涉及已有位置待同步，不扩成整书离线下载。位置单位、合并频率和待同步保留期须 N3 前固化并验证账号隔离。

## 10. 书架与追更提醒

主按钮明确写“加入书架并追更”，原子且可幂等重试。关闭追更不移出书架。移出书架同时停止追更是工程提案，必须在 N4 表单明确提示并在评审中确认；不能隐藏副作用。再加入为新订阅代次，不补发普通历史章。

一次真正首发章产生一个事件。修订、完结、旧章恢复和资料修改不产生事件。站内提醒按订阅有效期与代次判定；关闭／重新开启不能串进旧订阅积压。只收到提醒不等于已读章。

整书隐藏期间的真正新章暂缓提醒；恢复后对尚未提醒且现在可读的新章发一条汇总，不逐章轰炸。重复恢复不重发；仍隐藏或受限的章不进入汇总，也不泄露标题正文。普通加入／重新追更不追溯旧章与隐藏期订阅者的应补提醒须分开判断。

工程方案优先 MySQL 事务 outbox 加维护任务，发布事务不逐个写粉丝通知，不先引入 Kafka。唯一键防重复投递；事件已落库、已生成通知、用户已读为不同状态。通知只存安全引用，展示和点击时动态判权。关闭追更停止新投递，已有消息不悄悄删除。积压、重试和失败可观测，但不凭无样本宣称可靠送达 SLA。

## 11. 按章两级评论

主评论、回复属于稳定章 ID，不记录对应正文修订版本。回复其他回复仍平铺在主评论下，标注回复对象。评论者删自己的主评论时明确提示并删除整串；删回复只删该条。作品作者可管理删除本作品评论；运营屏蔽主评论暂隐藏整串，撤销仅恢复未删除、未独立屏蔽的内容。

书或整章不可读时不允许读者获取／新发讨论。仅某个旧正文版本受限，不自动隐藏正常评论，与既有中篇规则一致。评论自身违规单独处置，不靠屏蔽正文版本代替。

已正常加载旧版时可评论当前章；提交前书隐藏、章受限则拒绝并保留输入。读者上下文只用于提交判权，不变成评论永久版本标签。工程上复用既有 1～1000 字符限制与原请求重试语义；App 评论只在内存保留，关闭不恢复。首版评论处置展示原因，不增加新复核链路。

## 12. 治理对象与权限

书级限制、整章限制、版本限制、评论屏蔽分开记录，按父级优先判权。后审、原因、撤销、作者可查看／导出、站内文字复核沿用已经交付的最小治理机制，不扩 B3.2 自动观察／模型识别制度。

未正式的待审首发与已正式后审任务不能同名混淆：前者未占正式目录，后者已有正式版本。读者不能看到待审或被处置的版本正文；作者自己的管理记录与受限正文仍可用。

运营对某个版本解除限制，不恢复作者隐藏、不解除其他独立案件；整改授权更不是全书编辑通行证。没有真实违规样本时只报告能力与测试，不报告治理业绩。

## 13. 契约和存量兼容

以下是能力分组；私密书籍资料和原请求回执已在 N1-A 实现，其余仍为候选。各期确定精确 URI、schema、分页和错误码，并更新唯一事实源 backend/internal/contract/openapi.yaml、生成声明与路由覆盖测试。

| 能力组 | 必要语义 |
|---|---|
| 作者书籍与资料 | 会话归属、资料稿与正式资料、修订条件 |
| 章节工作稿 | 明确书／章类型、CAS、加密本机目标映射 |
| 预览／提交／回执 | 固定快照、期限、原请求与业务目标隔离 |
| 隐藏／恢复／完结 | 分维度权限、不可逆确认、竞争失败保留内容 |
| 公共书籍／目录／阅读 | 分页、父级判权、不可读占位 |
| 频道／搜索 | 当前公开资料、稳定分页、旧中篇兼容 |
| 书架／追更／位置 | 私密归属、代次、冲突与重复请求 |
| 站内提醒 | 动态安全展示、幂等、已读与阅读分开 |
| 章评论／治理／整改 | 两级删除语义、精确对象、独立授权与审核 |

不能静默改现有 PublicWork 正文字段成为目录，也不能把旧 works.source_draft_id 唯一关系直接当一本书多章模型。N1 ADR 必须裁决书／章与旧 Work、Draft、Comment、Case 的物理关系、唯一键和外键、迁移与回滚、旧 App 兼容。此刻不预占迁移编号，避免并行端冲突。

## 14. 失败、容量与可观测性

并发、幂等、请求丢失和跨账号场景见验收表。400、401、403／404、409、410、429 和临时服务失败须有稳定语义，不能全部变成“发布失败”。未授权资源默认不泄露存在性；已确认发布与当前查询失败分开。服务端重新判权，不依赖按钮禁用。

配额和上限在 N1 契约冻结；超限保留草稿，不截断正文、不用字数替代低质判断。目录分页、按章加载，合成千章书验证查询和返回体；测试规模不等于杭州 2 核 2GB 的生产容量，也不需要启动已停 ECS。

日志只记录服务端请求 ID、固定路由模板、状态、耗时和错误类别。禁止正文、私密标题、邮箱、原始搜索参数、Cookie 和凭据；监控标签不放任意书／章／账号 ID。发布冲突、未知回执、通知积压和授权失败可定位；不采集个人阅读轨迹给运营。

## 15. 完成口径与待定出口

规格完成不等于接口完成，接口完成不等于 App 接线，模型／DOM 不等于真机。真实用户结果另记：外部作者是否完成一章发布，读者是否找到作品并续读、追更是否促成回访；尚无样本就写无。

P1／N1 前：物理模型 ADR、兼容迁移、计数上限、错误语义、共享触点确认。
P1／N2 前：首发序号与回执竞争、最小限制与撤销、公开权限验证。
P1／N3 前：段落定位和同步策略、完结竞争与整改完整链路。
P1／N4 前：移出书架的追更副作用评审、隐藏期补发和订阅代次细则。
P0／受影响真实作者交付前：由并行端报告输入、离线、账号隔离、并发与导航的实际设备证据。主开发不承担打包／USB／真机。
P1／对外运行前：恢复演练、资源容量、不可逆提示与生产入口另行评审，不以本机 Compose 代替生产部署。
