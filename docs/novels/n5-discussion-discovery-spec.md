# N5：按章交流与长文发现收口

2026-11-05。基线55ee71e，当前运行API0.28/迁移26。此文件是完整业务包规格，不是全部实现声明。主开发持有非Agent后端、契约、App、CI及设备任务；同事仅Agent/评测。本轮不启动ECS，不发送外部消息。

## 1. 目标、用户与范围

读者找到长文、进入一章阅读后，可以在该章发表主评论、展开两级回复，再从本人入口管理删除与查看处置原因；作者和运营能处理明确的评论对象。评论属于稳定章，不因正文修订迁移。长文元数据搜索让读者按书名、作者笔名、简介找到作品，旧中篇发现和搜索仍独立。

本包包括章评论与最小治理、实际App章底讨论/我的评论、现有Web运营评论入口的长文分区、长文频道分页与独立元数据搜索。不上全书书评、点赞、第三层回复、编辑、评论通知、复核、正文检索、推荐排名、离线正文、支付或生产部署。已有N4消息继续仅新章，不顺带扩评论通知。

## 2. 确认权利与工程默认

| 事项 | 规则 |
|---|---|
| 评论归属 | 书ID＋稳定章ID；不记录、公开评论对应的正文修订版本（N-D03） |
| 两级 | 主评论下回复平铺；回复某条回复只标记目标，不出现第三层 |
| 删除主评 | 评论者删本人主评或作者删本章主评时，明确确认所有回复一起删除，不留公开孤儿 |
| 删除回复 | 只删该条，其他回复保留；目标消失后不展示其旧身份，不自动改发对象 |
| 作者管理 | 作者可删自己作品下评论；作者身份由书归属决定，不能靠客户端owner_id |
| 运营 | 屏蔽主评整串不可见，撤销仅恢复未删除/未独立屏蔽内容；评论自身违规单独处置 |
| 内容限制 | 只限制一个非当前旧正文版本，不删除已有正常评论；书/整章当前不可读时读者不能绕道取讨论 |
| N-D21 | 当前展示版受限导致章入口不可读时，已加载正常旧版也不能新评，保留输入；仅保护已加载阅读 |
| 普通修订 | 旧版正常、书/章与当前展示均正常时，旧版加载者可继续评论；原阅读上下文只临时判权 |
| 完结 | 不额外关闭正常章讨论，不向读者暗示能恢复连载 |
| 输入 | 仅内存，关闭App不恢复；账号锁/同号确认/换号清除沿用现有CommentEditor |
| 内容与频率 | 纯文本1～1000 Unicode字符；沿用账号每分钟5次上限，幂等原请求重放不占新发表次数 |
| 排序 | 工程默认主评按服务端序列倒序、回复正序，各20条；不加热度排名 |

账号观察期目前约束作品发布，不借此自动引入读者评论先审制度。没有样本时不增加灌水阈值/自动封禁参数。原处置原因对本人和运营可查，对普通读者不公开；评论首版不提供复核。根评论屏蔽与子评论删除竞争必须有确定结果。

## 3. 正常路径与输入保护

游客可读当前公开章与讨论，也能先输入；登录后必须明确确认是否带入游客文字，不能自动发表。登录者只有主动点击发表才发送。回复对象必须来自同章正常主评/回复；跨章、已删除、被屏蔽、根被屏蔽均拒绝，保留输入，要求用户重新选择，不自动降为主评。

受理响应丢失时保留内存中的原mutation_id、账号、章、正文、上下文和回复目标，只允许核对/同载荷重试，不产生新标识。已确认后列表刷新失败只提示刷新失败，不能宣称发表失败并引导重发。关闭App后内存消失，重开先读服务器，不自动补发。

同号重新登录可以明确恢复当前进程内输入；换号清空，不呈现/提交旧账号内容。主动离开时沿用已有丢弃确认，收起面板不算离开。系统杀进程不能保证提示，也不冒充自动保存。

## 4. 身份、读权与删除

公开列表先在同一只读事务检查当前书/章/正式展示可读性，再读主评或回复，过滤删除/屏蔽及根状态。不通过本人评论入口回显别人的回复或不可读章标题。本人管理只可见自己的评论、已删除标志和本人处置原因，不复制章节正文；自己的删除动作不因父章被隐藏而丧失。作者的管理权限不等于读者权限，作者可按归属处理本人作品评论；运营入口不读取私人工作稿。

提交先验证服务端签名阅读上下文绑定书、章、正式版本，域与中篇隔离。事务锁当前账号、书、章及评论对象，重验N-D21、源版本及回复/根状态。token不是永久访问权、也不是“读完”证据；评论表不存正文版本或token。复制别章token不可评论目标章。

删除与新增回复竞争沿同一书/章锁顺序：回复先提交则随后随根删除，根先删除则新回复拒绝；不产生公开孤儿。删除抹除评论正文，审计保存操作者/动作/原因，不以删除回收评论ID或原请求。运营撤销不能恢复已删除正文。本人已删除请求重试返回原结果，不能因多次点击重复递增或复活。

## 5. 数据与兼容策略

既有work_comments通过真实外键绑定works，不能把章ID塞进work_id或把小说伪装成中篇。章节评论使用独立表与明确chapter_id/novel_id；根和回复约束同章，书章关系也由外键和服务双重保证。复用成熟会话、幂等摘要、错误、分页模式及App内存编辑器，不为两个领域搭通用社交平台。

迁移27仅新增章评论/动作/原请求及必要组合索引。旧中篇数据/契约不迁移、不清空、不混入新接口。新业务非空时回退拒绝，不能删用户讨论求回滚。升级前按重启手册备份/独立恢复，保留卷和凭据。原请求摘要包含动作与目标，不接受跨章/跨账号重用；原回执与当前公开状态分别读取。

## 6. 服务契约和错误

候选路径（交付以OpenAPI为准）：GET/POST /api/novels/{id}/chapters/{chapter}/comments；GET /api/my/chapter-comments与GET /api/my/novels/{id}/chapter-comments；POST /api/chapter-comments/{id}/actions；GET /api/ops/chapter-comments；POST /api/ops/chapter-comments/{id}/actions。作者管理需按本人书过滤，不能让普通用户获取全局评论。

返回应有稳定书/章/评论ID、作者笔名、根/回复关系、正文、序列/修订、时间、可删除与状态；公开响应原因清空。列表20条、游标有界，根锚点必须属于目标章。首版不返回虚构总评论数。

400载荷非法；401登录必需；403运营或同源拒绝；404无权限/不可读对象；409回复对象或修订变化、阅读上下文无效、原标识换载荷；429限频；503功能关闭/暂不可用。失败不暴露正文、token、邮箱或查询参数。一个API包括实现、OpenAPI、路由覆盖和请求响应契约、真实MySQL失败验证，不只写路径说明。

## 7. App与运营布局合同

沿现有原型、主题与CommentsPanel交互；章正文用原FlatList，不嵌套无限滚动大评论列表。章底有讨论入口与真实空/加载状态，展开面板包含主评和按需展开回复。关闭回到同章和原阅读位置；目录/消息/书架来源返回继续保留。评论面板与续读稳定视口互不伪造进度。

主任务是读章与交流：不加大块说明卡、装饰箭头、版本标签、假数字或彩色状态堆叠。主评作者/正文/时间有层次；删除次级动作，根删除二次确认明确影响。错误靠近输入/动作，能理解文字仍在。

“我的评论与原因”保留中篇入口，新增长文分区而非把不兼容对象硬混分页。Web运营同样分区，最小筛查/屏蔽/撤销/原因与原请求反馈同链路交付，不要求把运营后台移植手机。页面切换可往返、共用导航对齐；空、失败、禁用、权限改变、账号切换均有状态。

## 8. 长文搜索与发现

仅搜当前公开书名、作者笔名、正式简介；不搜邮箱、私稿、章正文、历史资料、待审资料或评论。1～64 Unicode字符，空/控制字符拒绝，大小写归一；参数化SQL，百分号/下划线按字面搜索，不当SQL通配。12条按稳定首次正式发布时间倒序，游标绑定归一查询；修订/恢复不顶帖。已有长文列表与旧中篇搜索兼容，不把它们一夜混成新对象。

搜索入口位于长文频道，返回频道；结果打开目录后能回原查询，返回时保留查询与已加载列表，显式刷新时重判当前可读。现有频道分页保持有界。暂无搜索热词/历史或个性化排序，不先引入ES/向量库；先验证当前数据规模的查询边界与耗时，超时明确失败，不当空结果。搜索和章讨论是同一N5包的两条链路，可在共享契约检查点拆阶段，但不逐函数Git循环。
