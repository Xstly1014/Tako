# N2：章节发布到逐章阅读

2026-11-03，完整业务阶段规格；尚未开始N2实现。规则源为[长文业务](longform-business-spec.md)、[预约审核ADR003](adr-003-chapter-publication.md)，新增权利N-D11/N-D12已由用户确认。

## 目标与完整主线

作者开书并确认章稿已同步 → 准备固定预览 → 核对候选章号与资料 → 明确提交 → 已公开/待审结果 → 本人章管理 → 独立审核与纠错 → 读者长文频道 → 书籍目录 → 一章正文 → 返回目录/频道。

阶段退出必须能完成这条链路，包含最低治理和失败恢复；可以拆提交，但不以单独API、按钮、空目录或原型截图宣布N2完成。N1本机私稿始终保留，正式操作不改正文；中篇C1/C2/M1～M5照常工作。

## 作者确认界面

- 从指定书/章、本人已同步服务端修订进入；有未同步输入时明确不纳入本次快照，不能暗取旧稿冒充最新。
- 固定预览显示正文/标题、来源修订、首次提交的候选号或同章已有号、预计V、审核模式、隐藏/受限影响及首份书籍资料。无正式发布授权时不能直接提交。
- 正式标题/正文不能仅空白，沿N1的200码点标题/1MiB正文上限；短篇幅可提示，不把字数直接当作低质判断或强行截断。
- 新章候选号不是已预约；另设备先受理同号后，当前提交409，保留固定内容，作者重新预览/确认新号。不能静默N→N+1。已预约章重提不因别章占更大号而冲突。
- 普通模式结果分别为“正式版已发布”和“当前可能隐藏/受限”；观察期显示“第N章已受理待审”，不可写成正式版成功。审核通过结果才有实际V和首次发布时间。
- 原请求发送前持久化最小确认标识，正文固定存在服务端；未知结果重进只查原标识，不再随机POST。确认成功后现状读取失败单独重试GET，不能退回未知发布。跨账号不能恢复/提交他人标识。

## 管理、审核与资料

本人可看未审核和受限的固定内容/原因，读者不能。每章一个当前pending、全书可多章pending，替换/撤回/旧审核竞争按ADR003处理。目录显示章ID、固定号、正式/待审/驳回/隐藏等必要状态；工作稿与这些固定内容分别展示，避免将待审正文当公开正文。

读者初始不开放长文历史版本切换或读者时间线；作者仍能追溯本人版本。旧章修订保持号和章ID，当前已加载读者不被替换。书籍资料单独明确发布，不能通过章提交覆盖已有正式资料；第一个正式章可为2，首份资料采用该章确认的快照，后到1不回滚。

运营对明确书/章/版本限制、撤销、填写原因；作者按既有站内文字复核处理。同一处置仅一条处理中，既定冷静期/主动撤销规则沿用，不新增附件、消息或App运营权限。N2治理是公开内容的必要纠错，不新增无样本的复杂自动制度。

## 读者行为

App长文频道显示真实公开书，不混入中篇PublicWork；至少一章当前可读才可发现，空列表是真空态。书籍页显示正式资料、作者、正式章数量与目录，不用预约数冒充总章数。第一章可为2，缺号合法，未公开槽位不显示“待审核”或私密标题。

目录50条/页、正文按章读取；隐藏/受限的正式章只保留安全占位。书列表12条/页。失败不当空列表、分页错误保留已加载项/原游标；跨号/隐藏/直链/父书限制全部服务端重新判权。返回保留列表现场；不可读章提供回目录/选择其他章，不自动跳章。

游客可读公开正文，不上传位置；本期不做离线正文缓存、跨设备续读、书架追更/通知、按章评论或搜索。这些分别N3～N5，保留明确未开放，不添加假数字。书和章隐藏/恢复均不顶最近新章更新，A1晚通过则按其首次发布算新章更新、目录仍在B2前。

## 契约候选与归属

下列是实施清单，不是已交付接口。实现时一次交付源码、唯一OpenAPI、生成声明、错误语义和真实MySQL/HTTP失败验证，不仅补Markdown。

| 接点 | 必要语义 |
|---|---|
| 本人章预览／受理／回执 | 书/章/修订/固定内容/候选号/幂等目标隔离；24h过期重新预览 |
| 本人正式资料发布／章版本管理 | 私稿/公开资料独立，CAS状态，隐藏与平台限制分维度 |
| 章审核及处置／复核 | 当前提交ID，旧审核拒绝，多pending独立，具体对象/原因/撤销 |
| 公共长文列表／书籍／目录／单章 | 独立Novel类型，父级权限、安全占位、12/50分页、仅当前正式正文 |

候选路径放/my/novels、novels和小说专用运营命名空间；不扩中篇/my/works来塞多态书籍。N1章稿routes继续兼容；新模块放backend/internal/novel及mobile/src/novels子域，不接管同事publication/author-works或其整条验收夹具。

错误类别：400参数/游标，401未登录，404资源无权或公开不可读，409预约/源修订/状态/旧审核竞争，410预览过期，413正文上限，429原限流，503临时不可用。细分code在实现契约固化；回执不等于现状，安全错误不含正文/原始查询/凭据。

## 三段交付与验收出口

1. **N2-A 固定发布与独立审核内核：** 模型/迁移/契约、预约、重复/竞争、受理与正式回执、资料首发、待审替换/撤回及审核；旧稿/旧中篇兼容，公开App入口暂不打开。
2. **N2-B 公共阅读与最低纠错：** 安全书列表/目录/正文，隐藏与分层限制/撤销/文字复核，千章缺号/晚通过/占位/分页验证。治理齐备后才开放公共能力。
3. **N2-C App完整接线与真实服务联调：** 实际N1编辑→固定发布→回执→管理→长文发现/目录/阅读/返回，用同一批合成数据验证，不靠拼接各自假JSON。未知结果、切号、迟到读取和作者/读者权利交叉覆盖。

必须执行N07～N17、N41～N46，另验证同章pending替换只保留一候选V、B先通过的首份资料、隐藏首次发布不假装可读、各限制独立撤销、完结接口仍不可用。千章是数据/查询和展示证据，不等于生产容量结论。

编译/模型、DOM、真实HTTP/MySQL、迁移恢复、原生、真实用户分别记账。主开发负责前四及集成，设备由同事待用户恢复条件后处理；不要求用户每次手测。每个子段推送刷新handoff和设备任务，实际条件未满足就记未验，不消除或冒充通过。
