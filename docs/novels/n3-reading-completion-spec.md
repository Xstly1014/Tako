# N3：私密续读与完结整改

2026-11-04。主开发连续业务包规格。基线main `89d83eb`（API0.22.0、迁移21），三条远程CI已成功。N2工程链路已接真实服务；原生已按用户新分工转主开发，设备可用再验，不把本文件写成N3已交付。业务基线为[长文规则](longform-business-spec.md)的N-D05～09、N-D13及[验收矩阵](delivery-and-acceptance.md)N18～28。

## 目标与范围

读者换设备后能明确回到自己上次的位置，位置冲突不覆盖本人选择；作者能不可逆地完结作品，同时保留平台指定章节整改这一必要纠错通道。首版免费、不提供整书离线下载、不记录完读率、不向作者提供读者个人轨迹。书架追更/通知N4、按章讨论/长文搜索N5、自动低质治理、付费、生产部署不混入本批。

一个连续交付包包含位置服务与实际App接线、完结核对/确认、运营指定整改/作者固定提交/人工决定、必要契约/失败与真实服务整条。内部任务允许局部提交，不要求用户反复说继续。不能只交完结按钮再把整改无限推后。

## A. 阅读位置的语义

每个会话账号、每本书一个云端位置：稳定章ID、实际加载的正式内容版本、定位算法版本、段落序号、段内Unicode码点偏移、单调递增位置修订与服务端保存时间。位置不是章序号，也不是像素、百分比或读完证明。客户端时间不决定冲突胜负。

工程采用明确版本的文本定位规则：换行标准化为LF后按换行形成逻辑段落，保留空段，段落0起算；偏移按Unicode码点而不是UTF-16索引计数。表情/组合字符不截断代理对；原文及原哈希不因定位标准化改写。渲染的长段拆块必须保留到原逻辑段落/码点的映射，不能把现有readingChunks的每2000字符块号当永久段落号。定位规则以后变化必须拒绝误套旧算法，明确回同章起点。

App自动记录首个稳定可见段落起点，按真实阅读滚动/跳转而非预取更新；不承诺精确到屏幕某个字。工程默认停留2秒后视为稳定，活跃阅读最多每10秒合并一次写入；离开/进入后台尽力提交，系统强杀不承诺最后一瞬同步。离线持久化是否开放等待上表裁决。不能每像素一次API，也不能靠服务器猜测翻页。

保存只对本人会话，不接收owner_id。首次写base_revision=0，后续CAS；重复同mutation及载荷返回原回执，同标识不同载荷拒绝。写结果未知先查原回执，不创建新标识重发。云端位置读取失败不能当没有位置，进而以0修订覆盖。

目标必须是实际正式章和其曾公开过的固定版本，段落/偏移必须落在对应正文范围。受限旧版不通过定位接口返回正文或标题。客户端伪造位置没有业务奖励，但仍需校验身份、章归属、版本与范围，避免私稿位置泄漏。已加载但后来不可读时，不发新的内容请求，当前阅读保持；位置同步受动态权限约束。位置读取的不可用投影不带旧标题或正文。服务端仅在当前章和来源正式版本仍可读时受理新位置；隐藏或限制后保留本机候选，拒绝新的保存，不以已有正文获得新的读取权。

## B. 跨设备、正文修订与不可读

冲突返回可解释的当前位置修订；本机候选保留。两种明确选择：采用云端位置，或以刚核对的云端修订提交“使用本机位置”。再次竞争仍提示，不能循环强制覆盖。选择位置不妨碍继续读当前正文；旧设备迟到不能静默倒退云端位置。

继续阅读先重新获取章的当前公开版本。版本一致才使用段落定位；版本变化不做隐式模糊匹配，提示“本章已修订，从本章开头继续”，读者明确进入。章/书隐藏或受限保留原私人指针，提供返回目录/自行选章，不擅自下一章。不允许通过旧位置接口读到被限制版本。

游客位置不写服务器，也不静默并入登录账号。换账号立即隐藏位置及候选、废弃迟到结果；会话失效等待同账号重登。作者/运营常规工具没有读某个读者进度的接口。移出未来书架仍保留位置。

## C. 完结前核对与不可逆确认

入口位于现有正式书籍管理的次级设置动作，保持已确认的紧凑章节列表和标签。先向服务器取得一次核对摘要：正式章数、最后正式章、最后预约号、隐藏/限制数量、当前待审数、未发布私稿提示、当前书状态及核对标识/期限。摘要不把“最后预约章”冒充“最后正式章”。私稿只是提醒，不允许将私稿自动发布或删除。

工程候选为24小时内有效的固定核对记录，绑定会话作者、书及公开/提交状态指纹；确认事务重新核对而不是只信摘要的章数。若实施时现有state_revision不能覆盖章发布变化，应在同一书锁下比较正式/待审状态，不把漏掉章变化的revision当并发保护。续读服务占用迁移22；完结核对/授权表的后续迁移号在fresh协作核对后分配，不重复占号。

确认页明确“完结后不能恢复连载，旧章不能普通修改，后续故事需另开作品”；只在正式章数大于0、没有普通pending时可确认。后审任务不等于首次待审，不自动阻止完结。隐藏或受限章不阻止，但数量和影响必须在摘要提示。书籍资料仍可按原审核方式管理，不能用它改章标题/正文或恢复连载。

完结与预约新章、正式修订、审核落版、资料发布共用既有书锁/账号锁顺序；先到者完成后，另一方重判。已发布后摘要过旧必须要求重新核对，不静默完结新内容。完结只写生命周期、状态/审计/原回执，不产生新章事件，不顶最近更新，不解除限制。未知结果仅查原命令，成功后的当前状态读取失败不重发。

所有普通发布入口（包括旧预览、原生与HTTP直接调用、审核通过）都重验completed_at；不是隐藏按钮就算禁止。工作稿及加密离线内容继续保留和导出，用户可另创作品；不会自动搬迁评论、章节号或追更者。

## D. 平台指定章整改

授权只能由运营从一个实际未撤销的书/章/版本处置发起，明确完结书、指定正式章、基准正式版本、关联处置、原因与授权标识。不能以普通错字为理由给完结书开放任意编辑。首版不支持批量、跨章、跨书、运营代写正文或普通恢复连载。

每章同时至多一个有效授权/整改候选。授权状态独立：可提交→已提交→通过或驳回；可提交时可取消，提交后取消须撤销当前候选，旧审核拒绝。目标正式版本或关联处置发生变化，授权失效或要求重新核对，不能替换新目标。数据不物理删除，原因和操作可追溯。

作者可以从私稿准备整改正文；审核方只能读取明确提交的固定快照。整改预览绑定授权、书/章、基准正式版、来源服务器修订；24小时未提交预览到期重新核对，不消耗授权。正式提交事务消耗一次授权，固定候选，不允许像普通pending一样反复替换；响应未知仍沿原请求恢复。正文不进操作journal。

运营人工通过时再次核对当前授权、提交、基准正式版、关联处置；只创建指定章的新正式版本，完结状态、章号、其他章节和私稿均不变。不产生首发章事件/提醒，不顶最近更新。该版本本身不是未经审查的后审任务。是否同步撤销关联处置采用用户本轮裁决；无论选择如何，不能清作者隐藏或其他独立限制。作者恢复仍需满足现有全部可读条件。

驳回记录原因，正式原文不变，授权已经用完；作者后续修改保留，重新提交须运营新授权。误判仍走原文复核，不能强迫以整改替代申诉。重复通过/驳回/取消、迟到审核、撤销关联处置、完结与源变化都必须具备CAS/固定载荷回执和明确冲突。

## E. 接口与存量契约计划

下面仅为待实现能力，不代表已发布路径；`backend/internal/contract/openapi.yaml`始终是唯一HTTP事实源。位置单独域、完结单独命令/回执、整改单独授权/提交，不能用中篇version0或原章节普通发布回执冒充新业务。

| 能力 | 必要输入/输出与错误 |
|---|---|
| 本人续读查询/保存/原回执 | 从会话身份取账号；书/章/正式版/locator/CAS/mutation；不可用位置安全投影；401/404/409分明 |
| 本人完结核对/确认/原回执 | 固定摘要、绑定书、有效期、不可逆确认；过期410，状态/待审竞争409 |
| 运营整改授权/取消及列表详情 | 实际处置上下文、指定章/版、原因、CAS、不可变回执；普通作者无运营权 |
| 作者整改固定预览/提交/撤回与原回执 | 归属、同章、单次授权、固定快照、24h、原命令隔离；不可另发新章 |
| 运营整改待审/人工决定 | 固定候选、理由、目标和关联处置重验；不串普通先审队列 |

旧中篇契约保持；现有公开章响应不因新增私人位置泄漏用户身份。需要新增内容定位字段时采用可兼容版本标记；旧App读取行为保持，旧版不能通过普通发布绕过完结。迁移只加法，回退有业务数据拒绝；密文升级不清库、不换密钥抹输入。
