# ADR003：章号预约、独立审核与正式阅读

2026-11-03。N2实施裁决，固定预览/受理/独立审核内核已开始实现；不是完整N2已交付声明，证据见[连续实施记录](../reviews/n2-publication-implementation-review.md)。业务基线N-D01～N-D12，[阶段规格](n2-publication-reading-spec.md)。N1独立书/章稿结构不变，不把长文塞入中篇Work。

## 1. 章号不是审核通过次序

用户明确多章可同时待审、互不阻塞，且作者提交顺序优先。首次提交事务受理时为稳定Chapter预约ordinal；首次通过才有正式版本。A先受理为1、B后受理为2，B先通过即第2章；A后通过补入1，B不改号。驳回/撤回不退号，同章重提沿号，新章不能顶替。

事务未提交的参数/权限/竞争/数据库失败不占号；已受理后的驳回不等于事务失败。恢复副本有新Chapter ID，提交时只能预约新号。私密建章/保存不预约，预览也不预约。

新号以书行锁和预览expected_last_position作竞争条件，稳定章号唯一约束为(novel_id,ordinal)，序号仅递增。原请求回执先按账号与操作目标核对，重复提交不占新号；失败/重新预览不能把未知请求变成新请求。已预约章的重提不重新比较“最后预约号”，否则后续章会错误阻塞早章整改。

## 2. 三次不同的状态变化

1. **准备：** 固定章稿服务端修订、正文、标题、书/章/账号、候选正式版本、已有章号或下一个候选号。新书还冻结待确认书籍资料。24小时有效，不公开。
2. **受理：** 校验原预览和原请求，预约新号或沿原号。正常作者可同事务成为正式版并产生后审任务；观察期作者只形成首次待审/修订待审，不产生正式版和新章事件。
3. **审核：** 精确检查当前pending提交ID与内容指纹、章目标、书未完结及其他适用限制。不同章可独立通过，不能比较一个因别章发布而增长的全书目录revision来拒绝早章。旧pending被替换/撤回则审核返回冲突。

每章最多一个当前pending，多次修订替换该章当前pending，保留审计但不多加正式版本号；不同章的pending不互相替换。驳回留记录、工作稿不被回滚，重提须新预览/明确确认；原回执仍可读。撤销作者观察期不自动公开已有pending，沿既有规则继续人工审核。

## 3. 新书资料与时间

首个实际产生正式版本的章建立书的首份正式资料及first_published_at，可能是ordinal2。每个首次预览展示固定资料，并说明“若其他章已先发布，不替换已有正式资料”。后到的ordinal1审核不倒退资料或首次时间。后续资料走独立明确发布，不通过章修订暗改。

正式发布不等于当前可读：书隐藏、章隐藏、平台限制分别生效。即使首个正式版处于隐藏，时间也记录实际正式提交，不用恢复时间把它顶为新书。资料、章号、实际首次发布、新章事件分别建模。

“最近发布的章”按首次落正式版的时间；“目录最末章”按ordinal，不能混用。A1晚通过是一次真正新章发布，N4可据事件提醒；不是B2重发。旧章V2/资料/隐藏恢复均不生成新章事件。

## 4. 物理边界与兼容

实施时独立维护正式书资料、章固定预览、提交/审核、正式版本、回执和管理事件，使用稳定书/章外键。候选实体novel_publications、chapter_previews、chapter_submissions、chapter_versions、chapter_publication_receipts及小说处置表，最终DDL随N2实现交付，不在规格阶段占迁移号。

章号与章身份绑定；章版本唯一键(chapter_id,version)，回执按(owner,mutation_id)并含操作/目标/载荷指纹判重。预览指向N1章稿，不依赖章历史清理后仍存在的正文；保留固定文本。事务内同步写首次正式事件以便后续N4消费，当前不部署消息队列或假通知。

中篇的作品/回执/治理表及M3目录契约继续独立。读者Novel/Chapter类型独立于PublicWork，旧中篇客户端不会收到新型对象；不手拼生成声明。N2仅改小说schema片段，与同事M3原GET本人作品的片段保持已协调边界。

## 5. 公开目录与权限

公开目录只选已有正式版本的章，ordinal升序，50条游标分页。未过审/驳回/撤回的首次章不出现，目录可缺号；不能返回其标题、字数、原因或pending数量。已正式章被作者隐藏/平台限制时保留ordinal和通用不可读占位，其他字段不泄露。数量按正式章计，不用最大预约号冒充章数。

每次正文/目录/书卡片请求重验父书和章权限；公开展示只取当前可读正式版，作者私有读取另走归属验证。新请求不可读返回通用404，已加载阅读不强清/偷偷换版。下一章以目录合法可读项由读者主动选择，不自动跨过不可读章。

实时分页不承诺跨请求冻结：晚过审的A1可能位于已翻过的范围，刷新首屏才能看到；不重新编号解决分页。静态千章验收要求无漏项/重复，并发场景则验证边界与刷新语义。

## 6. 最低治理与退出

首次公开前交付书、章与章版本的精确限制/撤销/原因留痕，作者能查看本人固定内容/处置并按既有文字复核规则纠错；权限和处置不能仅靠按钮禁用。不同限制不连带撤销，普通撤销不自动恢复作者隐藏或切换展示。

服务端限流、原观察期、前审/后审按现有语义复用；不在本阶段添加自动低质算法或LLM审稿。隐藏可继续受理/审核，但绝不顺带恢复公开。完结与指定整改须等N3一并实现，不开放不完整按钮。

N2完成依据为同一版本的契约/真实MySQL/实际App客户端与组件验证、千章目录与失败恢复；不以本ADR或空路由算交付。迁移、结构回退拒绝和旧中篇回归沿N1标准。原生另交同事，ECS/付费/推荐/离线下载不在范围。
