# C1-C · 编辑页与发布页交接

2026-11-02，主开发维护。基线 47510be；复用并行端维护的 `docs/handoff/c1-c2-interface.md`，本文件只说明 C1 调用与返回，不复制 C2 状态机或改变业务权利。

## 当前输入的确认门槛

编辑页“准备发布”只在当前账号已在线确认、原账号归属匹配、当前输入等于本机记录、没有本机保存/同步进行中，且记录 clean/pending=null、有合法服务器 ID、正修订和确认时间时可用。离线许可不授予发布资格。恢复副本若仍 dirty，需要先同步新增输入，不能只看 recovered 结果。

实际点击重新校验 /me、本人本机记录与服务器元数据，最后再读本机确认当前输入未变化。整个过程不 POST 草稿、不创建预览或正式发布；身份核对可更新既有安全许可。生成的内存票据绑定当前编辑器、本机 ID/seq、服务器 ID/修订与会话代次，只有该次成功签发的对象可以消费一次。输入、代次或本机确认变化后拒绝旧票据；不把它当成服务端授权凭证。

同步消费时只以 push 进入 `/publish?draft_id=<serverId>&source_revision=<revision>`。无标题、正文、本机 ID、seq、owner、令牌或正式版本号。C2 仍按实际 Bearer 确认本人资源，优先恢复既有账号 journal；C1 不清除、覆盖或补发 C2 标识。

如果服务器已到 R2、当前输入曾确认于 R1，仍交接 R1，由 C2 显式提示和选择，不能偷换到 R2。若旧修订不再保留或权限变化，C2 使用服务器错误，不能自动改用最新版。

## 返回与并发

编辑器保留在原生返回栈。焦点恢复后读本机、校验身份与服务器元数据，但不替换为服务器全文、不提升本机 baseRevision、不把发布 V 当成草稿 R，也不因返回发草稿/预览/发布 POST。网络读取失败仍保留现有输入并显示错误。

返回读取可能比新的本机保存更晚：若读取期间记录已由新保存/同步推进，旧读取不回滚界面，即使新输入已经落盘也一样。尚未落盘的输入继续按原 C1-B CAS/另存规则处理；不能靠提升基线覆盖另一窗口。

## 验证与边界

- 模型拒绝未同步、离线、保存/同步进行中、核对期间新输入、换号、伪造或二次消费票据；覆盖 recovered 仍 dirty、恢复后新服务器 ID、服务器 R2/本机 R1、返回读取迟到和网络失败。
- 真实 3300 HTTP/MySQL 与本机 SQLite/WebCrypto：编辑同步→票据→C2 固定预览→正式发布→匿名读取→只读返回，结束后隐藏合成作品。
- 实际路由夹具：C1 入口 disabled、仅两项参数、真实 PublishRoute/Workspace、保留编辑器栈、固定 R1 发布、返回不覆盖、旧 journal 优先。原生视图/存储/HTTP 部分由适配器替代，不能记为设备结果。
- 仍须关闭新路由夹具远程 CI 接入、前端既有依赖审计与设备体验门槛；分别见阶段复盘。无 USB 条件不阻塞独立开发，但不能宣布手机创作体验通过。
