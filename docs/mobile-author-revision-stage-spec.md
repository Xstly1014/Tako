## 目标与唯一主线

服务已经发表中篇、需要持续修订与控制读者展示的作者。作者能围绕**同一部作品**完成：

我的作品 → 指定作品 → 读取其服务器工作稿修订 → 核对发布目标及固定预览 → 显式追加正式版本 → 回到原作品详情 → 调整展示／隐藏／历史权限 → 核对读者当前展示。

阶段成功的判据是作者清楚知道“改的是哪个工作稿、发布到哪部作品、确认了哪个正式版本、读者现在看到什么”，且失败／重开／竞争不会换作品、重复发行或改写私稿。不是增加若干入口就宣布完成。

起点为已有正式中篇及其服务器工作稿；修订文字沿已有C1草稿箱完成并确认同步。M2不重做编辑器，不声称本机未同步文字已经进入本次发行。新书与章稿不进入中篇Work链路。

## 必须交付的业务行为

1. **定向准备。** 作者在作品详情发起修订发行。以本人当前会话读取作品状态及其绑定工作稿；草稿ID和最新R来自服务器，不能用作品V、本机seq或旧缓存猜测。读取失败留在当前上下文，不能退回通用列表自动换稿。
2. **明确目标。** 发布页显示此行将追加到哪部已有作品，以及选定R／当前服务器R、下一正式V。实际预览由服务器固定修订生成；后台工作稿变化不替换预览。发布授权仍默认未勾选，生成预览和正式发布仍为两次显式操作。
3. **同作品发行。** 服务端绑定工作稿与作品的关系始终为事实源。正式确认必须属于目标作品。原记录若指向另一待确认发布，先显示并核对原结果，不能覆盖、清除或借本次入口换成另一请求。
4. **正确回到原作品。** 成功后提供返回该作品详情的路径，读取最新正式版本、当前展示与隐藏／限制状态；读取失败保留原成功确认并只重试GET。导航不复制管理栈，不因返回自动再发布。
5. **展示管理闭环。** 新发行沿用现有服务规则：增加正式版本并将display_version更新为最新；不解除author_hidden、作品／版本限制或更改历史权限。作者可按既有规则切换正常旧版、隐藏／恢复及开关历史，动作确认后重新读现状；不能把发行成功说成已经公开或审核通过。
6. **公开结果核对。** 阅读入口按公共Reader读取当前展示，只交接作品ID。作者私有版本读取与公共读取严格分开。隐藏和整体受限不提供公开阅读捷径，期间发生可见性变化由公共接口再次拒绝。

## 路由与归属边界

- 本端负责M1/C2页面、客户端协调、路由交接、相关模型／组件／真实服务验收及阶段记录；承担从定向准备到版本管理的整条M2链路。
- C1本机仓储／同步／编辑、认证、小说N1-B、共享依赖／构建配置与HTTP契约仍由原负责方维护。需要其变更时先给最小接口差异，只暂停受影响接点，不直接越界改文件。
- 已冻结三种入口：无参数为明确通用选稿器；`/publish?draft_id=...&source_revision=...`保留C1选定修订；`/publish?work_id=...`为M2定向发行。后两种互斥，混用、缺项、数组或坏标识拒绝。M2先恢复原journal，无原记录才按会话读取本人作品绑定及最新服务器R；不让目标读取失败阻断原结果确认，work_id不替代服务端归属验证。
- 定向发行成功后以实际确认的work_id替换至`/my-works/[id]`，而非强行回本次传入的目标。原journal属于另一作品时仍返回原确认作品。该详情复用M1状态／动作，返回列表收起到原管理列表；坏ID不发业务读取，切号和失效隐藏旧资料。
- 预计复用现有HTTP接口，不新增表、迁移或权限。若现有API不足以提供必要事实，先记录契约缺口并与主开发协调；不得用前端推算补足。

## 必须验收的业务场景

| 场景 | 通过判据 |
|---|---|
| 作品A已有V1，工作稿R更新，再发行 | 同一work_id增加V2；不出现第二部作品；工作稿不被发行改写 |
| A与B同时存在 | 从A进入、预览、确认、返回始终绑定A，不误用B |
| 读取工作稿／作品状态失败 | 不生成预览或POST；保留上下文并可显式重试 |
| 工作稿未同步／修订超过服务器R | 不将本机内容视作可发行事实；沿现有错误处理 |
| 预览后服务器工作稿更新 | 仍发行选定快照，不能换成新文字 |
| 两端竞争追加正式版本 | 原预览冲突被明确呈现；不得自动重建预览或追加另一版本 |
| 正式提交成功但响应丢失 | 保留原标识，原请求确认不增加版本；重开按既定规则只读原结果 |
| 已有另一作品的未知发行记录 | 原记录优先，不能被A入口覆盖；旧成功不能清掉新记录 |
| 成功后当前状态GET失败 | V确认保留，只GET重试，不重发、不猜公开状态 |
| 隐藏作品发行新V | 仍隐藏；匿名读取拒绝；作者明确恢复后才按当前规则可读 |
| 切回正常旧V、历史关闭／开放 | 当前展示与历史正文权限实际符合既有B2规则，私稿不变 |
| 作品／最新版受限 | 不绕过限制；旧版恢复须用户明确选择，不静默降级 |
| 切号／退出／迟到响应 | A的目标、预览、回执和私有资料不能显示或提交到B |
| 返回、重复点击、重开 | 不重复栈、不新增隐式POST；回到原作品或明确说明目标不可用 |

每个场景区分纯模型、实际组件、真实HTTP/MySQL和设备证据；禁止把整张表全部标为某一层级“通过”。
