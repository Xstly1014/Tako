# App 创作下一阶段方向 · 2026-11-02

方向已进入 [C1 业务规格与契约预检](mobile-drafts-spec.md)，尚未接入 App 页或加密仓储。先以中篇私密纯文本工作稿为纵向链路，复用 A 的保存、冲突恢复、归属校验，再接发布；不在同一阶段发明短内容/长文模型或移植整个 Web 管理后台。

## 用户已确认

- 草稿允许加密保存在本机，断网/关闭 App 后可恢复；联网后自动尝试同步，版本冲突另存恢复副本。
- 按账号隔离；切账号不能读取或提交上一账号的草稿。评论仍仅内存，关闭 App 不恢复，不能因创作引入本机存储而改变评论行为。
- 成功写入本机不等于服务端保存成功；本机加密和服务端确认必须在状态上区分。
- 退出前提醒未同步稿，退出成功后保留密文并隐藏；仅同账号在线重登可恢复。曾登录且未主动退出的本机可断网重开续写，联网先校验，明确失效锁定；锁定状态须跨重启保留。

## 开发前需要写清的规则

优先级 P1：按 C1 规格验证存储提交与密钥失败、回执未确认、会话锁定及副本续写，再接页面。账号与退出边界已由用户确认；不得继续把已确认问题列成待决，也不得把规格写成已实现。涉及新的权利或数据丢失风险仍需讨论。

工程选择优先已有 Expo 能力和成熟认证加密，正文不能塞进只适合小凭据的存储；密钥与正文分离、原子写入、失败不静默丢字。先核对 SDK 58 官方能力与现有 A 契约；不自造加密算法，不为离线引入第二套业务后端或泛化同步框架。

## 验收方向

真实 API 身份/归属/幂等/竞争验证；可注入的存储故障与同步状态回归；App 页面输入/导航保护；最终 Android 构建。具备设备条件后，补中文输入、粘贴、断网、切后台/杀进程、切账号和冲突副本真机验证。电脑夹具或数据库集成通过不能覆盖原生存储与生命周期门槛。
