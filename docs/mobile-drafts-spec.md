当前实施拆分与归属见 [离线授权和编辑接入](mobile-draft-access-spec.md)。C1→C2 接口复用并行端维护的 `docs/handoff/c1-c2-interface.md`；主开发已审查 c905d7a 并接受其与既有权利一致的调用条件，尚未实现编辑页调用点。

日期：2026-11-02。状态：C1.1 已实现加密仓储/同步核心与 SDK 适配，模型、真实 SQLite 与真实 API 分层验证；**C1-A 授权、C1-B 草稿箱/编辑已接源码；当前验收见 mobile-draft-editor-review.md，发布调用与设备门槛仍未关闭**。承接 [创作方向](mobile-authoring-plan.md) 与 A 既定语义。C1 不包含公开发布、长文目录、图文短帖、实时协作或删除草稿。

## 第一条作者链路

已登录作者从加号的中篇入口或“我的 → 草稿箱”进入自己的草稿列表，新建或打开纯文本工作稿，编辑后先加密暂存本机，再尝试同步服务端；重开后续写，冲突保留两份。游客先登录，不创建无归属的游客草稿。首次使用此设备须联网成功登录。

服务端仍使用已有 A 接口，不创建 App 专用第二套草稿库。标题上限 200 字符，正文上限 1 MiB UTF-8，空白私稿可存在；缺笔名在同步前提示设置，不能因此丢掉已经编辑的文字。工作稿不公开，不出现在社区或运营后审中。

## 用户明确确认的权利

- 草稿可加密本机暂存，断网、后台和重开后可恢复；联网后自动尝试同步，冲突另存恢复副本。
- 退出前提醒未同步数量，退出成功后保留加密记录但立即从可见界面隐藏。只有同账号重新在线登录后，才可确认恢复；不能向其他账号展示标题、正文或待同步操作。沿用现有“断网退出未完成，联网后再退出”，不在 C1 悄悄加入离线注销队列。
- 曾成功登录且**没有主动退出**的本机，断网重开可离线续写之前账号的本机稿；不是一次新的服务端认证。联网后先校验实际会话；401 等明确失效结果锁定草稿并要求同账号重登，不因超时/503删除本机数据。
- 主动退出或明确失效的锁定结果必须持久化；重开且断网不能绕过已知锁定恢复旧离线身份。上一会话与账号映射不匹配时拒绝离线解锁。
- 评论继续仅内存，关闭 App 不恢复。草稿存储不接收评论文字。

## 保存与恢复状态

| 状态 | 含义与用户可做的事 |
|---|---|
| 尚未暂存 | 文字仍在内存；不显示已保存，离开提示风险 |
| 已暂存本机，待同步 | 加密写入成功；可以继续编辑，明确尚未到服务器 |
| 正在同步／结果未确认 | 原请求身份和快照已持久化；可继续编辑新文字，不能替换未确认请求再发 |
| 已保存到服务器 | 事务确认仅覆盖本次提交的输入；期间新输入仍待同步，不被旧回执标成已保存 |
| 已另存恢复副本 | 服务端冲突确认，原稿保留对方新版，当前离线文字确认存为新稿，编辑器切到恢复副本继续写 |
| 需重新登录／账号不符 | 隐藏私密内容并冻结同步；原账号重登确认恢复，其他账号不能领取 |
| 暂存失败 | 原有效本机记录不覆盖，当前内存输入保留，提示重试；不假报保存或静默离开 |

“允许重开恢复”只覆盖已成功加密写入的输入；系统在写入完成前终止进程，最后未暂存的输入可能丢失。卸载/清除数据、本机密钥丢失不是服务端备份。页面要把这些状态说清，不能承诺每个按键都已持久化。

## 同步行为与竞争

1. 本机记录绑定账号、设备内记录 ID、服务端草稿 ID（首次同步前可为空）、基础修订、当前输入代次、已确认时间，以及冻结的未确认请求；身份映射与正文一起加密保护。
2. 新建采用 `/api/drafts/create`，服务端确认前已有持久化 mutation_id 和首次提交快照；丢响应重开后先确认原请求，不能创建第二份。新输入可以继续本机暂存，收到首次确认后再用新修订保存。
3. 同步前确认真实会话仍为记录所属账号；后台返回/网络重试不靠客户端 owner_id 授权。请求与回执都绑定会话代次，切号后的迟到回执不能清空另一账号编辑区。
4. 正常保存按 `base_revision`，同一记录串行同步。未知结果（断网/超时/503）保留原 mutation_id 和全文快照；明确 `revision_conflict` 后才生成一次 `/recover` 请求，成功前不能称已另存。
5. 恢复请求本身可重试，不因重复点击生成多个副本。恢复期间新增输入继续留在本机；回执只确认恢复快照，不丢掉后写的文字。不会自动合并两台设备的正文。
6. 本机脏记录优先保护：重新读取服务端只用于比较基础修订或确认结果，不能直接用服务端正文覆盖本机未同步文字。服务端新内容与本机相同可记录已确认，否则走保存/恢复。
7. 自动同步只保证 App 活跃时的尝试；本轮不承诺被系统终止后继续后台同步，不增加后台常驻服务。恢复前台后重新检查身份与本机队列。

## 本机存储和失败边界

采用现有 Expo Crypto 的 AES-GCM、SecureStore 保存按账号分开的少量密钥、SQLite 事务保存密文。SDK 58 官方安装器加入 `expo-sqlite` ~58.0.15 及其插件，锁文件同步；不自造加密或原子文件协议。正文/标题、原请求和账号绑定进行认证加密；不把正文塞进 SecureStore，不自动写日志、共享目录或剪贴板，不把密钥硬编码在包内。

存储采用 `WAL`、`synchronous=FULL` 与独占事务；密文与存储修订一起提交，异常回滚保留旧记录。认证附加数据绑定账号、记录 ID 和存储修订，拒绝把密文搬到其他账号/稿件/修订。SQLite 库文件并非整库 SQLCipher 加密：可检索的 UUID 和存储修订是索引元数据，标题、正文、待发送快照及其绑定信息在密文中。密钥与库分开保管。

Node 真实 SQLite 的异常回滚、提交后回执丢失及子进程在提交前退出已验证；原生 Expo Crypto/SQLite/SecureStore 的设备行为仍需真机，不能将 Node 的 WebCrypto 或本机事务结果直接算作 Android 安全存储验收。仓储是底层存储能力，尚未接入登录/离线授权；草稿页面禁止绕过后续授权保护直接根据路由 owner 参数读仓储。

密钥不可用、密文被改动或格式不兼容，保留原文件，显示恢复失败；不能静默生成新密钥覆盖旧稿。明确认证失效时隐藏并锁定；保留未落盘输入仅供原账号重新认证后恢复，不能借“导出救援”向别的账号泄露。存储失败时先阻止无提示离开，不靠删除旧稿腾空间。

## 已有接口与预检

使用 `/api/drafts`、`/api/drafts/{id}`、`/create`、`/save`、`/recover` 及 `/api/me`；OpenAPI 仍是唯一源。原生请求使用自己的 Bearer，不能混入 Cookie/Origin。公共作品接口不能替代私稿接口。

本阶段先通过真实 3300 验证原生新建/读取/保存/结果未确认重试/跨账号拒绝/冲突恢复，再进入本机加密仓储与同步逻辑。预检只证明 API 前提，不等于草稿 App 已可用。

2026-11-02 已执行 `node scripts/mobile_draft_preflight.cjs` 并通过：正常原生注册、创建/保存原回执重放、载荷复用拒绝、跨账号读写/恢复拒绝、冲突保留原稿、恢复唯一副本与副本独立续写。仅新建两个合成账号及其私稿，退出会话，不访问现有作者文字、不发信。没有模拟真实断网，而是“服务端确认后重复原请求”的契约检查；本机崩溃/加密/同步队列仍待实现与验证。

## 分段交付与验收门槛

- C1.1：规格、原生契约预检、加密仓储与同步状态的故障模型。持久化原请求、写入失败、回执失败、身份切换/失效、损坏记录和冲突副本都要有失败证据。
- C1.2：真实草稿列表/编辑页及明确保存状态接入；从原型加号和“我的”双向导航，不重排其他频道。实际组件验证状态和输入保护，不能只交基础类。
- C1.3：Android 构建与源码一致性核对；设备恢复后补中文/表情/粘贴、切网、后台/杀进程重开、账号隔离、两端冲突，才宣称设备创作体验通过。

发布和作品管理后续复用 B1/B2，单独按固定预览/正式版语义验收；C1 不自动让草稿公开。
