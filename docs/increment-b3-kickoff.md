# B3 启动评审

前置基线：B1/B2 已实现，前端调整已提交 `0ad3ca1`。当前本机只有正式版本后审任务，没有运营审核、处置或复核功能。本文为启动方案，不把规划标成能力。

## 已确认的新规则

观察期提前撤销后，已有待审仍继续人工审核，不自动公开；同作品继续替换待审，不借重新提交绕过审核。与自然到期保持一致。

## 开发顺序

1. **B3.1 人工后审及纠错**：从既有正式版本任务开始，运营读取固定版本，记录审核结论；具体版本/作品限制与撤销；作者查看原因、申请站内文字复核，运营维持或撤销，读者权限随实际有效限制变化。
2. **B3.2 观察期及先审后发**：7 天观察期、替换/撤回待审、通过后分配正式编号、驳回节点、不覆盖工作稿；处理观察期变更与提交/审核的并发关系。
3. **B3.3 明确规则与时效**：经样本评审的明确灌水规则、临时版本限制、48 小时积压与复核目标、超时站内提示和故障告警。B 不接入大模型。

分批只是实施与验收顺序，B3.1 通过不代表 B3 全部完成，也不能作为公开运营门槛已满足。

## B3.1 第一条闭环

以“已经公开的 V2 被运营发现问题”为验收主线：

- 队列按作品组织，保留每个正式版本的独立后审任务；突出超时任务和当前公开版。新版发布不取消旧版任务，不读取工作稿。
- 运营打开固定的版本号与正文，再提交针对该版本的审核结果。另一个人已处理时，旧页面返回状态冲突，不能覆盖结论；相同操作丢响应重试只记一次。
- 限制 V2 后，当前展示若是 V2，新的读者访问不可读；不自动切到 V1。作者仍能看和导出 V2，能明确选择正常 V1 展示，但作品级限制仍优先。
- 作者能看到具体原因和时间，针对该处置提交站内文字复核。不能把复核申请当作自动解除。
- 撤销只撤对应处置。其他有效处置、作者隐藏、公开展示指针和观察期分别判断；撤销 V2 限制不会把当前 V1 自动切回 V2。
- 审核通过只完成本次后审，不代表平台推荐、授权认证，也不替代其他有效限制。

## 接口与数据约束（实现前需写入契约）

- 运营使用真实账号会话，服务端用配置的运营账号 ID 授权；无配置则默认无运营权限。不提供前端自报管理员、隐藏 URL 充当权限、万能测试会话或复杂角色平台。
- 审核权限仅涵盖已提交发布的固定内容，不扩展到私人工作稿与未提交预览。作者与运营接口分别授权，作者只能看到自己作品的处置与复核。
- 既有 `publication_review_tasks` 仅有版本、状态及首次等待时间；需增加可验证的处理修订与不可变审核记录，不能只更新字符串状态而丢掉操作者/原因。
- 处置记录与撤销记录独立保留；现有布尔限制字段只能反映有效处置的汇总，不能撤销一条就无条件设为 false。
- 保持账号 → 作品的既有加锁顺序，在同一事务中更新审核/处置状态、可见性修订、审计记录及幂等确认；不锁定或改写工作稿。固定目标版本的审核不应因作者发布了新版而误审新稿。
- OpenAPI 同时定义队列、固定内容、审核、处置、复核及冲突/权限错误。运营写入须通过同源保护；日志不含正文、原始复核文字、验证码或凭据。

## 仍需共同决定

- 再次复核与冷静期已确认，见下节；不重新推定其他频率处罚。
- B3.2 被替换、驳回、撤回提交正文的保留期与到期后的作者提示。正式版本沿用既有保留规则，不借清理待审资料删除正式作品。
- 明确灌水规则与阈值、临时限制的超时处理；在规则未确认前，不把疑似低质变成自动处罚。

## 验收标准

正常处理只是起点，还须验证：非运营读写被拒绝、作者跨账号读取被拒绝、旧审核不能套新内容、并发处理不能覆盖、丢响应重试不重复、限制与撤销不越范围、隐藏和展示指针不被改变、复核单条在途约束、任务超时不自动通过。使用真实 API/MySQL 与浏览器串联，迁移与恢复保留 B1/B2 数据；不通过手动改库冒充运营入口。

## 已确认：再次复核与冷静期

- 作者可补充新理由再次申请；历次申请、结论及原因均保留。同一处置最多一条处理中申请。
- 首次复核可立即申请；运营维持处置后，同一处置进入 24 小时冷静期，从结论在站内可查询的时间开始计算，不以作者实际打开页面时间为起点。
- 冷静期只限制同一处置的再次申请，不限制修改、发布新版本或其他处置的首次复核。页面展示明确的可再次申请时间。
- 冷静期内保留联系运营的入口；运营可主动重新检查及撤销误判。联系不等于承诺即时处理，不新增聊天或业务邮件系统。
- 不按申请次数自动延长冷静期，不由文本相似度或大模型判断作者是否有权申请。运营如何标记无新增信息的申请，尚未由本次确认单独确定。
- 接口以服务端时间判断，不依赖前端倒计时；同一操作成功后丢响应的重试仍应返回原结果，不因在途约束或冷静期被误拒绝。并发申请最多成功一条。
- 补充验收：冷静期开始前/到期边界、客户端改时钟不能绕过、切换处置不误拦、主动撤销后不再允许对失效处置创建新申请。最后一项属于状态终结设计，实施前需与其他处置撤销规则一并核对。
