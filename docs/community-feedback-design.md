# 收藏与评论 · 技术设计评审

2026-11-01 两级评论现已接入本机测试环境并通过工程检查，完整实现与证据见 [本批复盘](reviews/two-level-comments-review.md)。收藏工程检查点见 `reviews/favorites-review.md`；用户本人本批操作验收仍待记录。

依据 [业务规格](community-feedback-spec.md)，收藏与两级评论接口、迁移与工程验证已完成。用户已停止 ECS，当前只在独立本机测试环境推进。

## 业务与已有能力的连接

沿用 Go/Gin、MySQL、现有密码会话、服务端运营白名单与共享导航。工作稿、发布预览和正式版本保持现有独立关系。收藏和评论连接作品，不连接可变工作稿。评论不持久记录版本归属。

评论复核首版关闭：不扩展现有作品/版本申诉入口接收评论，不复用其处置 ID 空间。运营仍需有屏蔽、主动撤销和原因留痕，不能只加一个数据库标志而没有实际操作入口。

## 数据与写入边界

- 收藏关系：账号、作品唯一；保留有效状态、收藏时间和修订号。取消后重新收藏可更新收藏时间；原请求重放不得把取消后的收藏重新置为有效。
- 收藏操作确认：账号与请求 UUID 唯一，保存输入摘要与确认结果。采用显式“收藏/取消”而非 toggle；失去响应时可确认原结果。
- 评论：唯一 ID、作品、评论者、主评论 ID（主评论自身为空）、可选回复对象 ID、正文、发表时间、删除状态、平台屏蔽状态与修订号。不增加版本归属字段。回复目标必须位于同一作品与主评论串，不能任意引用其他作品或其他串的回复。
- 公开回复资格同时检查自身、主评论与作品的可见性。主评论删除使其全部回复不可恢复地删除；主评论屏蔽只临时阻止整串公开，不将子回复逐条记作受处罚。撤销时保留独立删除和屏蔽状态。
- 评论操作确认：账号与请求 UUID 唯一，输入摘要与结果同正文事务提交；删除或屏蔽后重放发表请求，只返回原评论标识及确认，不重新返回已不可见正文。
- 评论处置与审计：独立评论处置标识，记录操作者、原因、屏蔽/撤销及时间。评论者仅可读取本人原因，运营按白名单授权。首版无评论申诉记录和申请接口。

迁移采用新增表、索引与外键；已有草稿、作品、会话和处置记录不改写。删除的公共结果永久不可读；正文保留/清理实现不得提供恢复已删除评论的业务操作。

## 阅读上下文

现有公开正文响应增加由服务端生成的临时权限上下文，明确当前加载的作品与正式内容。它仅用于提交时检查阅读页面的权限，不持久写入评论归属，不授予读取隐藏历史的权限，也不表示读者已经读完。

发表时在同一事务内核验上下文、账号与笔名、作品未隐藏/整体未受限、来源版本未受限，以及当前限流状态；核验与写入必须和隐藏/限制竞争有确定结果。关闭历史阅读不单独否决已有阅读上下文，不能简单调用现有 Read(version) 再判定发表评论权限。

上下文采用何种保存或签名方案，在实现前按匿名阅读后登录、页面刷新、不同环境密钥隔离及无正文权限扩张核对。不得为了实现方便加入未经讨论的“历史关闭后必须切最新版”限制，也不得把上下文当作登录身份凭据。

## 接口分组草案

具体路径、字段与错误码在编码时同步进入 OpenAPI，不以本表代替契约。

| 用途 | 权限 | 主要约束 |
|---|---|---|
| 当前作品收藏状态、收藏/取消、原操作确认 | 当前会话 | 归属验证、显式目标状态、幂等确认 |
| 我的收藏分页 | 当前会话 | 不可访问作品只返回关系标识和状态；可取消 |
| 作品评论分页 | 游客可读 | 作品访问控制；不以来源旧版限制连带过滤正常评论 |
| 发表评论与原操作确认 | 当前会话 | 阅读上下文、版本不可伪造、笔名、限流与并发权限 |
| 删除评论 | 评论者或作品作者 | 服务端确认身份；重复与并发删除不复活 |
| 本人评论处置结果 | 评论者本人 | 原因可查；作品隐藏时不泄露其他作者受保护元数据 |
| 评论检查、屏蔽、撤销屏蔽 | 运营白名单 | 原因必填、期望修订、防旧页覆盖、审计同事务 |

## 界面与失败体验

阅读页提供收藏与两级评论区；回复其他回复仍平铺并标记对象。评论为纯文本，用户输入不解释成 HTML。已有“我的收藏”导航与返回社区/阅读入口继续保留。评论者在处理结果区域查看本人评论处置，不展示复核按钮；运营评论处置与现有作品后审明确区分。

游客登录前后保留作品目标及待提交文字；不同账号的未提交内容不能自动转移或提交。网络失败保留输入与原请求标识，不显示未经服务端确认的“评论成功”。服务端已确认、列表刷新失败时分别提示，不能重发新请求制造重复评论。

发表评论期间作品或来源版本被限制时，保留文字供复制，明确当前无法发表；不自动改绑到新版本，也不把失败评论当成成功。收藏列表不可访问记录保留取消入口，恢复作品后按当前权限重新取元数据。

## 开发与验证顺序

1. 收藏：迁移、真实 MySQL 幂等/竞争、HTTP 契约、阅读页与我的收藏、真实浏览器往返及隐藏恢复。
2. 评论：阅读上下文、发表/分页/删除、版本变化与隐藏限制竞争、多账号权限、丢响应重试。
3. 评论平台处置：原因展示、运营屏蔽与撤销、无复核入口、删除优先于撤销及跨对象 ID 拒绝。
4. 在持久测试环境补充适量评论/收藏场景数据，验证大量作品下的导航、分页、长文本与错误状态；不把生成关系数当作真实互动指标。
5. 本人完成“发现—阅读—收藏—再次访问—评论—作者看到”的操作验收，再执行新增表加密备份与独立恢复，记录实际结果。正式部署另行完成存量数据保护和升级检查。

B3.2 的观察期、自动规则与先审后发不作为本批前置条件。评论复核暂缓，但运营主动纠错必须可实际操作；若出现真实评论处置争议，再评估补入申诉链路。
