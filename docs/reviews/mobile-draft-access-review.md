# C1-A · 会话绑定与本机草稿访问复盘

日期：2026-11-02。主开发维护。源码基线 main 59694d6，实际实现以包含本记录的提交为准；规格为 mobile-draft-access-spec.md。没有修改后端 API、OpenAPI、依赖或对方发布状态机。

## 这次解决什么

C1 核心仓储此前接受 owner 参数，不能直接接页面。手机虽存有旧令牌或密钥，也不能据此判定当前使用者有权读稿。本轮将本机草稿授权与真实会话绑定，并接到现有 Session/原生安全存储；页面只使用无 owner 参数的 AuthorizedDrafts。

- 凭据与授权保存在同一 SecureStore 项：单个小型 envelope，不另存密码、正文或令牌副本。原始字符串令牌兼容联网恢复，旧令牌离线不自动获得权限。新登录均先进入 confirmation，同账号重登也需要主动确认。
- confirmDraftAccess 重新请求真实 /me，检查账号及代次后才持久化许可。未退出的同一令牌/账号可以在断网重开后取得 offline 草稿权利；主 Session 仍为 offline/account=null，不冒充在线，authorized HTTP 不能因此放行。
- 主动退出先持久化锁定，再请求注销。网络失败保留会话供重试，但草稿先锁住；联网恢复身份后仍需确认。401 立即隐藏私稿并尝试锁定、删除凭据；不能把 503、网络、契约/环境错误都当作认证失效。
- 锁定失败不发送主动注销；删除失败会留下明确 storage 错误，修复了会话代次变化吞掉注销落盘失败的情况。restore 保持原有 fire-and-observe 调用约定，失败存于 snapshot.error；logout/confirm 返回可处理的失败。
- 授权仓储从会话派生归属，首次、锁定、确认中和忙碌状态不打开仓储；打开/解密期间代次变化拒绝交付结果。已经开始的本机写入可能最终以原账号密文提交，但不会交给新账号视图；不删除旧密文或将其转给新账号。
