# Android 原型一致性纠偏 · 2026-11-01

用户指出首包与 `docs/prototypes/mobile-app-v1/` 不一致，复查成立。首包擅自加入最新/精选分区、标签筛选和测试说明，省略开屏/游客/偏好页，底部图标与字号密度也未按原型实现。它只验证了安装阅读能力，不是原型设计交付。

## 本轮确定规则

1. 原型是布局基线，不再重新设计首页。恢复开屏、Q 版游客入口、形态选择、中篇首页和整页阅读；原型文件保留，不改成适配实现的样子。
2. 用户已确认：保留原型中尚未接入能力的位置与外观，明确提示尚未开放。不填假数字、不模拟注册、关注、评论或支付成功。
3. 首页使用原型频道栏、搜索位置、全宽中篇行、五位底栏；取消首包自加筛选编排。实际数据仍为本机 API 的公开中篇，原型合成数组不进入 App。
4. 原型字号、行高、边距、头像大小和图标路径逐项映射为原生组件；仅因安全区、触控和真实状态做必要适配。
5. 未接入业务：搜索/关注/赞/周边/消息/原生身份与创作。保留入口并明确不可用，原生身份仍需单独评审，不伪造 Origin。
6. 已实测：APK 签名/内置 JS/权限检查通过、真机安装成功，USB 断开后的列表失败可重试，顶部返回保持列表精确位置。Android 系统返回异常已在兼容更新后真机复测：返回中篇列表，前后 5 个可见作品及其坐标一致，没有退出 App。

## 本轮纠偏复盘

首包将“安装阅读能力验证”与“按原型交付界面”混为一谈。能力可以分期，未经确认不能借此重新安排用户已认可的界面。后续逐屏使用原型截图对照，未接入能力采用用户确认的不可用状态。

首包还主动打开了模板默认关闭的预测式返回，在 Android 14 真机出现退出而非返回列表的问题。显式 JS 返回监听未解决；通过 Expo 生成器恢复默认返回模式后，检查 APK Manifest 确认配置生效，并在 vivo Android 14 真机复测通过。不能以代码存在替代真实行为证明。
