# 作者业务真实服务页面整体验收

2026-11-03，对应[验收规格](../mobile-author-workflow-acceptance-spec.md)。本轮没有增加产品功能或管理权利；将C2/M2/M3/M4/M5及读者反馈放在同一批真实数据上验证，并新增CI门禁。没有把尚未合入main的业务或原生设备标为已交付。

## 本轮实际走通的业务

1. 新建随机合成作者与读者；历史目录夹具45条。实际作者工作台读取20/40/45条；服务器新稿R1由真实接口确认，未经过C1本机编辑器。
2. 实际发布页选R1、简介/标签/授权确认、固定预览，再提交。转发真实POST成功后故意丢掉响应；页面明确未知。离开提示后重入只GET恢复原发布，正式POST次数仍为1。
3. 真实工作台提交标题条件，进入作品管理；服务端保存R2，定向修订发行先显示旧journal结果，明确确认后才采用目标R2。实际发行V2仍是同一work_id，累计正式POST2次。以保留底层页面栈的导航适配返回列表，查询输入仍为原条件，未回到旧内部详情。
4. 实际核对组件读取当前V2与候选V1，两份中文/表情完整正文；经原确认动作切换V1，公共Reader实际显示V1正文。工作稿保持R2。
5. 切换到真实读者账号，在实际评论面板发主评论；切回作者刷新并回复，真实API读回回复。返回管理时，跨账号已经清除的内部作品选择和查询不应被恢复，页面直接回到列表，栈不多一层。
6. 测试运营通过实际白名单API限制固定V2，作者实际处置页读取原因、提交复核，只有一条在途；运营维持，页面显示结论与服务端时间。再次申请由真实服务器409冷静期拒绝，历史仍1条。运营主动撤销，作者页读回撤销原因，公共读取仍为作者所选V1。
7. 整条结束再次读取工作稿，与R2时完整响应相同；不借处置/评论/展示操作改稿。自有历史夹具按随机ID清理，自有正式作品隐藏，自己的会话注销；临时凭据文件和模块遮罩目录在路径核验后删除，正常业务审计保留。

## 证据边界与安全

- 产品页面、Session、客户端、固定请求协调器均为实际源码；HTTP进入现有3300及同一Compose真实API/MySQL，没有返回模拟业务JSON。运营是测试API动作，不是App新增后台界面。
- React Native组件/安全存储/导航由明确的DOM、页外内存和保留栈适配承载。适配只验证焦点、移除保护和路由交接的产品行为，不证明Expo原生导航、键盘、原生SecureStore、App杀进程或真机长正文体验。USB仍由用户暂停，未构建/安装/ADB/ECS。
- 原生Bearer/登录入口主动拒绝浏览器Origin/Cookie。适配模拟原生fetch不发送Origin、拒绝任何Cookie，另以带浏览器Origin的真实登录验证403/origin_rejected；未改变后端同源保护。原服务端生成请求ID，未伪造账号归属或运营白名单。
- 初始R1/R2保存是实际API前置，不冒充C1创作页与同步。本轮新增的是跨页面真服务验收，不是外部作者/运营成效或容量证明。邮件未打开/发送；仅随机合成账号和本次自有作品进入测试。
- 缺服务/非test环境直接失败，不能skip或退回假服务。夹具受已有test数据库守卫与随机账号/ID约束；不清认证/发布计数、不修改旧账号/凭据/卷、不变更依赖锁。根目录只读挂载到浏览器容器；不上传配置、API日志或页面产物。
- 只输出固定阶段、脚本行号、会话阶段、最多8个已分类HTTP状态和错误数量；不输出正文/理由/凭据/Cookie/DSN/原查询或响应。故障与非test前置的单元门禁验证没有写入及敏感错误回显。只有子场景与清理全部成功才打印PASS。

## 首轮失败与纠正

最初把浏览器Origin原样转发到原生登录，被真实服务403拒绝；这是原生入口的安全规则。改正平台适配，并保留带Origin拒绝反例，未放宽服务端。

第一次达到读者反馈段后，多按一次“返回作品列表”的假设失败；实际Session切号已按安全要求清掉底层旧选择，Reader返回即列表。本轮明确断言空查询及单层栈，不将正确隔离改成恢复旧账号上下文。其余已走完发布恢复/修订/核对步骤的成功不冒充首轮整条通过；纠正后完整重跑成功。未发现本轮场景需要改产品实现的确定缺陷。
