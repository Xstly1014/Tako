2026-11-03，主开发维护；规则源为[完整 N2 规格](../novels/n2-publication-reading-spec.md)和[ADR003](../novels/adr-003-chapter-publication.md)。本页连续跟踪同一业务包，不把内部检查点当作 N2 完成。

## 当前实现：固定预览、受理、独立审核内核

作者指定本人书、章稿及已保存修订，获得固定预览；预览不占号。明确授权提交时预约固定章号，普通作者同事务产生正式版本及后审任务，观察期只进入待审。多个章独立审核；A1 后过审不会被 B2 已过审阻塞，也不会倒退 B 首次发布的书籍资料。驳回、撤回不退号，同章修改重提沿用原号；替换同章待审只占一个候选版本，旧审核返回冲突。

原操作按会话账号、书、操作、目标、固定载荷判重；回执与现状分开。作者提交列表、固定详情和运营待审队列已实现 HTTP 契约；运营白名单沿现有配置，不能由客户端传作者 ID。正式操作不改工作稿，不解除书/章隐藏。首次章节事件仅首次正式版本写入，旧章修订不重复产生新章事件。

预览正文独立于私稿历史；未提交 24 小时后不可发布，维护进程按账号锁重查后分批清理正文。已受理预览、审核记录和正式版本保留；原请求回执保留，旧标识不能在清理后重新变成新操作。预览采用与中篇相同的每账号每小时 30 次阈值，长文独立计数，原请求确认先于额度检查。

新迁移 00016 与 N1 增量兼容，带预约号或任何 N2 数据时拒绝回退。唯一契约是 `backend/internal/contract/openapi.yaml`，App 声明从完整契约生成，未覆盖中篇接口。独立 App 客户端已实现快照、受理回执、列表、详情、撤回和只读确认的目标/语义校验；目前尚未接入界面或原生恢复记录，不能称为 App 发布交付。
