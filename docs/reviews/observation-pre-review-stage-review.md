# 观察期与中篇先审阶段复盘（2026-11-04）

## 解决的业务问题

既有长文已经具备固定发布、正式管理、治理纠错与公开阅读，但观察期只能由数据库建样，没有正常运营入口；中篇观察期直接拒绝发布，更不是先审业务。用户确认本批一起补齐，明确延长从原结束时间加7天、过期重启7天。基线main 2da15cc，同事e99ab22已合入；本批不改其反馈/列表编排、CI、锁与原生，也不承担手机构建和验收。

## 交付行为与实际边界

- 运营从已正式发布的书/中篇定位作者，启动、延长或提前撤销账号级观察期；必须填写原因，CAS竞争与不可变操作回执保留，作者可看原因、结束时间及分页记录。不存在按客户端owner_id授权或随意读取未提交私稿的入口。
- 中篇明确提交固定预览后成为待审。首次受理没有正式版/公开标题/正文；正常作者原四字段正式回执保留。先审受理以version=0、published_at=null及submission标识表达，页面不画V0，不给假读者链接。
- 同作品新待审替换旧候选，候选号仍为last+1、首次等待不重置；通过才建立正式版；驳回、撤回留作者记录，工作稿不变。撤回/通过并发仅一方成功。结束观察期不释放待审，重提已有待审也不自动公开。
- 作者正式作品默认仍展示正式版，待审/驳回/撤回用圆点线进入固定内容；被替换节点不入可见时间线，完整提交记录保留。已通过节点归正式时间线。中篇先审记录入口支持首次没有正式版的作品；详情链接绑定作品与提交，换路由/换号清旧内容。
- 审核不清作者隐藏、不清独立平台限制；原受理回执永久表示当时受理，页面说明“受理不代表当前仍待审”，现状另查。网络未知保留最小原命令，重开只读查询，不能把已受理重发成新版本。

## 发现的问题与修正

长文章/资料待审在观察期撤销后重提曾绕过审核，现沿待审对象继续先审，数据库反例和实际App整条均覆盖。中篇首次待审隐藏曾引用不存在的正式V0，现保留作者状态与原操作回执，不建立假正式事件。生成器对discriminator映射联合类型的处理丢掉嵌套判别字段，改为语义等价oneOf+各分支enum，由生成类型及响应契约共同验证。未降低契约校验。

全后端首轮600秒超时，不能算通过；专用测试显式20分钟后765.593秒通过。定位契约测试每次重复解析相同路由，采用测试内sync.Once复用只读解析路由，每次响应仍独立校验，最终全race/vet/真实MySQL/路由与请求响应契约158.296秒通过。没有缓存业务响应或跳过测试。
