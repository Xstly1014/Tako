## 业务裁决与取舍

用户选择未发表评论全部只在内存中保留，关闭 App 不恢复。已说明系统回收也可能丢失，不能以“切后台”承诺永久保留。保留断网失败输入、防止跨账号转移、离开页面提示和明确发表；不使用系统安全存储保存正文，也不改变 A 创作草稿持久化。

具体规格见 `docs/mobile-comments-spec.md`，继承已有两级评论删除/屏蔽/无版本归属规则，不新增点赞、通知或评论复核。下一步仍先重连手机验证现有账号/收藏包，再接评论界面。

## 独立验证

扩展已有真实 MySQL HTTP 评论测试：通过实际密码服务为合成读者创建原生会话，不注入 Origin/Cookie；原生重放已成功评论返回同一回执、本人可删除、游客无删除权限、错误 expected_account_id 被拒、本人可读取处置原因。它验证既有接口对原生身份的行为，不能冒充 App 登录表单或设备验收。

本批无接口或 schema 修改，OpenAPI 仍 0.12.0、schema 13。修正预期后，在独立 `tako_feedback_test` 执行全量 `go test -race -count=1 ./...` 与 `go vet ./...` 通过，HTTP 契约/权限包耗时 146.343 秒。该结果包含路由、请求/响应契约和实际 MySQL，不是内存数据库或 App 真机操作。

首轮新增测试误将评论的账号不匹配预期为收藏接口的 409；检查现有实现与契约后，评论实际定义为 400 invalid_input。修正测试假设，补充拒绝前后评论列表一致检查，不改服务端来迎合测试。App 实现需分别处理，不能把所有账号冲突硬编码成同一错误码。
