# M3 作者作品工作台阶段核对

2026-11-03。对应[完整规格](../mobile-author-catalog-stage-spec.md)及[共享片段](../handoff/m3-shared-contract.md)。源码与本记录同提交；远程整合证据在本文后续追加，未检查的新SHA不沿用旧CI结论。

## 业务实现

作者从本人全部正式中篇按展示/最新正式标题查找，组合作者隐藏与平台限制状态，按创建时间/ID稳定读取20条一页，进入管理或修订后按原条件刷新首屏。仅会话账号判权，不查正文、私稿或他人目录，不新增管理权利。

`publication/catalog.go`独立实现查询；现有`/api/my/works`显式带q/visibility/restriction进入M3，否则保留旧接口及UUID游标。M3游标为v1/锚点ID/账号与归一化条件摘要，最大512；摘要绑定查询但不是签名或授权凭证，数据归属仍由每条SQL的owner条件保证。游标不含原始关键词。锚点变隐藏后仍可继续同条件翻页；实时查询不承诺冻结快照。使用既有works_owner_created索引，无新表/迁移。

关键词去首尾空白、大小写归一、最多64码点，拒绝控制字符/坏编码；SQL使用参数和独立转义符，让%、_、反斜线按字面匹配。限制状态分别保留作品级和展示版本级；作者未隐藏不是公开/审核结论。最新正式标题不同于展示标题时明确并列，避免新标题命中却只见旧标题。

客户端复用旧摘要验证并强制M3扩展字段。工作台输入/选择不自动请求，显式查找或键盘提交；待应用条件禁翻页，刷新使用已应用条件，清空恢复全部。控制器取消请求并以代次/会话阻断迟到写入；分页失败保留结果和游标、去重并拒绝游标循环。管理返回清旧结果重读首屏，不用管理回执拼目录。修订跳转在失焦时把底层列表切回目录，保持查询，避免新的定向详情返回后仍出现旧内部详情。

## 首轮失败及修正

最初后端夹具通过Prepare/Publish连续制造55条，触发既有每小时30次预览保护，publication包失败；其余HTTP包通过。随后改为事务植入历史合成目录，真实新修订与管理仍走实际Store/API，重新完整race/vet通过。没有清计数、改保护、跳过测试或把初次失败重标通过。

本机React lint拒绝渲染期间传递含ref的校验闭包，改为控制器独立会话检查与生命周期取消，lint/模型/组件重新通过。规格复核发现修订路由替换后，保留的底层列表可能还停留内部详情；补失焦准备列表与实际组件焦点回归。既有M2管理未知结果、版本展示/恢复与C1均保留回归。
