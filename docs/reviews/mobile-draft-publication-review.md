# C1-C · 发布交接与返回续写复盘

2026-11-02，主开发维护。起始 main 47510be，已 fetch 并读取对方 mobile-publication@5f153c3 的进度；实际实现以包含本记录的提交为准。规格见 mobile-draft-publication-handoff-spec.md 与 c1-c2-interface.md。

## 交付行为

编辑页接“准备发布”，同步移到页脚；未确认输入、离线许可与进行中的本机保存/同步不能交接。点击只读复验并签发一次性内存票据，push 只传服务器 ID/修订；核对期间继续输入或换号会拒绝旧票据。C2 仍负责固定快照、发布、旧 journal 优先级与原请求重试，没有修改对方 PublicationWorkspace/flow/API 或扩大业务权利。

返回使用 resume，只核对本人本机与服务器元数据，保留输入和原确认基线；旧读取不能回滚期间已经落盘的新文字。已确认 R1 而服务器有 R2 时，C1 仍传 R1，由既有 C2 明确选择，不自动替换正文。公开发布成功只确认 V，不确认任何新的草稿输入。

- 11 项真实服务整组通过，零 skip/todo；新增链路并入既有 drafts-service 测试，使用真实本机 3300 HTTP/MySQL 和 Node SQLite/WebCrypto，执行中篇编辑→实际票据参数→PublicationFlow 固定预览→正式发布→匿名阅读→只读返回，最后隐藏自己的合成作品。没有发邮件、访问既有作者私稿或使用 ECS。
- 新 C1 实际路由夹具通过：真正的 EditorRoute 与 PublishRoute/Workspace 共用会话及返回栈，固定 R1 而服务器为 R2、预览零正式发布、明确发布 V1、返回零草稿写、保持本机 R1；新稿入口遇到旧 journal 先只读恢复 V1且发布数不增加。还有原 C1-B 锁定恢复/失败/另存/退出隔离检查。
- 类型/lint、四套既有组件通过。契约/5 项门禁、冻结包、远程结果分别在最终收口追加，未执行前不借用旧绿灯。新增测试仍在既有分类文件，不新增未分类 .test.ts。
- 模型/真实 API 不等于 Expo 原生运行；路由夹具的导航、视图、存储和 HTTP 适配不是手机键盘/系统返回或 SecureStore 设备证据。

开发中测试传输器泛型不匹配已修正；保留栈让隐藏 textarea 也包含相同文字，已将预览断言限定到发布页。修正的是夹具误匹配，不为此改产品或放松断言。另以实际安装 Expo Router 58 源码核对 repeat/disablePrevention 行为，没有凭记忆改动对方返回保护。
