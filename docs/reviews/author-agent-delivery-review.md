# 作者服务Agent：回答校验与安全回退阶段

2026-11-04。业务/协作基线7ee5fa7，main30b68a0；开始fresh fetch无新发布，主开发继续N3与非Agent开发/设备。本包仅独立Agent源码、探针及本端记录；用户cv.tex不提交。

## 规格与实现

上一批发现模型误读限制、给错核对入口、自由解释扩大历史回执范围。本包解决“输出错误能否被交付层限制”，不通过改参考答案或反复追加提示词追求全绿。

- 模型仍选择工具及诊断；`diagnose`是完整诊断入口，始终返回顶层delivery。原模型verdict/evidence/usage留作评测资料，不能直接展示trial里的自由解释。
- `delivery.ts`只消费请求标识、实际工具证据与模型结构化提案；不依赖Case/expected/reference。检查指定资源、证据/状态修订、草稿关系、原结果限定与下一步目标。复用原事实校验与分页快照选择，未创建第二套用例答案引擎。
- 核对通过后用被验证的元信息生成受控解释，不转发模型自由文字；回执只说明历史，状态只说明观察时点，工作稿只来自draft metadata。同名候选与工具错误按证据说明，标题/正文/原查询文本不进入答复模板。
- 不支持的事实、伪造证据、无正式目标的详情导航、标识冲突或格式失败，返回明确fallback。回退不拼接原错误解释，不自动重试或补发；缺少目标请求标识或只读确认原结果。回退可以安全但不解决任务，指标独立。
- 底层推理错误不改成“成功”。SDK失败保留未知费用，公共入口返回incomplete+fallback；没有清费用或自动再次调用。格式空白且usage已返回时按usage结算，仍是未完成。

依据：[Anthropic有效Agent实践](https://www.anthropic.com/engineering/building-effective-agents)提出在步骤间加入程序检查；[DeepSeek JSON模式文档](https://api-docs.deepseek.com/guides/json_mode/)说明即使JSON模式也可能返回空白。本轮据此验证失败分支。具体业务规则仍来自Tako；没有引入评审模型、模型训练或多Agent。

三类关键变化：

1. older-display：原模型说display_limited=true，证据为false；拒绝交付这段诊断，回退未知与原结果核对，任务仍失败。
2. unconfirmed：没有可确认的正式作品目标，且作者限定只查原结果；拒绝open_work_detail，回退保留原预览标识，任务仍失败。
3. hidden：原结构化结论有据，原解释却扩大先审历史范围；现在只陈述原回执V2、当前隐藏及展示V1，不再转发那段自由解释。并未让模型本身变正确。

另发现初批人工/任务规则漏项：pre-review允许open_work_detail，但证据仅有历史先审submission，没有正式作品导航目标。新校验拒绝此建议；正确的先审参考解check_original_result仍通过。原批已通过的结论不被抹去，本批记录为额外不合适导航，不为维持旧分数放宽规则。下一包可通过明确提交记录入口改善业务完成度，不能现在伪造正式作品。

## 结果边界与下一阶段

本轮完成交付校验与回退闭环，**不是Agent准确率提升或生产可用性证明**。29单测不等于29模型任务，离线重放不是新模型样本，受控fetch不是真实供应商故障。人工复核者仍是本开发助手，未冒充独立标注或用户验收。CLI没有产品入口；任意外部调用方如果继续展示trial里的原解释，会绕过本轮交付边界。

下一完整包建议：**保留可核对的部分事实并完成下一步衔接**。针对三份回退，提供明确的原结果确认/已有先审记录入口，分别计“正确诊断、正确澄清、安全未解决”，验证固定案例和相邻反例，避免用全部unknown掩盖可用性损失。涉及新HTTP能力/正式导航权利时先按主开发唯一契约边界交接，Agent不新增发布权。

P1：真实供应商费用不明对账恢复仍未完成，扩大留出集/多轮规模付费前关闭；本次仅一次真实链路，没有扩批。P1：进入可切号App/服务前需输出时会话账号与代次复核，当前仅冻结会话的本机合成CLI，不将已有读取鉴权当作最终异步输出隔离已验。P2：语境标识解析范围有限，暂只支持既有中文ID写法，不能声称开放式实体解析已完善。共享CI接线仍归主开发，本轮是本机检查。
