# B3.1 人工后审与纠错闭环

## 背景与范围

B1/B2 已能发布正式版本并生成后审任务，但没有真实运营处理和作者纠错入口。本批次接通“运营查看固定正式版 → 处置 → 作者文字复核 → 维持/撤销 → 读者权限变化”。不把观察期、先审后发和自动规则算成已完成。

前端调整基线已本地提交 `0ad3ca1`；本轮 B3 实现单独保留，尚未提交或推送。B3 启动评审与已确认规则见 `increment-b3-kickoff.md`。

## 实现与取舍

- schema 9：后审任务有处理修订；新增独立处置、复核和不可变操作确认/审计表。现有版本/作品限制迁移为独立有效处置，撤销只重算相应范围，不改变作者隐藏和展示指针。
- OpenAPI 0.6.0：运营队列、固定正式正文、后审决策、处置列表/详情/撤销、作者处置查询与复核。运营是服务端 UUID 白名单，空配置默认拒绝，仍使用正常邮箱会话和同源写保护。没有授权读取私密工作稿。
- 账号→作品→任务/处置串行化，固定版本与审核修订防止旧页面覆盖新结论。操作确认与业务写入同事务；先返回原幂等确认，再检查在途/冷静期，避免丢响应后重试被误拒绝。
- 同一处置最多一个处理中申请，事务和唯一索引共同保证。维持时写入可站内查询的结论并开始 24 小时冷静期；按服务端时间判断，支持补充理由再申请。运营仍可主动撤销，不必等作者新申请。
- 待复核按较早申请先处理，所有队列和历史有 20 条稳定分页。显示等待时间及超过 48 小时提示；自动告警尚未纳入本批，超时不自动通过。
- 真实页面 `/ops/reviews` 与 `/moderation`；作品受限提示与设置区提供纠错入口。提交前显示目标、范围和理由，结果不确定沿用原标识；会话变化隐藏旧账号数据。保留公示的运营联系邮箱作为冷静期内人工帮助入口，不做聊天或自动业务邮件。
- 主动撤销的原因及时间从同事务写入的不可变审计记录读取，作者可直接查看；撤销后不再显示可再次申请倒计时。不能只改一个状态标签而丢失纠错解释。

## 验证

| 层次 | 证据 |
|---|---|
| 数据与事务 | 真实 MySQL/race：并发审核只能一个成功、在途复核唯一、冷静期到期前一微秒拒绝而到期接受、原请求重放不被冷静期拦截、撤销不改隐藏/展示、其他有效限制保留、注入审计写失败全事务回滚 |
| 分页与归属 | 25 条处置/复核，作者隔离，稳定分页不重复；运营待复核按递增 ID 返回较早申请 |
| HTTP 契约 | 路由覆盖、请求/响应验证；未登录 401、普通作者运营访问 403、私有资源归属 404、状态/在途/冷静期 409；恢复后读者权限正确 |
| 真服务浏览器 | 独立 writing_test，两个独立合成账号：运营读固定正式版，限制响应丢失后重试仅一条处置，作者复核，运营维持与冷静期禁用，运营主动撤销，匿名读者恢复访问。不是 API 夹具，不发送邮件 |
| 兼容 | B1 固定预览和发布重试、B2 历史撤权、隐藏中发布及恢复、受限作者导出和读者节点过滤继续通过 |
| 写作回归 | 最终构建下原九个登录、草稿保存/重开、断网恢复、冲突副本、跨账号隔离、存储降级、手机布局与过期会话场景全部通过 |
| 恢复 | 含治理数据的独立加密备份恢复，20 张表全字段指纹一致，约 27.91 秒；本机独立容器，不是 ECS/OSS 新数据验证或生产 SLA |

浏览器测试最初误把“重试按钮出现”当成原请求已结束，提前解除拦截造成测试竞态；修正为等网络失败反馈后再重试，不改变业务行为。读取、处置和表单截图只使用合成内容。

最终回归还发现前端发起新操作时保留上一条成功提示，导致可能将旧确认误认为新确认；已在选择记录和执行新操作时清空旧提示。回归必须等待本次操作的新确认，再检查读者权限，不能依赖旧提示通过验收。
