# 验证码发送阶段复盘 · 2026-10-29

## 本轮完成边界

收口上轮发现的“发送幂等与持久化缺失”，不扩展内容发布或推荐。当前能证明数据库与任务协议正确，不等于真实邮件系统已经验收。

## 已落实

- 入队事务同时写入挑战、加密载荷、发送任务及限流计数；相同 delivery_id 重放不生成新码、不重复扣额度。
- 独立 mail-worker，持久化租约与领取令牌，超时退避、过期跳过、上限停止、终态清除载荷。
- 因 SMTP 接受后确认丢失而重复发送时沿用原验证码，明确至少一次语义。
- 限量清理过期任务、旧会话、旧挑战和旧限流；幂等任务记录至少保留 24 小时。
- OpenAPI 0.2.0 同步新增必填 delivery_id、expires_at 与任务状态。自动化验证实现、路由与响应，未保留旧同步 sent 语义。
- API 访问日志包含 delivery_id，可关联 worker 事件；仍不记录邮箱、正文、验证码和凭据。

## 测试带来的纠正

1. 同请求竞争暴露了 INSERT IGNORE 再升级行锁的死锁风险，改为直接取得排他锁；十轮重复竞争测试通过。
2. MySQL 微秒精度与 Go 纳秒响应可能使重放的 expires_at 不完全一致，入库时间统一到微秒。
3. 超过最大尝试后丢失确认的任务，在回收终止时也需使旧挑战失效；新增测试。
4. 多个测试包共用数据库，可能相互领取邮件任务；用数据库命名锁隔离测试夹具，业务内的并发竞争仍实际执行。

## 验证证据

- MySQL 8.4 迁移至 version 3。
- `go test -race -count=1 ./...` 及 `go vet ./...` 通过。
- `go test -race -count=10 -run TestEnqueueAtomicAndIdempotent ./internal/identity` 通过。
- 覆盖并发幂等、异邮箱复用、冷却不部分写入、同码重试、租约恢复、多 worker、过期／消费／取代、终态失败和清理保留期。
- HTTP 登录到保存与契约检查仍通过。重放入队响应的有效期一致。

## 尚不可主张

- 测试发送器没有证明真实 SMTP 接受或收件箱送达。
- 新 Service 实例与租约模拟进程丢失，没有完成真实网络中断或整机恢复演练。
- mail profile 尚未因本轮调整自动启用，真实 SMTP 未配置；不发送测试外邮件。
- 没有监控 worker 存活／积压的告警验收，也没有公网部署或远程 CI 结果。
- 密钥备份与轮换仍需运行手册及演练；丢失密钥不能恢复待发载荷，不能靠重新随机生成伪装恢复。
