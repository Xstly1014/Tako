# 发布诊断会话隔离与独立业务探索

主线基线 `898803c`，主开发负责短内容发布与治理。本端实现 Node 侧诊断调用边界，保留 App、Web 与 HTTP 契约的现有分工。

固定查询入口 `checkPublication` 接受当前会话及结构化作品或原预览标识。每次读取前后核对账号和会话代次。失效时丢弃在途结果，旧句柄停止提供答复和下一步。下一步由调用方显式执行，只能沿用本次交付提供的只读目标。调用方应在显示时读取句柄，并在会话变化时清除已经显示的内容。该模块当前在 Node 运行，产品接线仍须决定运行位置与界面刷新，不能直接当作 React Native 模块使用。

46 项 Agent 测试与类型检查通过。实际 Session 类的受控异步测试覆盖切到另一账号期间的查询、同账号重新登录期间的下一步，均不交付旧结果。真实 test HTTP/MySQL 批次 `073861da-5aa8-4a25-a0b0-a711c5525bc0` 通过 19 项。新增检查在收到真实回执后暂缓交付，经同账号重新恢复会话，确认原在途答复、已完成答复和后续动作一并失效。合成作品已隐藏，会话已撤销。本次模型请求为零。

## 可独立推进的业务候选

| 候选 | 已确认的业务缺口 | 可以隔离交付的范围 |
| --- | --- | --- |
| 中篇审核逾期巡检 | 首期运营目标为 48 小时。现有工作台可人工查看时间，但主动巡检、告警恢复与负责人演练仍是开放前的 P1。先审列表已有 `first_waiting_at`，替换时沿用首次等待。 [业务规则](../increment-b-review.md) · [开放门槛](../handoff/07-primary-takeover.md) | 先做本地、只读巡检，使用既有运营队列权限，覆盖先审、后审和复核的分页、首次等待与待处理状态。扫描失败应报告观测不完整，不能当成积压清零。先验收去重和恢复结果，再协调负责人及通知渠道。正式运营接线属于主开发范围。 |
| 作者发布后的读者可见性核验 | 现有诊断根据本人回执和作品状态解释作者隐藏、作品受限或展示版受限。目前的“未记录限制”只覆盖已读状态。公开阅读接口提供另一份可直接核验的结果。 | 仅对作者会话已确认归属的中篇作品，从匿名公开入口读取当前展示结果，比较作品和展示版本。用测试环境区分真实不可见、请求故障、发布状态刚变化。仅保留必要元信息，独立在本端诊断和探针内验收。只有真实接口对照能发现现有诊断遗漏时才进入产品设计。 |

优先级建议是审核巡检先于读者视角核验，理由是前者有明确的开放门槛和验收规则。运营访问、告警负责人及通知权限需要单独定边界，本轮只完成候选调查，未认领运营实现。读者视角核验可在现有作者诊断目录里独立做技术试验，产品入口和新权限另议。

## 读者可见性核验

选择先交付读者核验，因为它可在既有诊断模块内使用现有接口，运营巡检留待对齐。Node 诊断句柄提供显式调用 `checkReaderVisibility()`。只有诊断已确认归属且结果可交付的中篇作品可查询。通过无凭据的公开阅读入口取得实际展示版本，前后读取本人状态，避免把期间的版本切换当作读者结果异常。输出只包含核验结果与版本号。原发行版本来自同一作品的已确认回执。

匿名 404 表示该次读取不可见。网络或服务错误返回无法核验。两次本人状态不同返回状态变化。同一状态下公开结果与本人展示信息冲突则单列。会话失效时放弃结果。

同步主线 `7f152ea` 后，类型检查与三项定向测试通过。真实 test HTTP/MySQL 探针 `f327c928-53e3-467d-8e8e-ad03908074ed` 共 21 项通过。V2 发行后切回展示 V1，匿名读到 V1。作者隐藏后，匿名返回不可见，V2 的原发行回执保持有效。合成资源清理完成。并发变化及传输失败通过受控输入验证。本包交付 Node 调用能力，App 入口由主开发另行安排。

## 处置复核后的可见性

`checkModerationVisibility` 接受本人处置编号，使用已有复核详情确认归属，再核对匿名读者结果。报告分别给出处置范围与状态、最近一条复核状态，以及当前是否可读。若确认作者隐藏、作品限制或展示版限制，返回相应状态。两次读取之间的处置变化返回重新核对结果。不可读记录沿用服务的统一语义。查询时沿用会话代次保护，结果仅投影状态和版本元信息。

主线基线 `b1278a4`。真实 test HTTP/MySQL 探针 `7010820b-9f60-411d-89f4-d8f1df021cc3` 通过 24 项。新增场景覆盖版级限制及待复核、另一账号无法读取、平台撤销后仍受作者隐藏、作者明确恢复后匿名读者看到 V1。变更动作由探针设置合成数据，诊断模块仅执行 GET。测试作品已隐藏，会话已撤销。类型及三项定向测试通过。本轮交付 Node 调用能力，产品入口由主开发安排。

## 本地作者查询入口

同步主线 `33c824d`。脚本 `scripts/check-author.ts` 将发布诊断和处置核验接入同一入口。用本地测试作者会话查询，可提供作品 UUID、原预览 UUID 或单独的处置编号。作品和原预览可同时输入用于核对归属。输出包括答复、可用的下一步和匿名可见性。调用完成后退出会话。

使用已有测试作者及实际记录验证了命令的作品查询和处置查询。前者取得本人诊断与匿名可见结果，后者返回处置状态。重复参数被拒绝。类型检查通过。本轮验收覆盖测试命令入口，正式产品入口由主开发另行安排。 [运行命令](../../agents/author-support/README.md)

本地作者命令增加显式 `--follow-up`。以原预览查询先审受理时，它执行诊断给出的只读下一步，返回同一提交的当前状态。原受理答复和当前状态分别保留。命令默认使用本地测试作者，也可通过本地环境中的 `TEST_AUTHOR_EMAIL` 与 `TEST_AUTHOR_PASSWORD` 指定另一测试账号，所有资源继续由当前会话校验归属。

真实 test HTTP/MySQL 探针 `e935d995-1acd-4e3f-b6aa-a847500bee1e` 通过 26 项。首次运行命令读到待审，合成作者从原入口撤回后，再跑同一条命令读到撤回。两次的提交编号和历史受理答复相同。类型检查通过，合成作品隐藏及会话撤销完成。

命令增加 `--submissions`，可分页浏览本人先审提交，并可按作品筛选。列表只返回标识、时间和状态，作者可用其中的 `previewId` 继续查询同一次提交。分页游标由服务绑定账号和筛选条件。该列表覆盖进入先审的提交。普通直接发行仍依赖原预览标识或作品状态核对。

主线基线 `539df1c`。真实 test HTTP/MySQL 探针 `553d9f73-4577-45eb-9fa2-4db67181f467` 通过 26 项。先从列表取回原预览标识，再分别查询待审和撤回，关联同一提交且历史受理答复一致。类型检查通过，合成作品隐藏及会话撤销完成。

## 先审替换后的当前待审定位

当原提交已被替换，显式下一步继续保留原记录及其历史受理，并附加同一作品当前待审的提交标识、预览和等待起点。该结果描述查询时的当前待审，不标记直接替换关系。分页完整走完仍未找到时返回 `none_observed`。查询失败、游标回环或超过八页时返回 `unavailable`，原提交的确认结果仍可交付。所有读取使用本人会话。

同步主线 `ef466b1`。真实 test HTTP/MySQL 探针 `f792b058-9763-4aa1-a0d0-a3d13cfc9ac5` 通过 27 项。命令验证旧单待审后被新单替换，旧回执保留，新单沿用首次等待时间。新单撤回后，旧单保持已被替换，当前待审未观测到。三项定向测试、类型及合成资源清理通过。

## 先审通过与驳回

原预览继续描述当时的受理结果。显式查询同一提交时，若记录已通过发行，返回该提交的正式版本，再单独核对读者当前能否打开及看到哪一版。驳回结果保留历史受理和当前驳回状态。正式版字段只在该提交确认为已发行时出现。

真实 test HTTP/MySQL 探针 `d6ac9117-0e3a-45f1-ad17-aa63736789ff` 通过 29 项。先审驳回时只返回驳回，另一次提交通过后核对到正式 V1，匿名读者读到 V1。作者隐藏后，同一提交仍为正式 V1，匿名读取变为不可见。类型、三项定向测试及合成资源清理通过。

## 作者答复与接入边界

本地作者命令将 `answer` 作为面向作者的文字，`explanation` 保留原回执的解释。显式执行下一步后，答复综合原受理、同一提交的当前状态，以及通过发行时的匿名读者观察。查不到当前状态时保留原回执，说明这次读取失败。返回的提交编号必须与原回执给出的下一步匹配。

真实 test HTTP/MySQL 探针 `3b9660ba-25c3-4cd9-aa93-8ece53fef246` 通过 29 项。新增文字断言覆盖待审、替换、撤回、驳回、通过发行及发行后隐藏，类型检查通过，合成资源清理完成。

本地作者流程至此可从先审提交历史找回预览，核对原回执和当前决定，再确认读者实际看到的版本。产品接入时使用同一会话绑定与答复投影，界面在会话切换时清除旧结果，作者明确操作后才读取下一步。主开发继续负责 App、Web 与 HTTP 契约。 [命令入口](../../agents/author-support/README.md)
