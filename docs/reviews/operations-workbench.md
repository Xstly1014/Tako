# 本地运营工作台整包

日期：2026-11-11（Asia/Shanghai）。代码基线：并行端 `9e2633d`，已同步主线 `4d8602b`。

## 业务目标与范围

将已交付的中篇运营命令串成可以直接使用的浏览器工作台：查看复盘与异常 → 定位班次和待办 → 核对/续查 → 接收交班 → 进入既有运营页面处理。精选检查作为独立入口。

用户本轮选择首页优先展示复盘报表与异常概览。因此首页展示最近班次、最近精选核验、观察时间与周期报表；积压与交班、精选核验为两个次级入口。概览只代表最近快照，读取失败、未检查、期间变更不能显示为正常。

仅新增 `agents/author-support` 下的本地工具及本端记录。既有业务 HTTP 契约仍由 `backend/internal/contract/openapi.yaml` 定义，本包消费原接口；本地工具命令桥使用独立 `workbench/openapi.json`，不挂载在业务 HTTP 服务、App 或主开发 Web 内。它不是线上运营部署。

## 交付规格

| 链路 | 行为与失败语义 |
| --- | --- |
| 首页复盘 | 读取最近报表，显示上海日期、期初待决、本期提交/决定、期末待决和截止时点；旧口径缺失项提示重新生成，不能伪补零 |
| 异常概览 | 显示最近班次完整性、待办和交班情况，精选位读取失败、不可读、恢复后待重选、期间变化分别保留；明确观察时间 |
| 开始值班 | 日期校验后异步串行执行原整班作业；同一工作台仅一项作业运行，重复启动 409 |
| 待办核对 | 原任务状态、决定、核对时间、运营处理入口；每页 20 条，按待处理/已有决定/需续查筛选；被替换稿的新稿读取失败仍算需续查 |
| 续查与停止 | 使用已有 SQLite 分段检查点，只续未完成阶段；停止通过 AbortSignal 中断请求，退出运营会话后结束；重启从班次历史找回 |
| 交班接收 | 只允许完整班次；接收人格式明确，绑定具体 revision；修订变更返回 `shift_changed`，首份接收记录幂等保留；不等于完成审核 |
| 历史 | 班次、复盘、精选均持久化；按编号倒序每页 20 条，游标不受插入新记录影响 |
| 周期对照 | 只比较完整、同口径、等长、已结束且不重叠周期；旧口径/倒序/未完整/未结束有稳定错误 |
| 精选核验 | 复用配置、匿名列表和实际作品版本核对；报告保存后显示六个位置及复查入口 |

## 本地接口与安全

启动：仓库根目录 `node --no-warnings --env-file=.runtime/local-test/.env agents/author-support/scripts/operations-workbench.ts`；地址固定 `http://127.0.0.1:3410`，只连接既有 `127.0.0.1:3300/api` 测试服务。运营凭据仍由本机忽略文件提供。

`GET /local/state` 读取当前进程作业，其余为 JSON POST：`history`、`report`、`compare`、`start`、`resume`、`stop`、`ack`、`curation`。`openapi.json` 是本地平面命令请求的校验源；请求限制 2048 字节、禁止未知字段和查询参数。报告响应复用现有版本化 TypeScript 投影，保留报告自身完整性，不把异步作业执行完毕等同于检查完整。

参考 [OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) 的来源精确匹配、Fetch Metadata 与自定义请求头建议。本实现绑定 loopback，检查精确 Host/Origin（含端口），拒绝跨来源 Fetch Metadata，要求进程随机 HttpOnly/SameSite=Strict Cookie 和命令请求头。不同端口同站请求同样被拒绝。浏览器不接收运营密码、刷新凭据或 API 会话。

页面使用外部脚本与样式、CSP、禁止嵌框、`no-store`、服务端生成请求 ID；上游错误仅转成固定错误码。认证限频提示等待窗口后手动重试，不清计数、不自动重登。页面文本通过 `textContent` 构建。参考 [Node HTTP](https://nodejs.org/docs/latest-v24.x/api/http.html) 配置请求头/请求时限与关闭连接，关闭时等待作业退出后才关闭 SQLite。

## 边界与退出条件

- 本轮退出：浏览器可完成上述整条本地运营链路，所有失败有反馈与恢复入口；不以只补命令或文档作为完成。
- P1：若要给多人或线上运营使用，由主开发确认统一登录、会话权限与部署范围后集成现有 Web；当前本地标签不是可审计的企业身份。该条件达成前禁止将本工具直接公开监听。
- P2：通知渠道保持用户已确认的本地事件和值班接收；只有确认实际通知目标、凭据和验收方式后再开外部投递。
