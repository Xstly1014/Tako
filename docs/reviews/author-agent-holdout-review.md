## 失败归因与业务决策

- **共同缺陷是对外错误语义不完整。** 标识冲突的六份答复均通过机器检查，交付拦截了跨对象状态，却用通用未知提示覆盖了“两个标识不对应”。作者沿建议重查原预览，仍不知道自己复制了两件作品的标识。P1，在进入产品前应在已验证两个标识的归属、且回执明确指向另一件作品时交付明确冲突提示与核对入口。资源不可读时仍保持原有模糊语义。退出条件是人工答复和动作都通过，且跨资源主张仍被拒。保留本次六条失败，修正后的结果另记。
- **Agent 的波动同时发生在取证和动作决策。** 先审两次已读到正确历史回执，漏的是原提交记录这一步。澄清后三类各有一次失败，分别来自把未知写成未确认、没有沿回执继续取证、没有消费新标识。同样任务在别轮通过，因此单次通过会漏掉这些问题。
- **这个范围优先选固定查询。** 两个分组的固定流程完成数都更高，六个用例中没有 Agent 独有的业务成功。在当前作者发布诊断范围内，固定流程是后续默认候选。Agent 保留为评测对照。重新评估的条件是收到固定查询实际覆盖不了的咨询，并在新案例上验证动态取证带来可重复收益。

本次样本是六个合成状态与输入组合，来自实际业务语义和开发失败，尚无真实工单分布或上线数据。三个澄清分支使用相同首轮问题及预定补充，因此结果适用于本次选择目标与补标识的路径。人工判读为本端单人复核。留出环境复用现有 GET 适配器，产品接入前仍需以真实会话和服务验收归属、标识冲突以及下一步入口。
