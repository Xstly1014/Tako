# App 读者账号与收藏 · 2026-11-01

## 背景与交付问题

用户将独立 App 作为主要开发端，并授权开发者自行完成常规回归。上一包只能匿名阅读；Web 已有注册和收藏，不能将这些能力直接记为手机端交付。本批目标为游客阅读→自主注册/登录→原作品→收藏→我的收藏再次阅读。规格见 [读者账号与收藏](../mobile-reader-account-spec.md)。ECS 保持停机，不连接、不部署。

## 实现策略

- 原生与 Web 共用账号、密码限频、MySQL 会话和收藏业务；不另建账号体系。新增 App 注册/登录/退出端点，随机会话带原生类型前缀，数据库仅保存散列，七天有效。
- App Bearer 与浏览器 Cookie 互用拒绝；Origin/Cookie 混入原生请求拒绝。浏览器写请求继续精确检查 Origin，没有放开 CORS、伪造 Origin 或把密码嵌入包中。
- 使用 Expo 58 官方 SecureStore 保存令牌，Crypto 生成幂等 UUID；密码只在当前输入界面内存中。安全存储失败不能报告登录成功，并尽力撤销新会话。
- 会话恢复区分网络故障与 401，账号切换使旧响应失效并重建私有视图。用户已确认断网退出保持状态、联网重试；本轮没有离线注销队列。
- 收藏复用服务端 revision/幂等回执；保留未确认请求再检查，隐藏/受限记录不泄露元数据且可取消。账号归属由会话验证，expected_account_id 只用于发现账号变化，不能授权。
- 首页、阅读收藏、“我的”和收藏页接入真实数据；个人中心按原型保留菜单顺序，未实现入口明确不可用，不提供假数字。原型文件不改。

| 原生设备 | 用户已拔下 USB；新账号/收藏包未安装验收，不能把上面测试记作 SecureStore 真机持久化或键盘/导航验收。旧版匿名阅读的真机证据单独保留 |

最终 Android 复建成功（4m32s，581 tasks），模板 debug 签名验证及内置 Hermes JS 校验通过；包 `me.takostory.app.test` / 0.1.0 / minSdk 24 / targetSdk 36，ARM64 与 ARMv7。APK SHA-256：`bc45b8a582dd127458e59ce5096459340d2905e247b5b8f4799dfb2e8b7e9bfc`。构建 sourcemap 中会话、收藏控件、账号页和登录表单与最终源码逐项一致。产物只在忽略目录，不进入 Git。

SecureStore 库声明了 USE_BIOMETRIC / USE_FINGERPRINT 普通权限，本轮没有启用生物识别门禁，也没有实测该能力。不得沿用旧匿名包“仅 INTERNET”描述当前包。当前验证是构建与静态包检查，仍不替代设备操作。

新凭据边界会使部分 GET 在混合凭据时返回 403，首轮契约测试发现文档遗漏；已补齐后重跑完整 MySQL/race 回归通过。没有新增数据库结构，本批无需 schema 14 迁移；A 的真机尾测和历史离机恢复不被本批替代。
