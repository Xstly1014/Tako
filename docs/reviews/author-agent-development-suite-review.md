# 作者服务 Agent：多任务开发评测与失败归因

2026-11-04。基线 `cfa4aeb`；本包代码检查点 `406e77f`，正常合入 main `30b68a0` 为 `aca77b6`。本文随下一包含它的提交发布。未推进 App/CI/设备或新的业务接口。

## 本阶段规格与交付

将起步任务落为11个明确标注来源的合成开发案例：隐藏、原结果未确认、草稿领先、旧展示版、跨页展示限制、作品限制、展示版限制、同名歧义、非本人、工具失败、先审受理。每例包含初始状态、问题、参考解、允许建议和证据断言，见 `agents/author-support/src/cases.ts`。模型只看到问题、策略与工具；期望答案/参考解不注入请求。

实现：真实模型驱动受控 HTTP transport、程序事实检查与任务目标分层、逐步落盘、失败/未执行计数、脱敏工具投影和答案重放、显式人工判定与原结果绑定。程序失败会令运行退出码非0；人工不通过不能被程序绿灯抵消。旧报告不改写，同一任务重跑创建新run。CLI不默认通过，不覆盖已有复核。

这是开发集，不是留出集、真实用户工单或生产客服。受控transport验证模型/适配器/评分器；真实HTTP探针验证实际权限与业务状态，两者分开。四工具投影前仍在进程内消费既有正文端点，不宣称服务端从未读取正文或已建立新字段级权限。

## 失败与改动的证据

1. **确定评分器缺陷，已修正。** 同修订的第一页display_limited未知、第二页已知，同时引用却取第一页而误判。参考解执行即复现；按最新修订选择已知元信息，同修订冲突拒绝。追加页序互换、矛盾布尔、较新修订不能借旧页补全。随后读到主开发对cfa4aeb独立审查的同一P2，接受结论，现有修正及反例覆盖其建议。
2. **确定任务规则过严，已修正。** 草稿任务只要求比较R2/R1，模型额外查到可靠访问状态，却因期望unknown被判错。改为非访问目标允许有证据的附加结论，仍执行事实校验。同一原始答案用v3无付费重放通过，原v2失败保留，不能记作模型变聪明。
3. **实际输出格式失败，有限复验。** 同名歧义没有返回可解析JSON。查 [DeepSeek官方JSON模式](https://api-docs.deepseek.com/guides/json_mode/) 后增加显式 `response_format=json_object` 选项，保留本地schema校验。相同问题单例复验通过；不足以证明格式错误率已显著下降。
4. **自然语言工作稿混淆，有限修正。** 初批展示版限制答案未查草稿，却将latest正式版说成工作稿。策略补“只有draft metadata revision能说明工作稿”，完整批该题未再出现此误述，但不是多次稳定性证明。

最后完整批次仍有三例失败，保留而不凑绿：

| 案例 | 观察与归因 | 处置 |
| --- | --- | --- |
| older-display | 工具display_limited=false，模型结构化与文字均说true；工具投影正确，属于模型对事实的误读 | 程序拦截，原输出不应进入产品回答；下一包增加输出准入/安全回退及反例 |
| unconfirmed | 正确说尚未确认，但没有正式work_id时把作者导向作品详情，偏离只核对原结果的目标 | 任务目标拦截，不放宽允许动作来换通过 |
| hidden | 结构化事实正确、程序通过，但把本次submission为空扩大成没有先审提交记录，又混淆能读取的可见状态范围 | 人工事实/不确定性检查不通过；狭义评分器尚不能覆盖全部自由文本 |

人工复核由本开发助手完成，不冒充用户验收、盲标或独立双人标注。逐例理由及与原输出的绑定在本地human-review.json。不同检查层各有边界：一致说unknown可以无事实错误，但未必完成任务；JSON正确也不保证中文解释正确。

采用方法依据是 [Anthropic Agent评测实践](https://www.anthropic.com/research/demystifying-evals-for-ai-agents) 中的任务/轨迹/结果分离与混合判定，以及 [工具设计实践](https://www.anthropic.com/engineering/writing-tools-for-agents) 中按实际调用改进工具；本项目具体判定来自Tako业务规格，不声称复刻企业内部流程。
