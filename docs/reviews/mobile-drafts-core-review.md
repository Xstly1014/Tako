# C1.1 加密草稿仓储与同步核心 · 2026-11-02

## 业务目标与交付范围

为 App 中篇私稿提供可靠本机暂存与服务器确认：断网和不确定回执不会重复创建，手机与电脑发生竞争时两份文字都保留，切账号后旧回执不能作用到新账号。已确认退出保留密文和离线续写规则，见 `../mobile-drafts-spec.md`。

本轮实现 `mobile/src/drafts/` 的记录模型、SQLite 密文仓储、Expo Crypto/SecureStore 适配、原生 HTTP 客户端与同步核心。没有接入草稿页面，也没有把离线授权/退出锁定挂到现有 Session；不能称为 App 已可写作。后端 API、OpenAPI 0.12.0 与 schema 13 无变更。

## 策略与已处理失败

- 用 SQLite 独占事务处理密文与修订提交，替代候选的手写文件切换协议。原生 `expo-sqlite` 通过 SDK 安装器加入；未手改生成 android/ios 文件。
- 按账号密钥 AES-GCM 加密标题、正文及冻结请求，AAD 绑定账号/记录/存储修订。已存在数据而密钥丢失时拒绝生成替代密钥；篡改或搬运密文拒绝读取，保留原记录。库中的 UUID/存储修订是索引元数据，不宣称整个数据库文件已加密。
- 首次 HTTP 前先事务保存 mutation_id、输入代次及完整快照。请求已提交但响应丢失时重读仓储继续确认原请求；成功后持久化回执，回执只确认其输入代次。
- 基础修订已落后则另存；检查后才发生竞争收到 409 时，把唯一 recover 请求落盘后再发送。恢复期间新写文字仍在本机，副本确认后继续同步，不覆盖原稿。
- 仓储失败不冒充已暂存，原请求落盘失败不发送。保存回执的账号代次、资源 ID 与修订都要匹配；会话失效/切号保留旧请求，不返回旧账号私密正文。
