# App 历史版本阅读复盘 · 2026-11-02

## 为什么做

App 的阅读、账号、收藏和评论已接入，但原型与 B2 已约定的历史阅读仍只有一个占位节点。读者无法查看修订轨迹或按作者授权切正文。本轮补齐这条既定链路，不将版本系统扩成新业务，也不改变原型频道编排。规格见 [历史阅读](../mobile-version-reading-spec.md)。

## 实现与边界

复用现有 `GET /api/works/{id}/timeline` 与 `/versions/{number}`，OpenAPI 仍为 0.12.0、schema 13；没有后端接口、迁移或新依赖。原生客户端加入响应字段/身份检查和分页去重，拒绝返回另一作品/版本或游标停滞的异常响应。

实际阅读页已接点线时间线；点节点显示次级日期/版本与权限说明，显式点击才读正文。切换成功统一替换正文/标题/标签/日期与评论上下文，调用滚动回顶部；失败保留本次正文。取消与代次保护阻止迟到响应覆盖新选择。受限节点只信公开接口，不补齐缺号。

评论面板始终归属当前作品，切版本不重建编辑器；未发表文字保留，已不确定的请求继续冻结原上下文和 mutation_id，不自动再发。收藏仍归属作品，返回不增加版本路由。错误显示安全的服务端请求编号，不打印正文或凭据。

- **31 项 Node 模型/客户端/真实服务测试通过，0 skip**。新增真实 3300 测试仅创建合成作者及两版合成作品；关闭历史拒绝新读、开放可读、再关闭仍拒绝；旧上下文的正常评论允许发表；运营限制旧版后节点/事件过滤、旧版新访问拒绝、已有正常评论保留；隐藏作品后新访问拒绝。测试最后隐藏自己的合成作品并注销会话，不修改存量用户作品、不发送邮件。
- **实际 ReaderScreen + VersionTimeline + CommentsPanel 组合夹具通过**，断网容器、React StrictMode。覆盖只看元数据、授权后换正文、评论输入保留、读取失败保留原文、迟到响应忽略、分页失败重试、去重与受限节点不补齐。SVG/原生控件和导航用 DOM 适配，滚动只检查调用；不是 Android 视觉/键盘/生命周期结果。
- App **typecheck 与 Expo lint 通过**；RN 0.88 ScrollView 使用组件引用实例类型；初始加载在异步结果回调更新状态，未关闭 lint 规则。
