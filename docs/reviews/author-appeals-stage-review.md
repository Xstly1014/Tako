# M4 作者处置与复核阶段核对

2026-11-03。对应[完整阶段规格](../mobile-author-appeals-stage-spec.md)。本阶段接续M3，承担处置读取、文字复核和结果返回整条App业务；复用B3.1服务端权利，不把既有后台实现算作本轮新增。

## 规格与实现

- 从本人作品工作台进入独立my-moderation路由。会话未在线确认时隐藏；本人处置分页，进入详情读取处置原因、范围、对应固定正式版本及历史复核。列表与历史使用独立before游标，客户端检查数值、降序、关联处置/作品/版本与分页边界，失败保留原结果；管理入口只传作品ID，不传私有正文。
- 理由仅页内存，按Unicode码点校验1～2000字；先显示范围/固定V/理由确认，单次生成mutation_id和expected_revision。网络、429、5xx或坏成功回执保留同一请求，阻止另写/换处置；明确400/401/403/404/409释放原请求，但新的申请必须等现状读取成功。
- 成功回执只标记申请确认，仍读取原处置ID；回执的申请ID不用于路由。后续读取失败保留“申请已确认”并只读重试；成功读取显示当前申请/结论。确认新申请时清除上次确认标记，防止新的拒绝沿用历史成功并丢弃新理由。
- 维持结论显示理由和服务端next_appeal_at，统一明确UTC；24小时资格由服务端校验，不用本机倒计时拦截或放权。用户可提交由服务器判断；冷静期、已在途和修订冲突分别解释。主动撤销展示独立原因/时间，不推断解除其他限制或公开作品。
- 未确认/待确认理由离开需明确选择；App关闭不保存正文、理由或操作标识，也不自动补发。账号代次、请求取消与epoch阻断迟到数据；离开后重入只读。系统返回与页内返回都有保护。
- 运营联系复用Web既有邮箱，按钮只在用户点击时打开邮件应用，不预填私密内容、不自动发送；打不开可复制邮箱。自动化适配器从不真正打开邮箱或发送邮件。

只增加独立作者API/协调器/页面、my-moderation路由、自己的工作台入口与测试；后端、OpenAPI、生成声明、认证/C1、小说、依赖锁及构建没有改动。主开发保留N2归属，不因其无发布接管在途工作。
