# 短帖举报治理 · 阶段交付

2026-11-16 开发与验收，2026-11-17 收口，Asia/Shanghai。用户告知主开发电脑故障并授权本端接续工作，随后确认本包业务和沿用的举报权利。基线为主线 `4322dac`、中篇举报 `80bca6b`。本记录不是生产上线或真机验收。

## 整条业务

App 阅读某正式图文版本 → 举报该版本 → 同账号同版重复请求读原记录 → 我的举报按中篇/短帖分开查询 → Web 核查原正式版标题、正文和有序图片 → 无需处置、限制原版本、限制整帖或关联已有生效轮次 → 回执留存与失败恢复 → 同一原生会话回查 → 匿名核验当前展示及原版本正文和原图 URL。

原作者后来修订不会替换举报证据。给作者的处置原因与给举报人的回执分别使用，不展示举报人身份，不按数量自动限制。规则与退出条件见[本包规格](../publication/short-post-reports-v1.md)。

## 实现

- API 0.39.0，迁移 **38**。独立 `short_post_reports` 保留同账号同版唯一键、队列和本人记录索引；数据库外键绑定真实正式版及该帖处置轮次。中篇契约和 `case_id` 语义保留。
- 八条接口覆盖创建、本人列表/详情、运营列表/详情/结案和固定原文/图片证据；OpenAPI、运行时验证、路由覆盖及生成 App 类型同源。
- 创建锁会话账号并在事务中验证公开可读，原记录先查以支持内容关闭后确认。运营结案按短帖 → 举报行的锁顺序，与处置撤销序列化；只接受该帖当前有效且适用于报告版本的 `case_revision`。同决定原请求重放，不覆盖已结案回执。
- App 复用举报页面和请求适配器，明确区分两种资源、接口及编号；切号/切类型重新挂载，失败保留说明，重开只回查、不自动补发。列表处理早期原记录回查及翻页重叠。
- Web 原图经报告证据接口授权，显示当前生效轮次；新限制与结案分步保留原请求，支持读取原回执、关联既有处置和重开恢复。匿名核验区分不可读与结果未确认，原版正文关闭时仍逐一检查已知原图 URL。

## Web 审计与兼容修复

`80bca6b` 的 Web CI 实际失败于 moderate 审计。官方公告 [请求路径判权绕过](https://github.com/nuxt/nuxt/security/advisories/GHSA-r99w-jh2x-3mg9) 与 [开发服务器父目录读取](https://github.com/nuxt/nuxt/security/advisories/GHSA-mjrq-cffv-q4qc) 均给出 4.6.4 补丁。本端在用户接续授权下将 Nuxt 4.6.3 升为 **4.6.4**，由 npm 更新锁文件，不降低阈值。

新 Nitro 消费 archiver 8；原兼容测试导入已移除的 archiver-utils、使用旧工厂 API，实际失败。本端按已安装上游源码与 [archiver 8 发布说明](https://github.com/archiverjs/node-archiver/releases/tag/8.0.0) 改为实际 `ZipArchive`，保留含中文文件、glob 排除、ZIP 头和动态资产追踪行为断言，没有跳过测试。干净 npm ci 和原 moderate 审计通过，仍为 **7 条 low** 的 deepmerge 传播链。P2：公开部署/下一次依赖更新前复核上游修复与不可信输入可达性；出现修复版或可达路径时升级或替换并复验实际消费者，禁止永久忽略。
