# 自主注册阶段复盘 · 2026-10-30

## 背景与目标

社区需要让团队朋友主动注册、写作和阅读。现有邮件发送受测试发件域名限制，不能把只有单个邮箱可收信的验证码入口当作对外可用的注册链路。用户选择私测无邀请、无邮箱验证，自主邮箱密码注册；社区发现、收藏及单层评论保持下一条业务链路，B3.2 暂缓。

## 实现与取舍

新增密码凭据表、注册和密码会话接口、存量会话首次设置密码、登录模式查询及密码页面。使用现有 MySQL 会话、同源保护和成熟 bcrypt，不替换草稿保存与账号归属机制。注册不覆盖旧邮箱账号；没有共享密码、预建账号或服务端认证绕过。

关键兼容问题是原验证码 Verify 按邮箱查找或创建账号：对未验证邮箱的密码账号，这不能继续作为可用的第二登录路径。因此 password 模式在服务端关闭发送及验证；即使误切回 email 模式，拥有密码的账号也不能经旧 Verify 接管。邮箱验证、邮件找回和账号合并均未引入。

首次设置密码只作用于会话自己的账号；同密码重试成功，不同密码不覆盖。注册结果丢失引导用原密码登录确认，不能把重复邮箱当成注册成功。散列运算并发及来源/账号频率均受限；测试不代表已通过真实攻击或高并发验收。

## 本机更新故障与纠正

api/web 容器重建后，本机 Nginx 静态解析仍指向旧地址，用户访问账号设置遇到 502。此前仅验证隔离环境、漏检本机网关，不能据构建成功声称页面已可用。重启网关恢复访问后，本机配置改用 Docker DNS 动态解析及共享 upstream zone，nginx -t 通过并热重载。之后切换密码模式再次重建 API，网关无需重启即恢复返回 200，页面与 OTP 关闭状态实测通过。原草稿浏览器回归在故障窗口失败，故障消除后重新运行，不能用失败前的结果替代。

修复网关后，9 项原草稿 Playwright 回归全部通过，包含断网后重新加载登录方式、跨账号文字不泄露及原账号恢复待同步文字。
