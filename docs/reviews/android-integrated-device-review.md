## 真机实际结果

### 账号与收藏：通过

真实手机操作贯穿游客阅读→从收藏唤起注册→回原阅读页→明确收藏→我的收藏→再阅读。笔名保存、杀进程后的 OS 安全凭据恢复通过。受控网络故障确实拦截请求，退出失败后保留当前账号，恢复网络后重试退出成功。错误密码被拒绝，账号 B 的收藏为空，未读取 A 收藏，最终回游客。

### 跨作品反馈收件箱：通过

从我的→作品管理→收件箱进入本人合成作品的指定讨论。中文/表情显示，未发表回复关闭评论后尝试离开触发保护，取消离开再打开保留原文；未发表文字不改变待回应资格。明确发表后待回应为空；在全部讨论打开原线程、删除自己的作者回复后，原讨论重新进入待回应。UI 与真实 API 条件独立核对。返回作品管理后单次“返回我的”到账号页。没有操作真实用户作品。

### N2 公开阅读：通过本节列出的场景

真实公开接口及原生 UI 读取一部 1001 章测试书，实际点击加载第二页并出现第 51 章以后的目录；隐藏/受限章节显示占位，不泄露合成章名。第一章 500 段中文/换行/表情正文实际打开、多次滚动、切后台再返回，已加载内容与位置保持。离开阅读后由本人测试账号隐藏该章，再从阅读地址进入被拒绝，没有从旧页面恢复正文；最后恢复该测试章节并验证目录→频道返回。

首章经真实作者发布 API 建立，其余章节是同一新建测试书的历史合成夹具，不是 1001 次真实客户端发布或容量测试。未逐章阅读全部目录，不代替三档屏幕、iOS、作者章节发行界面验收。

### 修订发行与未知结果恢复：通过，保留原生传输差异

首轮实际核对服务器 R2/正式 V1、明确采用、生成固定快照并点击发行。服务器提交后代理丢弃成功响应，观察到两次**相同发布标识/相同请求体**的 POST，均返回同一 V2；正式版本没有重复，客户端最终确认 V2。JS 请求层无自动循环，原生传输重试为待核实归因，不能写成“只发一次”。

第二轮明确确认旧结果后，重新核对同一 R2/当前 V2、采用并生成新预览；本轮两次相同请求的成功响应全部丢弃，客户端进入“检查原发布请求”。服务器仅新增 V3，匿名正文精确匹配 R2。解除故障、杀进程、重开并由作品管理重新进入原发布链路，安全存储中的最小原记录被只读确认 V3；本轮 POST 总数仍为 2、不同请求体 1、重开后新增 POST 0，服务端 R2 整份记录与发行前相等。进入作品管理→返回列表→单次返回我的通过。

收尾仅通过本人测试账号隐藏本轮合成作品和测试书，匿名两处均 404；私稿、正式版本、评论、加密记录保留。退出测试账号，App 回游客，USB 恢复 `3300→3300`，故障代理停止，没有清数据。
