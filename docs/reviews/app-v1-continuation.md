# App 原型 V1.16 补页

## V1.17 作品管理细化

用户指出“我的作品”的控件堆叠，操作路径不清。按已确认的紧凑目录和分组详情执行。三种内容形态采用文字标签，搜索和筛选共享一行，作品用可点击的细分隔文字行展示标题、状态、评论与收藏。详情优先呈现作品身份，再按内容、读者与记录、公开设置组织入口。

浏览器从“我的”进入，验证关键词与平台筛选叠加、选中作品、候选版本全文和确认弹窗、切换成功后的版本状态，以及返回目录保留条件。案例为合成内容和统计。此批验收聚焦中篇作品路径，短帖和长文管理详情仍沿用上一批呈现。

2026-11-19。用户要求在原 App 原型上继续。以 V1.15 源码和已确认的中篇作品列表、详情分组入口为基线。保留原开屏、角色素材、三形态布局、创作按钮、周边配色和立体书。新增页面样式集中在 `flows.css`，原 `style.css` 保留。

95 个子视图定义包含表单、选择、阅读、管理与结果状态。原型页内目录按业务分组，现有正常入口用于连续操作。弹层覆盖筛选、装帧、发布题材、阅读设置、付款预览及可改变状态的操作确认。完整入口范围见 [V1 说明](../prototypes/mobile-app-v1/README.md)。

浏览器实际完成原发帖入口到提交结果，核对权利未确认时拦截。由“我的”进入中篇详情，对照并切换展示版，重新读取到 V1。由原周边商品卡完成规格、缺地址阻断、补演示地址、订单与付款预览。由原短帖详情的更多菜单提交合成举报并读取说明。本地语法及 diff 检查通过。

P1 原生迁移出口：把现有会话、草稿、出版、评论和审核页面逐条绑定 V1 设计，确保保留权限、错误语义和恢复入口。当前是浏览器原型。部分状态和管理动作以合成示例表达，未覆盖真实服务或全部设备尺寸。周边真实订单、定制和关注权限仍需后续业务规格。
