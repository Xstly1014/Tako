# App 评论独立模块 · 2026-11-02

## 范围与交付

用户目前无条件连接手机，要求继续无依赖的开发与业务。实现评论客户端及内存编辑逻辑，暂不挂正式页面，不修改后端、OpenAPI、数据库或原生依赖。既有账号/收藏设备验收门槛没有消失。

- `mobile/src/api/comments.ts` 从 OpenAPI 类型接入主评论/回复分页、本人管理记录、发表与删除，验证字段、游标及作品/根评论范围；异常响应不当空列表。依赖注入现有会话请求方式，不存凭据、不伪造 Origin。
- `mobile/src/comments/editor.ts` 仅内存：游客输入带入确认、同账号过期重登主动恢复、切号清空与迟到响应隔离、未确认请求锁定并沿用原标识、失败保留文字和目标、关闭页面销毁。不调用磁盘或安全存储，不自动发表。
- 删除仍需未来 UI 明确确认，尤其根评论删整串；API 方法不因提供客户端就跳过确认。退出登录与账号过期在未来 UI 中需分别调用丢弃/锁定，不能仅凭编辑逻辑类推断已接入。

## 验证

- 最终 26 项 Node 测试通过：原有 14 项、新增 11 项独立评论逻辑/契约边界、1 项真实服务链路。
- 真实 3300 测试环境：正常自主注册测试读者、设置笔名、匿名阅读上下文、发表主评论和回复；先完成回复请求再模拟丢响应，重试后只有一条；删除根评论使公开入口不可读，两条本人管理记录为 deleted 且正文为空。
- 类型与 Expo lint 通过。纯逻辑测试可单独执行 `node --experimental-strip-types --test mobile/tests/comments.test.ts`，不需手机或运行 API；完整 `mobile/tests/*.test.ts` 仍需要已造数的 3300 环境。
- 首轮真实服务测试误以为删除后本人管理记录也应消失。核对既有实现后修正判据，保留删除墓碑与公开访问限制的区别；没有改变服务端来迎合测试。

本轮没有改 HTTP 接口，不重复宣称新增后端契约/迁移或真机成果。没有构建新 APK：代码未挂入应用入口，不能用新包编号冒充可体验功能。真实服务测试会留下合成账号与已清空正文的删除记录，不发邮件、不清库、不接 ECS。
