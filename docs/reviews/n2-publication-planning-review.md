# N2章发布与阅读规格复盘

2026-11-03。N1私密写作已实现，本轮仅完成N2具体业务/事务规格，不宣称新章发布接口或App入口已实现。主开发先整合同事M3～M5并回归，N2不接管其作者/发布/整体验收范围。

## 用户新裁决与原假设修正

主开发最初建议每书仅一章首次待审，用户明确拒绝：可多章独立排队，未过审章不能阻塞后续章。用A先提交/B后提交而B先过审的具体例子复核后，用户选择按提交顺序预约章号：B先为第2章可读，A通过后补第1章。用户另确认驳回/撤回保留原号，同章可改后重提，不给新草稿接替。

因此修改原规格“通过才分配正式序号”的假设，新增N-D11/N-D12及N41～N46验收，区分私密章ID、预约号、正式版本、实际发布时间/事件；不以已有代码简单就坚持单待审。预约事务失败不占号，受理后驳回不退号；旧审核不能作用于新pending，别章发布不能把早章审批一概判过时。

## 交付的规划

[ADR003](../novels/adr-003-chapter-publication.md)固化事务/资料首发/安全目录，[阶段规格](../novels/n2-publication-reading-spec.md)定义N2-A内核、N2-B公共读取与最低纠错、N2-C实际App完整联调。公开列表只含正式章，未审槽位不泄露，缺号合法；已正式隐藏章才安全占位。第一正式章可为2，后到1不能回滚书籍资料。最近发布章与最大章号分开。

规格继续要求固定预览、最小确认标识恢复、原权限/CAS、千章目录、最低限制/撤销/文字复核；无完结/追更/搜索/付费假入口。候选实体/路径只是实施方向，不预占迁移号，也不以Markdown代替API交付包。公共入口须等必要治理齐备。

本轮验证为决策一致性/本地链接/diff核对；N07～N17、N41～N46与千章场景仍未执行，均为N2实现的退出条件。下一步主开发N2-A迁移/契约/实现，旧中篇及同事共享schema片段必须保留。设备另待，ECS停机不影响独立开发。
