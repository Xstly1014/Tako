# 收藏与两级评论 · 业务评审草案

本批承接社区发现，补齐读者发现作品、阅读、收藏再访问和发表评论的链路。B3.2 继续暂缓。2026-11-01 用户将本轮评论从单层调整为两级，需重新确认主评论、回复的删除和版本规则；此前确认的收藏、已有评论公开与平台处置边界继续有效。本文不是接口实现或验收完成声明。

## 交付目标

读者从社区找到一篇公开中篇，阅读后收藏；进入“我的收藏”再次打开同一作品。登录读者可发表评论，作品作者能在作品评论区看到反馈。评论和回复均归属作品，不持久记录或展示版本归属。

首版包含收藏/取消收藏、我的收藏、发表评论、两级回复、评论分页、评论者删除、作品作者删除、运营屏蔽。回复已明确纳入；点赞与通知尚未因采用原型自动纳入，编辑、独立读后感及算法排序仍不在当前范围。短内容和长篇尚未实现，不通过造数假装具备这些能力。

## 本轮新增裁决

- 已确认：主评论删除时，其下回复一起删除，不采用保留子回复的删除占位方案。主评论删除操作须提示整串回复的影响；删除提交后不能新增子回复，重试或撤销平台屏蔽不能恢复被删除的整串。
- 已确认：不用记录版本。主评论和回复均不设置版本归属字段、不展示版本标签、不按版本拆分评论区。
- 已确认：所有回复平铺在主评论下，回复其他回复仅标记回复对象，不再增加第三层。删除某条回复仅删除该条；删除主评论才删除整串。
- 已确认：主评论本身被平台屏蔽时整串暂不可见；撤销后只恢复未删除、未被独立屏蔽的内容。单独屏蔽回复不连带屏蔽其他回复。
- 已确认：三个频道保持独立，创作者可在短内容帖子底部关联自己的长文小说，读者由关联卡片进入小说阅读。“作品管理”为口误，此处为“作品关联”，不授予管理他人作品或读者书架的权限。帖子与小说保持独立身份，不自动复制正文或变更所属频道。关联其他形态、数量及排序尚未确定。
- 周边为长期产品方向，本轮先完成免费社区链路，不因原型的主导航位置提前实现支付或实体履约。

## 已确认：收藏

- 收藏绑定作品，不绑定某个版本；切换展示版、发布修订后仍进入同一稳定作品链接。
- 同一账号同一作品至多一条有效收藏，重复收藏或重复取消不产生额外关系。
- 新增收藏时重新检查当前公开资格，不能凭过期卡片收藏已不可公开的作品。
- 隐藏或受限后保留原收藏关系；我的收藏只显示不可访问状态，不泄露标题、简介、作者笔名、正文等受保护信息，仍允许取消收藏。
- 恢复公开后原收藏关系继续有效；恢复收藏不等于重新入选人工精选。
- 游客可浏览作品，收藏操作需要登录；登录不能丢失原作品路径。

## 已确认：评论归属与提交

- 评论只关联作品、评论者、主评论及可选回复对象；不记录版本归属。阅读页面的权限上下文仅用于提交时校验，不写入评论记录、公开响应或原文审计，不作为读完作品的证据。
- 读者加载 V1 后，作者发布 V2、切换展示版或关闭历史阅读，仍允许读者在本次已加载的正常页面发表评论，评论归属作品。
- 提交前若作品被作者隐藏、作品被平台限制或来源 V1 被平台限制，阻止新增评论，保留读者输入。允许读完当前页面不自动赋予隐藏或受限后的互动权限。
- 服务端需要验证阅读上下文，提交时重新检查作品及来源版本状态；关闭历史阅读不应单独使已加载正常版本的评论失效。阅读上下文只证明服务端曾提供该版本，不证明用户实际读完，不授予重新读取历史正文的权限。
- 提交结果未确认时保留原请求标识与输入，检查/重试原请求，不能因丢响应发布两条评论。
- 已成功发布的原请求重放只确认原结果；不能在评论已删除或屏蔽后重新生成正文，也不能将旧请求解释成新的评论。

## 已确认：已有评论的展示

- 正常评论在作品下统一展示，不附版本标记或来源版本阅读入口。
- 作品旧版后来被限制，已有正常评论不因旧版限制自动屏蔽；评论本身违规时独立处置。
- 作者关闭历史阅读同样不隐藏既有评论。评论接口不附带不可公开的历史标题、正文或摘要。
- 作品整体隐藏或受限后，不通过独立评论接口绕过作品访问控制。
- 评论自身的屏蔽与作品/版本的限制分别生效；恢复作品或版本不会自动撤销评论自身的屏蔽。

## 已确认：删除

- 评论者可删除自己的评论，作品作者可删除本作品下的评论；第三方不能删除或编辑他人的评论。
- 统一称为“删除”，不提供“撤回”状态。删除后如需表达新内容，重新发表评论。
- 公共列表不再返回已删除评论的正文或作者信息；重复删除、刷新和并发操作不能恢复已删除评论。
- 运营可以因违规屏蔽评论，需记录原因与操作者。作者删除与平台屏蔽不能混为一个公开状态。
- 删除主评论覆盖其全部回复；删除回复只删除该条。主评论删除与回复提交并发时，以事务锁确保删除提交后没有新回复成功插入。

## 工程默认值建议

这些是本批可调整的初始边界，不代表质量判断或已测得的用户规律。

- 评论纯文本，去掉首尾空白后 1～1000 个 Unicode 字符；保留正常内部换行，拒绝纯空白，不解释 HTML。
- 单账号每分钟最多成功发表 5 条新评论；幂等重试不消耗新的发表次数，限流失败不清空输入。身份接口已有的保护继续生效。
- 评论按发布时间倒序，首批 20 条、游标加载更多；我的收藏按收藏时间倒序，首批 20 条。相同时间用唯一 ID 稳定排序，重复加载不重复插入。
- 不提前引入 Redis、消息队列或搜索系统；沿用 MySQL 事务、唯一约束和现有会话归属校验。并发锁顺序与现有隐藏、限制操作对齐。

## 已确认：平台屏蔽后的处理

用户选择：首版只向评论者展示平台处置原因，暂不开放评论复核，不为评论展示无效的申请入口。既有作品、版本的复核机制仍按原规则运行。

作品作者自行删除不计为平台处置，不进入平台申诉流程。运营保留主动撤销误屏蔽的能力，撤销需记录原因，且不能恢复已被评论者或作品作者删除的评论。评论复核列入后续治理评估；出现真实争议时重新评估，不将“无复核”当作治理可靠性的证据。

主评论被屏蔽导致的整串不可见属于父级可见性门槛，不把所有回复逐条改成被处罚状态。撤销主评论屏蔽时重新计算各条回复资格；已删除或独立屏蔽的回复仍不可见。

## 验收与交付边界

在独立本机测试环境实施与验收；ECS 正式环境升级需完成本批验证后再进行，不以测试库造数替代正式数据迁移。

必要场景：游客登录后返回原作品；收藏防重、取消重试与我的收藏导航；隐藏/受限收藏不泄露、仍能取消；收藏在作品恢复后可再访问；V1 加载后发布 V2 或关闭历史仍可按 V1 评论；提交前限制 V1 则保留输入并阻止新评论；已有 V1 评论继续公开但没有受限版入口；评论者和作品作者可删除，第三方拒绝；删除与屏蔽的并发结果不复活正文；原请求丢响应重试只生成一次。

评论处置专项：只有本人可查看自己的处置原因，运营能查看并主动撤销；普通读者不收到被屏蔽正文或处置原因，前端不展示评论复核按钮，接口不接受把评论处置 ID 当成作品处置 ID 申请复核。

接口交付包含 OpenAPI、错误语义、路由/请求/响应契约与真实 MySQL 验证；页面需要加载、空、失败重试、禁用和长文本状态，保持共享导航与移动端可达。工程通过后安排本人操作验收；没有外部样本前，不记录真实读者反馈率或回访结果。
