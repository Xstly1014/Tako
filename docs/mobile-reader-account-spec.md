# App 读者账号与收藏 · 2026-11-01

## 业务目标与顺序

App 为当前主要交付端，保留用户 mobile-app-v1 原型结构。先交付游客阅读→自主注册/密码登录→返回原作品→收藏→我的收藏再次阅读；随后接两级评论，再推进创作。Web/API 已完成的业务规则继续复用，不在两端分别定义权利。

用户已授权开发者自行完成常规自动化、真机回归，不再每一步要求本人实测。安装器授权、设备解锁或真实业务权利变化仍需用户参与。ECS 不连接、不部署，本批仅使用 3300 独立合成测试库。

## 身份与存量兼容

- 继续无邀请、无邮箱验证的邮箱+密码自主注册；界面明确邮箱尚未验证，不承诺邮件找回或拥有该邮箱。已有账号可用原密码登录，重复邮箱不能接管或覆盖账号。
- 邮箱、密码、笔名规则沿用服务端。密码不裁剪，输入错误保留邮箱；注册响应丢失不自动反复注册，提示使用刚设置密码登录确认。
- 游客可以阅读；收藏需要登录，完成或取消登录都回原作品，不自动执行一次未经再次点击的收藏。
- App 会话有效期七天，使用服务端可撤销随机令牌；数据库仅保存散列。每次登录独立会话，不替换 Web 会话。当前不引入 JWT、刷新令牌、多设备控制台或第三方登录。
- App 凭据只写系统安全存储，不保存密码、不写普通缓存或日志。冷启动先恢复凭据并校验账号；网络故障显示可重试，不将故障视为退出或清空有效凭据。明确 401 才清除过期会话。
- 账号切换前先完成退出；清空该账号私有视图和在途请求，旧响应不得填入下一账号。收藏等仍以服务端身份为准，不接收客户端 owner_id。
- 退出仅撤销当前 App 会话，不注销账号、不删除草稿/作品、不退出 Web。用户已确认：断网时提示退出未完成，保留状态，联网后重试；本轮不做离线注销队列，不能在撤销失败时虚报成功。

## 原生与浏览器契约

- 新增 App 密码注册/登录和当前会话注销接口，响应返回原生 Bearer 凭据，不下发浏览器 Cookie。
- App 不发送 Cookie 或伪造 Origin。原生令牌带专用类型前缀，Web Cookie 不能当作 App Bearer，App 令牌不能当作浏览器 Cookie。
- 浏览器写操作继续精确检查 Origin；原生入口拒绝 Origin/Cookie 混用。已有受保护资源允许合法原生 Bearer 身份；认证入口不因任意 Authorization 请求头而放开。
- 重用 MySQL sessions 和密码散列/限频能力，不新增第二套账号；请求 ID 由服务端生成，日志不含 Authorization、密码、正文或原始查询。
- OpenAPI 同时描述两种会话，路由覆盖、请求/响应契约、真实 MySQL 并发/隔离和浏览器回归同时交付。

## 收藏与界面

- 收藏绑定作品；重复操作沿用既有 revision/request_id 幂等契约，不以简单前端计数替代。
- 未确认结果保留原请求标识，可检查/重试；账号切换不会重放前一账号的写操作。
- 我的收藏分页，隐藏/受限保留不可访问记录且可取消，不泄露标题、作者、简介或正文。恢复公开可再次阅读。
- 主页保留频道和五位底栏；“我的”接入个人中心、我的收藏、退出。阅读底部收藏接入，其余未实现入口仍明确尚未开放；不添加假统计。
- 登录/注册沿原型 Q 版和表单形态，处理键盘、返回、取消、提交中、失败重试；不更改用户原型文件。
- 形态页尚无偏好持久化，本轮收窄文案为当前可用频道，不承诺尚不存在的阅读偏好设置。

## 验收与退出条件

1. 工程：类型、lint、契约、真实 MySQL；App/Web 凭据互用、错误 Origin、混合凭据均拒绝，退出后令牌失效但 Web 会话仍有效。
2. 真实测试服务：注册、错误密码、重复邮箱、重登、过期/撤销、收藏防重、隐藏/受限记录、账号 A/B 私有数据隔离，失败保留状态且不自动重复写。
3. 真机或可控原生设备：游客→登录→原作品、键盘/取消/系统返回、冷启动恢复、“我的”→收藏→阅读、退出→另一账号无串号。开发者自行测试，不把编译通过作为设备操作证据。
4. 阶段记录明确代码能力、工程/设备行为和真实用户结果；当前没有外部读者结果，不宣称社区留存提升或生产交付。
