# 中篇举报治理 · 完整阶段规格

日期 2026-11-16。用户明确将本阶段前后端、限定 OpenAPI 和迁移写入范围切给并行端，替代原“全部非 Agent 归主开发”在此业务上的约束。主开发继续短帖、设备及其他业务；发布记录不代表对方已读。

## 纵向链路

读者在已公开可读的中篇正式版提交举报 → 查看本人举报及原提交结果 → 运营 Web 查看原正式版与举报说明 → 在已有治理流程限制作品/版本或认定无需处置 → 保存举报处理回执 → 举报人在 App 读回结果 → 复查当前公开入口。

本阶段不以一个表单或列表作为完成。交付包含存储、契约、错误语义、权限、并发/重试、App 入口与本人记录、Web 核查和结果处理，以及完整业务的真实服务验收。验证按纵向链路检查点集中执行，不逐控件重跑全量测试。

## 已确认权利

- 2026-11-16 用户确认：同一账号对同一正式版本一条举报，包括已结案；重复提交返回原记录，不覆盖原说明。新版本可另行举报。
- 举报人只读自己的说明和处理回执。作者不获得举报人身份；无跨账号记录读取。
- 举报不自动下架，不依赖举报数量自动限制。限制及撤销复用已有运营权利与接口。
- 提交时服务端验证版本真实且当前可读，不能信任客户端作品标题、作者或 owner_id。正式版原文沿既有版本保留策略处理，举报表不复制正文。
- 内容后来隐藏或限制，不妨碍举报人读取自己提交的说明与回执，但不通过举报记录绕过原文访问限制。运营核查按原有运营权限读取。

## 范围与实现边界

并行端认领新举报存储/HTTP 文件、独立迁移（动手前核对编号）、OpenAPI 的举报路径和 schemas、生成声明中的对应片段、App 举报组件与入口、Web 举报工作台及必要导航。共享触点只作限定增量，不重排其他业务。原有身份、会话、锁文件、短帖逻辑和设备文件由主开发继续维护。

运营处理至少包括“无需处置”和“已按现有治理处置”，有明确处理说明与结果修订。与既有处置的关联需验证同一作品和版本适用范围，不能随意填写其他作品的 caseId 来结案。待处理/已结案读取采用服务端分页；并发处理和网络重试不能覆盖已结案结果。

## 验收出口

一位读者完成提交和断线重查；另一账号不能读取该记录；同账号同版重复返回原结果，新版可另报；作品变为不可读后仍可查本人回执但不能借此读取正文；运营完成核查与处置/无处置两分支；旧修订、关联错误、并发结案与重放有稳定语义；最终回到读者侧核对回执和实际公开状态。
