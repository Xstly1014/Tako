# 中篇观察期先审补齐（2026-11-04）

用户本轮明确选择与长文一起补齐。此前 publication.policy 在观察期返回 unsupported，不能再把它声称为先审已实现。本批由主开发负责中篇固定发布事务、迁移、唯一契约、App/必要Web待审接线及独立验收；沿用户新授权触及既有发布客户端，不接管同事反馈/列表布局/CI/原生。普通作者原正式发布行为保留。

## 既定业务边界

账号观察期作用于后续中篇/长文，默认7天，明确延长原结束加7天；结束不释放已有pending，同作品替换pending仍须人工审核。工作稿不被审核写回。作者明确提交固定预览后才能成为待审，不是预览就向运营暴露私稿。作者默认看原正式内容，可查看固定待审稿；读者只见正式版，首次pending没有公共标题或内容。

同作品最多一条当前pending；新提交替换旧pending，候选始终last_version+1，不增加正式版数量，保留首次等待时间/替换历史。通过才建立work_versions/正式展示指针；驳回留仅作者可见的原因与记录，撤回留记录。已通过/已替换/已撤回不能旧审核覆盖；撤回与通过竞争只一方成功。隐藏不取消待审，通过仍保隐藏；不解除平台限制、不覆盖草稿。运营只能读已提交固定内容，不读取其他私稿。到期/结束/换审核方式不自动批量发布。

## 契约与兼容工程决定

正常正式回执保留review_status=pending（后审）；新增pre_review明确表示已受理先审，version=0、published_at=null，携带submission_id/submitted_at，不能画成V0或成功公开。正式候选号只在本人提交详情作为次级信息。原预览消费结果与原mutation回执不可变，即使后来通过/驳回也不能改写原受理结果；现状走独立提交查询。消耗预览保留固定正文，不受24小时未提交预览清理影响。

列表20条分页：作者可看本人所有提交/按作品；运营只看pending。详情固定快照、状态/原因/首次等待和实际正式版本，不含任意私稿；决定/撤回使用原mutation、固定提交ID与载荷幂等，先保存原请求再发送，未知只查原结果，不随意重新创建。旧正式作者目录/发现/评论/收藏只沿已有正式版，不把首次待审伪装为作品已发布。

## 验收与退出

真实MySQL/请求响应契约/路由覆盖：普通发布兼容；先审不可匿名读；重复/丢响应；替换一候选且旧审核拒绝；结束后替换仍pending；通过/撤回竞争；隐藏通过仍隐藏；固定内容不随草稿改动；归属/ops拒绝与分页。实际App固定预览→受理待审→作者核对/撤回→运营通过/驳回→匿名正式读取，用同一合成数据；Web原发布与原操作恢复回归。迁移保旧数据，有新业务记录拒绝破坏性回退。

本机加法升级，ECS/邮件不操作；原生/系统Share/生命周期仍交同事，不以DOM或数据库测试冒称真实用户或真机。新范围未完成前不得宣布中篇观察期链路或N2整体收口。
