# 短帖举报治理

2026-11-16。用户确认本端接续同事范围并整包推进。基线：中篇举报治理 `80bca6b`，主开发短帖实现 `4322dac`。不推进 Agent 评测或新增模型调用。

## 完整业务与权利

读者从实际读到的正式图文版本举报，登录后填写说明；本人可分页查原记录与回执。运营按原正式版本核查标题、正文及有序配图，再决定无需处置、限制原版本、限制整帖，或关联已生效处置结案。结案后可复查当前公开图文与图片是否仍可读。

沿用用户刚确认的规则：同账号同正式版终身一条举报，重复返回原记录且不改原说明；新版可另报。举报不自动限制短帖。普通用户不能读他人的记录，作者不会得到举报人身份。报告说明和给举报人的回执不复制为作者处置原因。

短帖仍受已有 test 环境开关控制。新举报必须针对当前可公开读取的正式版，不能举报先审稿、未开放历史版、作者隐藏或平台限制内容。已有举报可在内容关闭后查询和重复确认。原文和图片的运营证据只经运营接口按该报告固定版本取回，不能借公开读图地址或作者私稿作为证据。

## 事务、恢复与兼容

复用既有短帖 `limit`、`limit_version` 操作和原请求标识；不新建第二套限制系统。处置编号是该帖的 `case_revision`，与中篇的 `case_id` 不同。结案关联必须是该帖当前有效且适用于目标版本的限制事件。撤销后或重新限制后，旧轮次不能用于新结案；已有历史回执保留原决定。

Web 按账号保存原请求、预期修订和处置阶段。结果未知时只继续原操作；处置成功而结案失败时可关联原生效轮次。不能用新请求掩盖冲突。切号及离页使旧回调失效，结案修订不允许互相覆盖。

App 沿用现有我的举报页面，分别进入中篇与短帖记录，不能混用两类编号；从短帖正文进入时携带服务端实际版本。原输入只在当前会话页保留，未知结果可从本人记录回查，重开不自动补发。

## 本包验收出口

后端、OpenAPI、生成声明、App 和 Web 一起交付。迁移 38 只在独立测试库执行。必要验证包括：重复、跨账号与非运营拒绝；历史/先审/隐藏不可新报；固定原图文证据；版本和整帖处置；撤销/旧轮次拒绝；相同结案重放与冲突；本人回执；公开正文和图片拒绝。只跑受影响的契约、真实 MySQL 链路及客户端模型和静态检查。Android 安装/真机、常驻环境升级和生产部署按各自证据另记。
