## 对照实际接口后确定的语义

1. 本人会话由现有 `Session.authorized` 提供；模型不能传 owner_id、token、任意路径。后端每次授权仍是最终边界。
2. 四工具：按标题找本人作品、读作品/版本状态、读服务器草稿修订元信息、查原预览发布结果。只准 GET。传给模型前剔除正文、简介及读者身份，不能读本机 C1 正文。
3. 正式版本第一页可能没有当前展示版。因此 `display_limited:null` 是未知，需继续翻页；不是 false。各页状态修订可能变化，不拼成同一快照。
4. 原预览的 `published` 是历史发布回执。其历史 `review_status` 不应被解释成当前审核或“提交未确认”，故不投影。无回执只表示查询时尚未确认，不能推断从未提交。
5. 404 对“不存在/非本人”保持同一错误。429/网络故障/契约错误不能被解释成作品未发布或未受限。
6. 证据 ID 是本地诊断标识，不冒充 HTTP 请求 ID。常规 trace 只记录摘要、错误分类、耗时；不记录正文、标题、原查询文本和凭据。
7. 推前同步 `89d83eb` 引入先审：`published` 可能是 version0 的历史受理回执。参照同事的中篇先审规格，适配层单独返回 `submission`，不能确认正式发行，更不能推断当前待审/通过/撤回。当前四工具不查实时审核详情，明确指引到既有提交记录。该新增边界成为下一包第11个任务，源于实际业务变更，不为凑规模添加工具。

## 试验与判定边界

首轮用真实本地测试 HTTP/MySQL 创建两个合成账号、草稿 R1/R2、固定预览及 V1/V2，再选择展示 V1 并隐藏。准备脚本可以写；Agent 单独获得只读 transport。每次创建新夹具，不复用其他测试用户的身份。未完成清理须显式失败，保护共享数据库和限频计数。

评分分三层：输入/输出及工具契约；结构化事实的资源与证据绑定；具体案例目标及自然语言人工复核。程序评分不要求唯一工具顺序。`unknown` 可以证据充分但没有解决问题，必须与任务目标分开计。已补反例防止用同作品的另一预览回执、旧状态或伪造证据蒙混通过。自然语言可能与结构化结论矛盾，尚需人工检查，不因 JSON 通过而放行。

模型真实调用只先跑一个开发任务；输入只含合成资源标识，未给答案或手工代填工具输出。没有真实用户工单，没有盲测，没有基线改进实验，也没有生产部署。原子账本预留、未知费用阻断及正常结算可验证，不宣称已完成供应商超时账单恢复演练。
