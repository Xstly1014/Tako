# 作者反馈工作台 · 完整业务包

2026-11-03，用户明确选择。并行端负责本人作品→反馈入口→线程/回复→既有作者删除→实际结果核对→返回原管理上下文。复用现有评论组件/接口，不新增通知、未读/未回复统计、评论复核或隐藏作品的私有评论读取权。

## 业务与边界

- 从本人作品管理进入独立反馈路由，只交接作品ID。坏ID拒绝；先按当前会话验证归属，再读取公共作品互动上下文。不能因作品公开就给其他作者工作台入口。工作稿/正式正文不投影进页面状态，评论不标记版本。
- 隐藏/整体受限或公共展示版不可读时不给评论入口，不自动恢复公开；进入后变化由原评论GET/POST再次检查，失败保留输入。状态已确认前不提供管理入口。
- 复用CommentsPanel的稳定分页、两级平铺回复、明确删除确认、服务端can_delete、原请求重查及刷新。作者删除主评论连同回复，删除回复只删该条，均沿既有权利；无批量操作。
- 收起评论只隐藏模态层，编辑器/原请求留在当前页内存。存在文字或未确认删除时禁止清空并重载上下文；离开页面必须提示丢弃，不隐式补发。正常返回原管理页不新建详情栈；会话变化后按原管理页隔离规则清除旧选择。同账号失效隐藏私有内容并保留锁定编辑器，重新登录并读回资格后提供明确恢复，访问读取失败可只重试GET，不销毁原编辑器；换账号清空原上下文。迟到读取不回填，关闭App不恢复评论文字。
- 仅新增本端author-works读取投影、反馈屏/路由、作品入口、已分类测试与既有本端验收；不改共享CommentsPanel/认证/C1/小说/OpenAPI/锁/构建/主开发记录。确需原组件修复先说明最小重叠，不能借复用接管评论模块。

## 验收与退出

模型覆盖归属先行、隐藏/限制拒绝、上下文/作品绑定、取消及正文最小投影。真实HTTP/MySQL覆盖本人/他人边界和隐藏保护，页面完整验证线程→作者回复→删除主评论及整串消失→返回管理；必要故障包含读取重试、未发表离开保护、未知写入原请求以及切号隔离。现有组件/服务/契约与工程检查按影响运行，精确CI确认后关闭P1；不得用旧SHA绿灯关闭本包。

用户设备暂停仍有效。P2原生返回/模态键盘/长评论/生命周期验收在用户恢复设备后按冻结源码执行；DOM+本地HTTP/MySQL不代表真机或真实外部用户反馈。
