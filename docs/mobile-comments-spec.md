# App 两级评论 · 2026-11-02

状态：业务规格、原生接口预检、评论客户端和内存编辑逻辑已实现；尚未接入 App 评论界面。既有账号/收藏新包设备验收等待手机重连，不把独立模块测试当成该门槛通过。

## 目标与范围

读者读完中篇后看到真实主评论，展开平铺回复，登录后发表或回复；作者与评论者按既有权限删除，评论者查看自己的平台处置原因。复用 `community-feedback-spec.md` 和现有 OpenAPI，不新增点赞、关注、消息通知、编辑、评论复核或推荐算法。

## 已确认输入策略

用户明确选择：全部只在内存中保留，不加密持久化评论草稿，不在 SecureStore、AsyncStorage、SQLite 或文件中写未发表正文。

- 当前页面正常驻留、收起输入面板和发表失败时保留内存输入；切后台仅在系统仍保留进程时延续。系统回收、强制关闭或重新启动不恢复，界面说明“未发表内容仅在当前页面保留”，不能声称已保存。
- 游客可写，登录前不发表。完成登录后明确确认是否带入刚才的游客文字；取消则不写入账号输入，更不能自动发表。游客文字未归属于任何账号，不默认为登录者意图。
- 已登录输入绑定当前会话账号、作品和回复目标。账号失效时保留当前进程内的输入但锁定编辑上下文；同账号重登后提供主动恢复选项，不自动发表。不同账号登录则清空原编辑上下文，不能查看或重放原账号文字；不能据此增加磁盘缓存。
- 有未发表文字时主动离开阅读页，提示“离开将丢弃未发表内容”，可继续编辑或明确丢弃；系统杀进程不能保证弹出提示。收起输入面板不等于离开页面。
- 本轮输入保护只针对评论，不改变 A 私密创作草稿的持久化与冲突恢复规则。

## 发表、回复与失败

沿用 1～1000 Unicode 字符、纯文本、限频、幂等与账号变化校验。提交只由显式“发表”触发，登录/恢复网络不会自动发表。未确认时保留原 mutation_id、正文、账号与回复目标，锁定该次请求供检查/重试；只有确认成功或明确失败后才结束这次提交。App 被关闭后这些内存状态也丢失，重新进入先读取服务器评论，不能自动补发或声称上一条未成功。

加载 V1 后普通修订不阻止本次正常阅读评论；提交前隐藏作品、限制作品或来源版本则阻止新评论并保留输入。阅读上下文只用于权限校验，不作为评论版本归属或“读完”证据，不持久记录或公开版本标签。

回复始终平铺在根评论下，仅标记回复对象；不新增第三层。目标删除/屏蔽后提交失败保留文字，用户重新选择目标或改发主评论，平台不自动改变其表达对象。

## 删除与可见性

删除根评论须确认全部回复一起删除；删回复只删该条。评论者可删自己的，作品作者可删本作品下的；其他用户无权。平台屏蔽根评论暂时隐藏整串，撤销只恢复未删除/未独立屏蔽部分。受限旧版不自动隐藏已有正常评论；作品整体不可读时不能绕过权限读评论。

评论者可在“我的评论与处置原因”查看本人原因，普通读者不能看到被屏蔽正文或他人的处置原因。首版不展示复核按钮。运营继续使用已有 Web 管理入口，不在本轮移植运营后台。

## 页面与验证门槛

沿用用户原型的阅读页评论区和底部输入入口：加载、空、失败重试、主评论/回复分页、输入中、发表未确认、权限变化均须有真实状态；不填假评论数或假头像身份。

用户确认当前继续无手机依赖的开发，因此允许先实现与验证评论网络客户端及内存状态逻辑；接入正式页面前仍须完成账号/收藏新包设备门槛。不能据此宣布 App 评论已交付。

验收需分别记录：真实 MySQL/HTTP 契约、账号 A/B 与游客权限、失败与幂等、App 键盘/返回/后台/切号、系统关闭后不恢复且无自动补发。常规回归由开发者自行执行，手机解锁与安装器授权才需要用户配合。
