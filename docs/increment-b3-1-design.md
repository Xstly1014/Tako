# B3.1 后审与复核实现设计

本批次处理正式版本后审，不创建先审后发提交。操作基于固定 work_id/version 和审核修订，决策为通过、限制版本、限制作品。每个正式版独立任务，运营授权来自服务端账号 ID 白名单，缺省关闭。读取固定正式正文，不读取草稿。

处置独立记录范围、原因、创建时间、状态和修订；从旧布尔限制迁移现存有效处置，撤销仅重算对应范围仍有效的处置，保持隐藏和展示指针。作者可申请文字复核；同处置单条在途由事务和唯一索引共同保证。维持结论写入时即站内可查询，设置服务端 24 小时冷静期。撤销关闭对应在途申请，作者仍可查询所有记录。

所有写入沿用账号→作品→任务/处置的锁顺序；先回放 actor/mutation 的原确认，再判断当前条件，确保丢响应重试不被冷静期误拦。不同操作者的过期处理返回状态冲突。操作者、目标、原因、幂等摘要及确认结果同事务持久化；日志不含正文或复核文字。

队列与处置/复核记录有稳定 ID 分页，每页 20，客户端明确刷新获取新增任务。后审展示首次等待时间和当前展示标记，超时不自动通过。本批首先人工队列，自动规则、48 小时主动告警和观察期在后续链路，不假装已实现。

HTTP 契约同步维护在 OpenAPI；未授权运营 403，资源非本人统一 404，过时决策/在途复核/冷静期 409，依赖故障 503。正文和 JSON 响应 no-store，所有写请求仍检查同源。

验收使用真实 MySQL：并发决策、响应重放、跨账号、固定版本、单条在途、24 小时边界、撤销不越范围、展示和隐藏不被改变；随后联通 API 与真实页面。迁移仅在独立测试库先验证，不以手动改库作为业务入口。
