# App 固定预览与正式发布 · C2

2026-11-02。用户在下一步规划后要求继续，由本端实现发布客户端、固定快照/发布状态、页面、测试。主开发继续 C1 草稿存储/同步/编辑；不修改 C1 或共享认证、依赖及后端。既有 B1/B2 与 OpenAPI 的业务权利不变。

入口为“我的 → 作品 → 发布服务器已保存稿件”。发布页只列服务器本人稿件元数据，不是第二套草稿箱。C1 后续可通过 `/publish?draft_id=<uuid>&source_revision=<服务器已确认修订>` 交接；接口仍校验当前会话归属。仅本机暂存/未确认同步的文字不能冒充服务器修订。传入旧修订时明确展示当前服务器修订，改用最新版必须用户主动选择；预览由后端读取固定修订，不取路由或本机正文。

简介最多 300 Unicode 字，标签 1～3 个，授权声明默认不勾选。未设笔名可在页内设置，保留表单。准备预览与正式发布是两次显式操作；完整展示标题、正文、简介、标签、修订、下一版本与有效期。草稿之后修改不替换快照。未提交预览有效 24 小时，已发布快照不可覆盖；过期或冲突提示用户检查，再明确选择新预览，不自动换稿或追加版本。

准备请求响应未知时，只在当前页面内存冻结原 mutation_id 和元数据，重试同一请求。此时尚无正式发布，关闭页面不保存正文或表单，重新进入需再次准备。离开提示风险，不静默补发。

用户明确确认：正式发布结果未确认时，允许系统安全存储保存按账号隔离的最小操作标识，重开后手动确认。记录只有版本标记、账号/草稿/预览 ID、服务器修订、原发布 mutation_id 和 expected_version；不含标题、正文、简介、标签、密码或令牌。使用现有 SecureStore，每账号一个未确认/待确认收讫记录，写入成功才发正式发布请求；失败不发送。记录损坏/身份不符保留并拒绝提交，不静默覆盖。账号退出或失效隐藏，原账号在线重登后才读取。

重开只 GET 原预览，已消费预览显示原确认；未消费时需要主动点击才沿原请求检查。结果未知时本机时钟过期不能阻止检查原请求，服务端决定是否已发布；明确过期才结束原标识。401/403 不删除可能已提交的标识。同账号多个页面通过写互斥与标识比较避免覆盖其他待确认请求，旧页面确认不能清掉新请求。正常确认后保留最小指针至用户明确收讫并重新选择，不自动发布下一稿。

恢复失败不能把新记录的请求标识与旧页面的成功结果组合：读取并校验完成后才一起替换目标，期间及失败后隐藏旧成功/快照，禁止发布和清除记录。用户明确重试读取；过期清理也须确认安全项仍属于所读的原请求，已被另一请求替换时继续保护，不借旧请求过期清除新标识。

发布确认不是公开或审核通过。成功后另外读取本人当前作品状态；隐藏中发布仍隐藏，受限状态不可绕过，当前可读按钮仍由真实阅读接口重新校验。首发绑定同一作品，修订增加正式版本；相同预览/原请求重试不得重复发布。API、schema 与生成类型不变。

发布结果已确认后，作品现状 GET 失败不撤销原确认，也不能显示成原发布结果未知。保留对应正式版本确认，单独提示现状未能读取，重试只 GET；在新鲜状态可用前不猜测公开/隐藏或提供公开阅读入口。

本阶段交付范围：服务器已确认稿件 → 固定预览 → 正式发布 → 作品管理/阅读。C1 尚未交付的手机写稿与同步入口不能算入本阶段已完成。P1：集成 C1、冻结源码并构建下一 APK；P0：真实移动作者交付前完成 SecureStore、关闭重开、账号切换、输入/返回等设备验收。电脑存储夹具和 HTTP 测试不能替代原生存储可靠性证据。
