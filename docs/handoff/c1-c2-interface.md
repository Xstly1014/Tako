# C1 → C2 发布交接约定

2026-11-02，并行端维护。核对基线：主开发 `de49a17`，本端 C2 `dc9e672`，集成 `b73fbe4`；本轮适配以包含本文件的提交为准。分工仍为主开发维护 C1/会话/离线授权/编辑页，本端维护 CI、作者管理、发布页。本文约定调用条件，不宣称尚未交付的 C1 编辑入口已经接通。

## 入口与来源

编辑页以 push 导航到 `/publish?draft_id=<serverId>&source_revision=<baseRevision>`，保留编辑页返回栈。两项必须一起传；`draft_id` 是服务器确认的非零 UUID，`source_revision` 是正安全整数的十进制字符串。不得传本机 `id`、`seq`、正式版本号、正文、标题、令牌或 owner_id。完全无参数的 `/publish` 保留为本人服务器稿件选择器；只传其中一项、重复参数数组、空值、浮点或指数表示均拒绝，不静默选最新版。

C1 在实际点击跳转时同时检查：

1. 当前账号、仓储 owner 和原操作 generation 一致，在线会话已确认；离线身份或仅缓存账号不能授权发布。
2. 当前编辑输入已经落盘，没有未完成的本机保存或同步；输入对应返回记录的 seq/内容。发布入口不能靠一次旧同步的完成事件驱动，跳转前还需核对当前编辑状态。
3. 最新返回记录 `dirty === false`、`pending === null`，有合法 `serverId`、正 `baseRevision` 和有效 `savedAt`。这些字段来自成功同步/读取确认，不在调用方猜测或自行置为已保存。
4. 冲突恢复改用返回记录的新 `serverId`；不要继续用恢复前的服务器 ID。`state === "recovered"` 单独不足以授权：`de49a17` 的同步器在请求期间发生新编辑时仍可返回 recovered 且 dirty=true。此时留在 C1 继续确认最新文字，不能把旧快照标成全部已同步。

C2 重新通过当前会话读取本人服务器稿件；路由参数只指定目标，不是服务端归属证明。C2 不 import `src/drafts/**`，不读取/改写 C1 的本机标题正文、dirty/pending/seq 或同步回执；预览正文仅由服务器按选定修订生成。两条链路不共用 mutation_id。

## 旧修订、失败与返回

- 传入 R1、服务器现为 R2：仍展示采用 R1 和当前 R2。后续准备请求固定 R1；只有用户主动选择“改用服务器最新 R2”才改目标，并重新确认发布授权。
- 传入修订大于服务器当前修订：拒绝进入准备流程，提示回草稿箱确认。旧修订不再保留、403/404 或发布冲突由服务器裁决，显示错误；不能自动换最新版、生成新预览或追加版本。
- 普通返回只退出 C2，不修改 C1。未提交表单或未知请求离开有提示；准备结果未知时原请求仅在该页面内存保留，离开不自动补发。正式发布未知另按下节恢复。
- C1 返回后重新核对当前账号和服务器元数据；若本机已有新输入，保留输入并走原 C1 保存/冲突策略，不能拿发布快照或服务器 GET 覆盖本机文字。发布成功是新增正式版本 V，不等于草稿修订 R 改变，也不代表作品现在公开或审核通过。
- 成功页可返回编辑页，也可替换到作品管理。C1 不能把返回、页面卸载或显示发布成功当成新的草稿同步确认。本轮夹具只验证 C2 返回动作及零写入；C1 实际栈恢复由编辑页实现后验收。

## 未确认发布恢复的优先级

用户已允许 SecureStore 按账号保存最小标识：账号/草稿/预览 ID、服务器修订、原发布 mutation_id 和 expected_version；没有标题、正文、简介、标签或凭据。存储成功才发正式发布 HTTP，存储失败不发送。

进入 C2 首先恢复该账号原记录，只 GET 原预览，不自动 POST。即使入口新传了另一稿件或修订，也先显示原固定快照和原结果，并明确提示与本次入口不同；不读取新稿正文、不替换原请求。原请求未消费时须用户主动点击才沿相同请求确认；已发布则展示原版本及另外读取的当前作品状态。明确收讫后回到选择器，不能自动发布先前传入的新稿。

网络/5xx/429、401/403、切号、损坏或账号不符的记录不能静默清除或覆盖。原账号在线重登后重新读取确认；其他账号看不到原记录。未知结果不能按本机时钟直接认定失败。只有明确服务端过期/确定拒绝或用户对已确认结果明确收讫，才按既有状态机结束原标识；同账号多页面按请求标识比较，旧页面不能清除新请求。
