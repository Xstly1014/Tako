## 建议任务：移动端检查流水线与干净电脑可复现性

这是交给另一端的方向，不是未经讨论就冻结的新业务规格。目标：让第二台电脑和 CI 能确认 API 类型未漂移、App 类型/lint/模型测试可运行，并验证交接中的首次启动路径。此工作能及时发现手机业务迭代的回归，且与主开发的页面/会话/评论实现分离。

先读本系列、AGENTS、skills、`mobile/AGENTS.md`，从本批最新 main 创建 `codex/mobile-ci-portability`。先在自己的机器上完成独立测试环境启动，记录实际版本、失败点及修正，不使用原电脑密钥、数据库或缓存冒充干净启动。

## 文件归属

| 范围 | 主开发（原电脑） | 并行开发（新电脑） |
|---|---|---|
| `mobile/src/**`、App 原型与视觉资产 | 负责账号/收藏验收收口，后续 App 两级评论规格和实现 | 只读；发现问题提交记录，不直接改页面/会话 |
| Go 业务、migrations、OpenAPI、生成类型 | 主开发统一协调，API 变更须完整契约/MySQL验证 | 只读；不能为 CI 改业务权利或手改生成类型 |
| `package*.json`、app.json、native plugins、构建脚本 | 共享高冲突文件，主开发维护 | 如确需修改先提出最小差异，单独约定文件归属后做 |
| 新的 `.github/workflows/mobile-checks.yml` | 不同时编辑 | 建议由并行端独占，先检查现有工作流再接入，避免重复服务/重复测试 |
| 新的 `scripts/check_mobile_contract.*` | 不同时编辑 | 建议并行端独占，在临时目录生成并比较契约类型，不能污染工作区或依赖本机隐藏文件 |
| `docs/handoff/parallel-ci-results.md`（新文件） | 只读 | 记录干净电脑复现、CI结果、限制与需要主开发配合的变更 |
| 本系列 01/02、current-progress、当前阶段复盘 | 主开发汇总 | 提建议，不同时重写这些文件 |

Web、ECS、部署、造短内容/长文数据、推荐系统、支付、重做 UI 都不属于这条并行任务。

## 建议验收方向

- 一次全新 clone 能按文档创建自己的 3300 环境，密码不复用原机、不提交。
- 工作流锁定 Node/依赖，覆盖类型、lint、契约生成一致性和现有模型测试；需要 MySQL/真实 API 的测试须真的提供服务，不能通过 skip 或 mock 冒充。
- CLI 能区分纯模型测试与依赖 3300 的集成测试。缺少真实服务明确失败或单独标记，不把未运行算成通过。
- 构建/测试失败输出不含密码、Cookie、Bearer、正文或 DSN。默认不跑真实发信、云端操作、Android商店签名或安装手机。
- 不要求一上来把完整 Android native 编译塞进每次 PR；结合缓存、耗时及公共 runner 条件提出可行门槛，让用户/主开发能评审成本。

## 合作与合并

1. 两台机器各用自己的分支/工作区/测试数据库，禁止同时推 main 或强制推送。每次推送前 fetch，核对远程新增提交和双方进度/重叠文件，先协调再合并与验证；本轮用户明确免远程对比，只适用于本轮。
2. 首次接手先报告准备修改的文件范围；跨到对方范围前停止那部分改动，交换最小接口/文件约定，其他独立工作继续。
3. 不自动创建额外代理/会话；这里描述的是用户已安排的另一台 Codex，不是授权无限委派。
4. 以小提交提交，说明问题、实际行为、验证层级及尾项。合并前 rebase/merge 最新 main 后重跑受影响检查；生成类型由契约重新生成，锁文件冲突不手拼。
5. 远程分支/PR 按用户当次授权操作；当前用户只要求主开发提交推送本批，不等于另一端可自行发布生产。
6. 不清理对方的源码或数据来消除冲突，不复制 .runtime、根 .env 或真实备份。
