# 05 · 主开发业务开发手册

2026-11-03，经用户明确的长期分工。与AGENTS和用户新指令一起使用；历史阶段中主开发曾构建/验手机，不代表当前仍负有该任务。

## 固定职责

| 工作 | 主开发 | 并行端 |
|---|---|---|
| 新业务需求、边界与规格 | 负责，业务权利不清时与用户argue | 按既有认领评审，不重复制定另一套规则 |
| 源码、OpenAPI、错误语义、迁移与兼容 | 在认领范围实现并集成 | 维护既有CI/M1/C2，跨文件先协调 |
| 模型/故障/组件、真实HTTP/MySQL、类型/lint/契约 | 主开发完成自己变更必要验证 | 维护CI和自身变更验证、独立复核 |
| 为真机冻结源码、APK构建、签名/安装、USB/ADB、手机操作 | 不承担，不自动探测或安装手机工具 | 负责本机执行与证据；按实际源码/包记录结果 |
| 构建脚本、依赖锁、原生配置的变更 | 仍是共享工程触点，沿约定单一写入方，不等同于亲自执行手机构建 | 提出所需差异，明确归属后修改；不能为设备临时绕过安全门槛 |
| 推送与真机任务交接 | 推送前同步；每次推送发布任务 | 读任务、认领、执行及反馈；不能把文件发布算作已读 |

本轮不把“手机可用了”解释成主开发必须先跑一轮真机。不购买/部署云端、发邮件或操作生产来弥补设备条件；ECS仍按用户关闭方向处理。

## 每轮开发的顺序

1. 读用户最新目标、AGENTS、business-first、对应规格和双方进度；用tako-collab同步实际main/对方分支。用户称同事无新进度不等于可忽略推送前检查，也不授权接管其未发布工作。
2. 说明解决谁的什么问题，核对现有能力和真实缺口；不靠新增中台、推荐参数或功能数量解释业务价值。
3. 对数据归属/丢失、跨账号、公开权利、删除/隐藏、商业化和范围的歧义提问；常规实现细节自主推进。规格区分已确认、工程建议、待用户决定；未决权利阻塞对应实现，不阻塞无关工作。
4. 按纵向业务链路拆段。API交付包含实现、OpenAPI、错误响应和必要真实MySQL/契约验证；App交付包含实际入口、返回、失败、并发/迟到响应处理，不能只做原型或基础类。
5. 测试强度随变更。区分纯模型、DOM原生适配、真实HTTP/MySQL、外部送达、恢复演练、构建和真机；不把一个层级替代另一个。不为纯文档跑全量构建，也不跳过失败用例换绿灯。
6. 每条链路/范围变化/收口更新自身review和primary-progress；对方报告与parallel-progress只读。不逐行写日报、不沿用旧SHA的审查覆盖新代码。
7. 每次推送前fetch→读新增进度/差异→核对重叠/共享接口→集成与受影响验证→普通推送→核对远程HEAD/CI。无新提交不等于对方闲置；禁止force、整份ours/theirs或手拼锁来抹掉工作。
8. 同一次推送将真机任务写入device-requests，包含具体运行SHA、前置API版本/环境、关键原生场景与通过判据；若仅文档或纯服务端且无新增原生变化，明确无需新包或重复设备测试。不是每次推送都要求重测整个App。

## 按完整业务包连续执行（用户调整，2026-11-03）

用户要求扩大一次规划与执行的范围，减少小任务反复Git/文档/CI收尾。当前按“规划后续三个业务包，连续执行当前一个”推进。N2-A/B/C是内部工作区，不是三次必须停下来等用户说继续的业务交付。

- 当前业务包有唯一用户结果、工作队列、归属和验收出口。实现、契约、失败处理、实际App接线及集成验证连续完成；不把一张表/一个接口/一个按钮当阶段成果。N2的完整任务队列见[阶段规格](../novels/n2-publication-reading-spec.md)。
- 本地提交可以小且可恢复，默认远程推送安排在必要的共享契约可消费检查点、完整业务包收口，或用户明确要求时；检查点推送后继续当前包，不自动结束工作等下一次指令。长时间/高风险开发可保留远程恢复检查点，不为减少流程放弃数据保护。
- 每次实际推送仍fresh fetch并检查main/真实peer分支；已读且SHA未变的技能、进度和差异不重新全文读取/播报，新增SHA才读新增事实与相关片段。自然检查点继续按协作skill执行，不在每个局部改动后全量同步。
- 对方新提交若与当前独占范围无依赖，记录待审和基线，在约定集成窗口批量处理；确定安全/数据丢失/共享契约冲突立即处理。不能让无关新测试/文档持续打断当前业务，也不能把待审代码说成已合入。
- 开发中运行有意义的局部失败/竞争验证；公开API检查点和业务包收口运行所需契约/MySQL及整合检查。全量通过后，没有新运行变化/失败/未解决疑点不机械重跑。CI等待期间可继续不依赖其结果的工作；结论必须绑定已确认的实际源码。
- 一份业务包复盘持续更新，不为每个内部任务建报告。CI结果随下一次必要提交补录，不为“补一行绿灯”默认再开独立推送/CI循环；纯文档不重新构建/要求设备验收。
- 技术实现、命名、SQL、分页实现等常规选择自主处理。仅新业务权利、数据丢失/跨账号、不可逆变化、必要范围改变或归属冲突需要咨询；等答复时推进不依赖的工作。不存在“每个内部小步骤需要用户审批”的规则。

本条减少重复流程，不豁免每次推送核对、API交付包、必要失败验证、阶段复盘、证据分账或已有安全规则。讨论执行方式本身不构成新业务完成，本次规划文档与后续必要代码检查点一并提交，不为流程讨论单独收尾推送。

## 收到设备结果后

- 先绑定对方实际源码、APK哈希、设备/系统和测试环境，核对与本轮运行树的差异；不拿本机夹具或旧包证明新功能设备通过。
- 自己范围的问题自己修；对方CI/M1/C2问题不抢改，提供复现/边界并继续独立工作。确定P0/P1阻塞相关交付，不把它永久记成“已知限制”。
- 对方的“部分通过”不能记为整个App或功能通过；源代码工程交付、设备体验、真实用户结果继续分账。
- 推送了任务尚未确认时，只记录“已发布/待领取”。通过仓库协作交接；没有可验证消息渠道时不声称已直接联系另一台电脑。

## 恢复与边界

服务恢复用tako-restart，只恢复本机3300/保留数据；跨电脑接手用tako-handoff。主开发和同事各有独立3300，端口相同不代表共享服务。改变对方环境前取得明确协调，不能自动复制其凭据、库或APK。

主开发只做本机代码/自动化所需的服务操作，不因本手册获得生产、真实发信或对外发布授权。密钥、正文、Cookie、DSN、原始查询参数不得输出或提交。未完约束必须有负责人、优先级和退出条件。
