# 草稿列表、保存确认与历史保留

## 列表契约

`GET /api/drafts?limit=20&cursor=...` 仅返回当前账号的标题、修订、保存时间、创建时间和恢复来源，不返回正文。按创建时间及 ID 倒序进行 keyset 分页，同一创建时间也有确定顺序；编辑不移动位置。

新建草稿在刷新第一页后可见，不插入已经开始的后续页。游标绑定账号，使用它不能获得其他账号权限。游标不是秘密，也不是授权凭证。当前不提供最近编辑排序、搜索或回收站。

## 服务端保存时间

写入结果与读取结果包含 `saved_at`（UTC）。确认值来自数据库，不使用浏览器本机时间。去重记录保存原始确认时间；后续出现更新修订后，重放旧请求仍返回旧确认，不能因此覆盖当前编辑状态。

版本新旧以 revision 为准，不能依赖时间戳；相邻操作可能具有相同保存时间。旧去重记录迁移采用当时请求记录的 created_at，无法重建原先未记录的精确正文更新时间。

## 快照与恢复

每次成功写入在同一事务保存正文、快照及幂等确认。冲突或失败不产生新的成功快照。历史读取必须通过草稿归属校验，恢复通过既有 recover 操作另存新草稿，不回退或覆盖当前正文。

这提供存储层恢复能力；尚未提供用户历史编辑器，也没有让普通管理员任意浏览草稿的入口。协助用户恢复的授权和操作界面仍需后续落实。

迁移前的草稿只补存当前快照，不伪造不存在的历史。

## 已确认保留规则

- 最近 24 小时保留每次保存。
- 24 小时至 30 天，按北京时间自然日保留当日最后一个修订。
- 超过 30 天的非当前历史可清理。
- 当前修订始终保留；独立恢复草稿的当前修订同样保留，不跟随来源历史清理。

清理最多每批 100 个候选，删除前按写入相同顺序锁账号并再次确认不是当前修订。历史抽稀不可逆，不能承诺保留期外仍可恢复所有修改。此规则只涉及历史快照，不清理当前草稿或草稿幂等请求记录。

## 运行

```sh
docker compose run --rm tools go run github.com/pressly/goose/v3/cmd/goose@v3.26.0 -dir migrations up
docker compose up -d --build api gateway
docker compose --profile maintenance up -d maintenance
```

maintenance 每分钟执行有界清理，只持有数据库配置，不读取 SMTP 凭据、不发送邮件。未启动该进程时历史不会按时抽稀；需监控其存活和失败事件。

全量快照有存储成本。公开测试前仍需测量写作频率、正文大小和历史占用，确定容量阈值与告警；当前未引入压缩、字数配额或自动缩短保留期。
