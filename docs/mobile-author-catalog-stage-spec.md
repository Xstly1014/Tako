# M3 作者作品检索与状态工作台

2026-11-03。用户明确由并行端负责完整前后端业务，先协调共享契约范围；本端承担规格、查询实现、App工作台、真实服务与整体验收。M2已进入main；本阶段不是继续增加M2零散入口。

## 主线与边界

本人全部中篇作品 → 明确提交标题/状态条件 → 稳定翻页 → 进入作品管理/修订发行 → 返回保留查询条件并读取最新列表。解决目前只能从20条起逐页寻找、无法定位隐藏/受限作品的问题；不以已加载数据的本地过滤冒充全量检索。

只查询当前会话账号的正式中篇。小说、章节、私稿正文和他人作品不纳入；不新增隐藏/删除/恢复/公开权利，不增加批量动作。

## 查询语义（本阶段工程默认，界面明确表达）

- 关键词为空表示不限制；非空1～64 Unicode码点，去首尾空白、大小写不敏感，拒绝换行/控制字符/坏UTF-8。只搜索当前展示标题与最新正式标题，不搜索正文、私稿或其他历史标题。
- 百分号、下划线、反斜线按字面匹配，不作为通配符。用户输入不进入日志。
- 作者状态：全部／作者未隐藏／作者已隐藏。未隐藏不等于已公开或审核通过。
- 平台状态：全部／受限／未受限；受限定义为作品整体受限或当前展示版本受限。两个状态维度组合取交集，隐藏且受限可同时命中。
- 列表显示当前展示标题；与最新正式标题不同时同时显示最新标题，解释关键词可能命中新标题。作品级和展示版本级限制分别呈现，不能合并成“作者隐藏”。
- 排序保持创建时间/ID降序，资料或可见性变化不顶列表。每页20，非事务快照；返回管理后保留已提交查询条件，重新读取首屏以反映刚完成的管理动作，明确说明已刷新，不承诺保留旧结果的分页位置。

## 契约提案与共享触点

在现有GET /api/my/works上增加q、visibility(all/shown/hidden)、restriction(all/restricted/unrestricted)。显式使用新参数进入M3模式；旧无参/UUID游标继续兼容M1。

M3返回带latest_title、display_limited的作品摘要及不透明游标；可复用AuthorWorkPage，在摘要上加向后兼容字段，并由M3客户端校验本模式必需字段。旧响应不强加新必填字段。M3游标绑定账号和归一化查询条件，不能用旧关键词/状态游标翻新结果；非法/重复参数/跨条件或跨账号游标返回400，而非空列表。不增加表/迁移，真实查询证据不支持时再评估索引。

本端认领backend/internal/publication的独立catalog实现/测试、httpapi/work_management的本人列表GET、OpenAPI中该GET参数/摘要相关schema及生成声明、M1客户端/工作台/测试。主开发继续N2目录/章发布与其schema；其他共享配置/依赖/C1/auth不动。具体片段与集成规则见handoff/m3-shared-contract.md。新字段不能改变现有platform_limited作品级语义。

## App行为

输入关键词/选择状态只改变待提交条件；点击查找或键盘提交才请求，结果说明当前已应用条件，未应用时禁止继续翻旧结果。刷新用已提交条件，清空显式恢复全部作品。

换条件/刷新/退出取消旧请求，所有迟到响应按代次和账号检查；分页用固定提交条件和原游标，失败保留结果、同游标重试、ID去重并拒绝循环游标。空结果与服务失败分别呈现。进入管理不改变筛选；返回按原条件刷新首屏，隐藏/恢复后不保留不符合条件的旧条目。切号立即隐藏并清除旧条件/私密列表，不持久化搜索历史。

## 三段交付与退出

1. M3.1：服务端全量检索/筛选/游标与兼容契约；真实MySQL、HTTP契约、跨账号及字面查询通过。
2. M3.2：实际工作台、状态协调、分页重试/迟到响应和管理返回；模型/组件绑定同一接口通过。
3. M3.3：超过两页的自有合成作品贯穿API→App查询→管理改变状态→按原条件返回；旧M1/M2、C1/小说组合与CI回归通过。

必须覆盖：仅第3页命中、A/B隔离、隐藏与展示受限交集、当前/最新标题不同、%、_、反斜线字面词、非法/重复参数、跨条件游标、标题/状态变更后的翻页、分页失败保留、清空/换条件晚响应、切号、管理返回刷新且不新增管理动作。

每段可提交可恢复检查点，M3完成按完整主线而非控件数量。工程退出须所有确定P0/P1处理，真实服务与CI齐备；设备体验单独待用户恢复USB后验收。本阶段无真实用户结果/高并发容量承诺，不把DOM或合成数据算成原生体验或运营成效。
