# 私测自主注册 · 业务确认与实现边界

## 用户最终确认

- 面向团队、朋友间的早期测试。游客可浏览阅读；用户自行用邮箱和密码注册后即可写作、发布及使用已经实现的互动能力。
- 不采用邀请机制，不发送注册验证码，不要求邮箱验证作为使用前提。注册主动权属于用户，不由运营预建共用账号。
- 邮件登录暂时收起，既有邮件实现、账号和内容保留。未来具备条件再评审邮箱验证，不因本次调整擅自回收或合并现有账号。
- 自主注册不等于公开上线或外部网络验收通过；可访问的私测环境仍需单独解决。

## 保持的基本行为

- 邮箱尚未验证，不能据此证明归属、重置他人密码、合并账号或取得他人内容。未验证邮箱不提供邮件找回。
- 每位注册者独立账号、密码与会话，继续由服务端校验草稿归属和运营权限。没有统一默认密码、共享测试身份或跳过会话验证的写接口。
- 已有账号遇到相同邮箱注册，不覆盖原账号和数据。已登录的原账号应能设置自己的密码并继续使用原 ID、草稿及权限；不通过匿名注册给旧账号绑定密码。
- 采用成熟密码散列能力和既有会话机制；密码不明文存储、不进入日志。保留必要的注册/登录频率限制和同源保护，不增加邀请、图形验证码或重型风控平台。
- 测试数据清理与账号回收另行明确，不将用户对内部测试风险的接受扩大为任意删除授权。后续验证策略不追溯自动转移未验证账号的内容。

## 下一条交付链路

注册 → 登录 → 设置笔名 → 创建/保存草稿 → 发布 → 游客阅读；同时验收已有账号设置密码、重复邮箱、错误密码、重复请求、跨账号访问及退出后的本机数据隔离。

先补状态/错误及 OpenAPI、数据迁移设计，再实现真实页面与服务。不将隐藏邮件按钮视为完成身份替代，不将本机测试视为朋友已经独立完成任务。忘记密码后的恢复路径仍待单独决定，不能使用未验证邮箱发送重置来冒充解决。
