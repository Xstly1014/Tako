# Tako 前端设计复盘与待评审方向

2026-10-30。依据用户本轮反馈、ui-deai 与 business-first。仅复盘与规划，本轮不改前端实现、不生成新角色图、不启动 B3。以下方案均为建议，不表示用户已批准视觉定稿。

## 当前结论

已有页面主要完成了业务状态的呈现，尚未形成统一品牌与信息架构。此前以减少卡片和改白底来纠偏，只修了一部分表面问题；内容主次、角色与组件关系、页面之间的共同语言没有一起设计。

源码证据：main.css 与 LoginPanel.vue 中出现 400/500/550/650/700/750/800/850/900 九档显式字重；品牌蓝并用 #285be8、#315bd4 等值，且 --green 实际承载蓝色。页面通过局部追加样式推进，缺少统一语义 token 和组件状态规范。该统计不是审美评分，只用于证明当前规则分散。

首页仍有英文装饰字、环形背景、概念图说明与彩色内容卡片；登录采用图与表单双栏，角色没有参与交互；手机仅把角色替换成小 Q 版。管理页将版本号/时间/状态/按钮整行平铺，作者第一眼需要同时处理太多层级。

## 品牌先定义成稳定规则

建议方向：年轻、有主见、略带俏皮的成年创作搭档；操作清楚，角色有趣，阅读安静。具体性格还需与用户讨论。

品牌结构：

- 主色：收拢到一个蓝色家族，选择后统一默认/悬停/按下/选中/禁用，不再逐页调蓝。具体主色尚未定稿。
- 辅助识别：章鱼发饰已有的珊瑚色，控制在 Logo/角色识别点，不扩大成全站第二操作色。
- 功能色：成功、待审、限制、撤回各有语义，配文字/图形，不与品牌色混用。
- 标识：tako 字标 + 从章鱼发饰提炼的小图形标；分别验证 16/24/32px、单色、深浅背景，不以每页文字加星号当完整 Logo 系统。当前字标与星形仅是早期占位，未形成定稿。
- 基础系统：统一中性色阶、界面字体/字阶、间距、边框圆角、图标笔画与交互状态。品牌展示、阅读正文和运营工具分别确定密度，不能套同一张页面模板。

ui-deai 的数值判据作为检查线索使用，不把固定色占比、汉堡菜单、行高公式或字重结论机械套到所有页面。正文阅读需要单独按可读性验证；动效时间也需区分眼睛眨动与组件过渡。

## 角色资产：角色身份、构图、状态分开

固定身份与服饰锚点沿用现有成年角色：蓝黑短发/蓝挑染、蓝眼、珊瑚章鱼发饰、蓝白街头外套、白内搭、深色裙装和不透明打底短裤、蓝白鞋。多动作不通过换服饰和换脸解决。

建立主设定参考与可复用图层规范：头/身比例、发饰朝向、发色、服装轮廓、阴影方向；精致版与 Q 版分别维护，交付独立素材而非合图。生成图目前可用作概念，但跨姿态的比例与衣服细节一致性需人工/逐图审查，不能靠提示词宣称自动固化。

| 场景 | 构图与动作建议 | 介入程度 |
|---|---|---|
| 登录初始 | 上半身近景，双臂搭在表单上沿，轻微探头 | 作为表单的一部分，占位稳定 |
| 邮箱聚焦 | 保持身体，仅眼睛看向输入区域 | 基于 focus，不读输入内容 |
| 验证码聚焦 | 目光移开或短暂闭眼 | 无密码输入，不暗示真实安全功能 |
| 请求处理中 | 安静等待/思考姿态，动作随后停止 | 与表单状态一致，不无限表演 |
| 登录完成 | 一次轻笑或小幅点头 | 让位给页面进入，不卡流程 |
| 空作品/空草稿 | 独立 Q 版翻本子或整理页签 | 小幅场景提示，不占内容主体 |
| 首页品牌 | 半身或中景，可改变镜头构图 | 一处明确品牌主视觉 |
| 阅读/审核操作区 | 正文优先，必要空态才出现角色 | 不常驻抢占注意力 |

移动端不因屏幕小就固定改成 Q 版；可采用同一成年角色的头肩近景。Q 版按场景使用。

规划表情包候选：招手、收到、灵感、赶稿、完成、休息、困倦、轻微无语。作为独立同角色资产，可先做设定清单，暂不生产整套。避免将嘲笑、夸张哭闹等表达用于审核驳回、保存失败或用户求助。

首批建议只制作一张表单接触姿态，以及睁眼/眨眼/移开目光几个可组合状态，再验证效果。身体/眼睛等局部层保持相同画布、锚点、光向；采用可控的分层图与轻量状态切换。技术选型待素材确认，不先引入重量级角色引擎。

## 角色交互约束

角色不能覆盖 label、输入文字、焦点环、错误提示或按钮；装饰层不拦截点击。身体和手与表单有明确接触关系，但输入区域本身保持清楚。状态资产同尺寸，换表情不让表单跳动；手机软键盘出现时不来回挤压输入框。

眨眼稀疏，目光变化围绕焦点，不按每次按键做动画。输入内容、邮箱、验证码都不作为表情分析数据，不接大模型。装饰角色不替代表单成功/失败语义；失败反馈用明确文字和重试操作，角色保持中性。

尊重 prefers-reduced-motion；后台标签停止计时，不播放声音。静态素材、动画禁用、图加载失败或脚本失败时，登录仍可完成。装饰角色不反复向屏幕阅读器播报状态。性能预算和具体动效频次需原型实测，当前不承诺帧率指标。

## 圆点时间线：把演进和详情分开

用户明确期望圆点—连线的简洁概览。建议平时只呈现节点、连接和当前选择，不逐个展开 V1/V2、日期、状态、标题和按钮。

点击节点仅选择预览，正文在主区域展示；版本号/精确发布时间/审核详情进入可收起的版本详情。设为读者展示需要单独动作及确认，不因选择节点直接公开切换。工作稿继续独立，不在该动作中恢复或回退。

两个必要区别：正在预览的节点与读者当前展示的节点；可用轻环/实心等有限形态区分，具体视觉需交互稿验证。待审/限制除颜色外还需不同图形与可访问名称，不通过一堆常驻文字强化。

读者侧仍只返回正常正式版本；历史关闭时点击旧节点明确提示正文未开放，不能通过 UI 简化而撤掉后端权限。受限版本及其目标记录不出现，保留原编号但不强行填补空缺。

作者需要处理的驳回/受限，可在作品层给一条简洁提示与定位入口；不把所有告警藏进圆点。普通版本元数据收起，影响行动的异常提示保持可发现。

大量节点采用有限窗口与翻页定位。移动端先显示少量节点，可进入完整历史；不把几十个小点硬挤在一行。可见点约 8～10px 的同时，触控命中范围保持足够大且不重叠；键盘可导航并选中节点，说明不能只靠 hover。实际尺寸需在原型中测量。

## 信息层级与文案

- 主信息：作品正文、当前任务、下一步动作。
- 次信息：选中节点含义、保存/发布/可见状态。
- 按需详情：版本号、精确时间、操作记录、问题编号和技术解释。

作者管理与读者阅读应各自组织界面，不能把管理台缩小后当读者页面。运营审核保留足够可追溯信息，但让任务列表、正文和处置动作有清楚顺序。

发布页的 R18/R19 等内部修订编号应进入详情，主要提示可用“工作稿又有修改，本次仍发布眼前这份内容”，并提供查看最新工作稿。反馈要对应具体动作，不用满页“状态已刷新/操作已确认”的过程说明替代结果。请求编号折叠到排查详情，不占据主要阅读区域。

## 后续步骤与验收

1. 共同确认品牌性格、主色与字标方向，形成小型品牌板和 token 基线。
2. 先做一个登录交互样稿和一个圆点时间线样稿，验证轻、清楚、克制；本轮不重做所有页面。
3. 确认角色与组件的接触姿势、眼睛层和镜头，再生成首批少量独立素材。
4. 定稿后实现复用组件，再推广到首页、写作、发布/管理和运营页面。已有业务权限、幂等与存储保护不因视觉重构退化。

检验问题：用户第一眼是否知道下一步；不看详情是否仍能完成常用任务；键盘/触控是否都能选择节点；长标题/多版本/失败与禁用是否可用；开启减弱动效、图片失败时是否仍能登录；跨页面是否复用同一套色彩和组件规则。用户本人审阅仍是视觉定稿依据，不能把自动测试通过当成审美已被认可。
