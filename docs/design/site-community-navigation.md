# 官网、社区首页与工作区导航

## 用户确认的定位

- 现有大视觉页面定位为 **Tako 官网/品牌介绍页**，不是社区首页；保留品牌张力和看板娘，并提供醒目的社区入口。
- 社区首页负责浏览真实内容。桌面参考起点与 B 站的信息组织；移动端参考小红书的信息流。共用内容身份和权限，不机械地把桌面三栏压成手机一栏。
- 用户给出的起点批注图是方向草图：Logo、Q 版形象、搜索、创作入口与账号区；分类、主推荐位、中篇图文和短内容文字区。不是完整规格，不将商业广告、榜单或推荐算法直接推定为首版能力。
- 等进入社区首页开发前继续评审布局细节；本次没有授权照搬参考站全部功能。官网社区主入口须与真实可用的内容浏览链路一起交付，不能先指向写作空间或空白占位页冒充社区。

## 导航缺陷与修正原则

实际根因：写作空间、作品管理、治理页分别维护导航，账号和入口位置不同；页面容器最大宽度分别为 1440/1280/1120/960，导航又嵌在内容容器中，跨页造成不必要的位移。

1. 官网、社区、创作工作区、运营工作区分别定义用途。创作相关页面共用稳定顶栏：品牌、固定导航组、账号组；页面操作（刷新、发布）放在内容工具栏，不挤占全站导航。
2. 同类工作区共享宽度、导航高度、左右锚点和字号。阅读正文可以更窄，但公共导航不能随正文宽度漂移。手机保持入口语义，并使用可展开导航，不能直接删掉必要返回入口。
3. 从作品管理准备修订、查看读者页、进入处置与复核，应提供明确的来源或所属页面入口。读者通过外部分享直接进入时仍有社区入口；不能只调用浏览器后退。
4. 不把任意 return_to 当作 URL 执行。若保存来源，使用站内允许路径和资源归属判断，并设置直接访问的默认去向。
5. 标题说明和主要操作保持各页面自身用途；统一导航不等于把阅读页、表单、编辑器与管理台全部做成同一内容布局。

## 同行评审的处理

同意：外部内容发现与反馈尚未建立，工程完成不等于社区价值验证；发信域名与外部入口阻碍真实用户；继续扩展治理规则前应重新检查优先级。

需商榷：评审中的代码/表数和“治理实现为零”是 B1/B2 快照，B3.1 之后已有变化；25%/70% 没有统一测量分母，不采用为进度指标。治理也是业务，最小人工处置与纠错有实际必要；问题是范围与顺序。搁置真机尾测不自动等于数据保护验收失败，但也不能当作外部用户价值验证通过。

评审文件中的冻结/删除/修改 AGENTS 等是建议，不自动成为项目指令。用户此前确认的功能不因外部评论而擅自删除。用户随后已确认暂缓 B3.2，优先真正的内容浏览与反馈闭环；不删除既有 B3.1。发现页首版采用当前真实中篇、人工精选、最新发布及标签浏览。
