# C1 下一步：离线授权与编辑接入

日期：2026-11-02。主开发维护，基线：C1 核心 `de49a17` 与已发布协作整合版本 `c905d7a`。本文件细化既定权利与接线验收，不宣称已实现，不改变评论仅内存或 C2 最小发布标识策略。

## 业务顺序

先完成 C1-A（授权保护与恢复），再做 C1-B（草稿列表/编辑与保存反馈），最后做 C1-C（已确认修订交接发布及返回续写）。目标是一篇中篇完成私稿→服务器确认→固定预览→正式发布→阅读反馈；不提前增加关注、点赞、推荐、B3.2 或其他频道模型，也不改变正式三频道首发范围。

## C1-A：本机可读与服务端可写分开

| 状态 | 本机草稿 | 同步/发布 |
|---|---|---|
| 首次使用/无匹配授权 | 登录入口，不创建游客私稿 | 禁止 |
| 在线身份已确认 | 只读写当前账号记录 | 同步可尝试；发布仍需最新输入的服务端确认 |
| 未退出的既有会话断网重开 | 只允许与该会话绑定的原账号离线续写 | 禁止；联网后先验证身份 |
| 已退出/明确认证失效 | 标题、正文、队列及他人未同步数量不可见，原密文保留 | 禁止；原账号在线重登后主动确认恢复 |
| 账号切换/恢复确认未完成 | 新账号不能领取原账号内容；确认前不展示原稿 | 禁止重放旧请求 |
| 本机授权/密钥/密文异常 | 不退回明文或自动换密钥；给出明确恢复失败 | 禁止把异常当成可同步身份 |

离线授权只证明本机此前的绑定，不是服务器会话仍有效的证明。密钥存在、路由 owner_id、本机记录中的账号字段均不能单独授权；同步继续检查实际在线会话和代次，后端仍按 Bearer 验证归属。

实现需将原账号、当前会话绑定标识和允许/锁定状态持久化，凭据仍只在现有安全存储；不另存密码或正文。主动退出或明确失效后的锁定不能因断网重启被旧缓存覆盖。写入安全状态失败不得报告“安全退出/恢复完成”，界面先拒绝私稿访问且保留原密文；具体提交顺序以失败模型验证，不靠 finally 清空状态掩盖持久化失败。

沿用断网退出未完成、保留会话供重试的既有行为，不增加离线注销队列。会话恢复时的网络/503不能当作明确认证失效；但也不能凭一份未匹配的旧账号缓存给新会话开离线权限。已有评论、收藏、M1/C2 的 generation 和账号隐藏规则不得回退。

## C1-B：草稿列表与编辑

从原型加号的中篇入口及“我的→草稿箱”进入，真实新建/续写，未登录先登录。服务器稿件与本机待同步稿按当前账号合并展示，不能覆盖本机脏记录或用合成占位充数。

编辑页区分“未暂存、已暂存本机、同步未确认、已获服务器确认、已另存副本、需重登、暂存失败”。保存失败保留输入；旧回执不能确认新输入。恢复副本使用返回的新 serverId 继续写，不覆盖原稿。

主开发维护新草稿路由/列表/编辑组件及加号、草稿箱调用点；个人中心保留对方 M1 已接“作品”入口。只调整 logout/草稿相关触点，不重写另一端作品管理和发布页面。按 ui-deai 和既有手机原型安排信息层级，明确来回导航，不为接入重排频道。

## C1-C：发布交接与返回

采用对方维护的 `docs/handoff/c1-c2-interface.md`，本端已阅读并接受其与既定业务一致的调用条件；C1 调用点仍未接通。实际点击时校验：

- 当前输入已成功暂存，且与最新同步记录 seq/内容一致，没有正在写入或同步的更新。
- 账号/代次/仓储归属一致，在线身份已确认，record.dirty=false、pending=null，serverId/baseRevision/savedAt 均来自确认。
- 仅传 `/publish?draft_id=<serverId>&source_revision=<baseRevision>`，用 push 保留编辑返回栈，不传本机正文或 owner。
- recovered 单独不足以授权。仍 dirty 或有新输入时继续同步，不发布旧快照冒充最新文字。
- C2 返回不等于一次草稿确认；保留本机新输入，重新检查账号与服务器元数据，不能用发布快照覆盖工作稿。
- C2 旧未知发布恢复优先，不清除或覆盖其最小标识，不与 C1 共用 mutation_id。

本端验证 C1 的拒绝/允许条件、调用参数和返回续写；并行端维护 C2 的入口消费与最小标识恢复，双方各维护自己的测试。最终整合后冻结源码构建，新包指纹与真机门槛分开记录。
