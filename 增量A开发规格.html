增量 A：登录与可靠草稿保存

状态：已进入实施，邮箱真实收件与页面登录已验收；可靠草稿主要能力已实现，增量 A 整体验收尚未完成。当前实现与缺口见 进度总览。业务承诺来自已确认基线；本文中的具体方案和参数是建议默认值，允许在实现前调整。目标是在真实环境完成“登录 → 写作 → 服务端确认保存 → 关闭 → 重开恢复”，不包含公开发布。

1 · 范围与非目标

包含邮箱验证码登录、首次创建笔名、私密草稿列表与编辑、自动保存、本地故障保护、多设备冲突保留、退出登录、最小运行诊断与恢复演练。

不包含草稿删除与回收站、完全离线启动、公开作品、评论、推荐、版本公开时间线、实时协同、富文本排版、附件上传、支付与完整运营后台。A 没有公开内容，先提供健康检查和不含正文的运行诊断；内容处置后台随 B／C 引入，不能用此为由提前开放未具备治理能力的公开发布。

2 · 核心不变量

  • “已保存”只在数据库事务成功后显示，并关联确定的服务端修订号；不是收到 HTTP 请求就算成功。
  • 草稿始终归属于一个账号；列表、读取、保存、冲突恢复都在服务端检查归属。不可凭草稿 ID 或本地缓存取得他人正文。
  • 任何过期写入不得静默覆盖较新版本；冲突必须保留双方内容。
  • 草稿内容不得进入应用日志、告警、分析事件或验证码邮件；邮箱与会话凭据同样避免明文记录。
  • 草稿保存修订用于恢复和并发控制，不等于未来作品公开版本。
  • 服务端确认保存不等于已完成异地备份；两者状态与指标分别管理。

3 · 用户流程

步骤行为与结果
请求验证码输入邮箱，收到统一请求结果；无论新老账号均不透露注册情况。失败明确可重试，限流给出等待提示。
验证并登录有效验证码一次性消费；不存在账号则创建账号。首次填写笔名，允许重名，身份靠内部 ID 区分；不要求实名或校园认证。
新建草稿在线创建并取得稳定 ID；重复创建请求返回同一结果。标题可空，列表显示“未命名草稿”。A 暂不支持断网新建，创建失败保留已输入内容。
编辑与保存输入立即进入当前设备暂存，随后串行提交服务端。页面显示保存中／已保存及时间／仅本机暂存／保存失败／存在冲突。
重新打开读取服务端内容并检查本机是否存在未同步修改；不能用旧的本机缓存自动覆盖服务端新版。
退出直接退出，保留本机草稿，不弹确认、不自动删除。在线撤销会话；撤销失败明确提示，不虚报成功。原账号重新登录后自动恢复同步，其他账号不得查看或接收这些文字。

4 · 保存协议与并发

建议采用完整正文快照保存，首版不实现字符级补丁。请求带 draft_id、base_revision、mutation_id、标题和正文。正文长度按 UTF-8 字节校验，字符计数仅用于界面提示。

  1. 事务内校验归属、大小与当前修订号，使用条件更新或等效并发控制，禁止先读后无条件覆盖。
  2. 相同 mutation_id 与相同载荷重复请求，返回原结果；相同 ID 不同载荷拒绝。去重记录与保存同事务提交。
  3. base_revision 相符则保存新修订并增加单调修订号，返回 revision、服务端保存时间。
  4. 不相符则保留当前服务端正文，自动把本机未同步文字另存为服务端恢复副本；成功后继续编辑副本，不自动合并、不要求立即整理。失败仅提示本机暂存，不能宣称双方已在服务端保留。提供查看两份和导出，不做逐行合并界面。
  5. 恢复操作必须幂等，重试、多标签页和重新登录不重复生成副本。保存原稿与副本关联，恢复期间的新输入继续写入副本，不能丢失。成功后标记本机已同步，不因退出清理正文。
  6. 单个编辑器最多一个保存请求在途；期间继续输入的内容排队合并。旧请求的成功响应只能确认其对应内容，不能把仍有修改的编辑器标成全部已保存。

网络超时属于结果未知，不自动宣告保存失败或生成新 mutation_id；重试原请求，必要时读取服务端状态确认。会话过期只暂停服务端同步，不跳转、不清空、不弹窗打断，不限制继续编辑时间；持续提示未同步。原账号重新登录自动同步，无冲突正常保存、有冲突自动另存、内容相同不重复写入。登录其他账号不转移文字。

5 · 本机保护与账号隔离

  • 建议用 IndexedDB，按账号和草稿隔离，记录正文、基础修订号、保存时间及待同步标识；不用 localStorage 存登录令牌。
  • 浏览器禁用存储、配额耗尽、隐私模式异常时，明确提示本机保护不可用，服务端保存仍可继续；提供手动导出。
  • 多标签页使用通知机制发现同草稿编辑；最终一致性仍由服务端修订校验保障，不依赖浏览器锁。
  • 切换账号不展示上一账号缓存；登录其他账号不能提交旧账号待同步内容。退出直接保留缓存，产品界面仅允许原账号重新登录后恢复。缓存不是加密保险箱，账号隔离不等于设备加密。清理是单独操作，不与退出绑定。
  • 关闭提醒只能作为辅助；移动端可能不触发关闭事件，不把它当保存机制。浏览器清理数据可损失未同步内容，不宣称断网绝不丢稿。

6 · 登录安全与失败语义

建议同源安全 Cookie 会话（HttpOnly、Secure、适当 SameSite），写操作验证来源并采取 CSRF 防护；生产强制 HTTPS。验证码安全随机生成，只保存安全校验值，不能写日志，验证次数和发送次数都受限制。

邮箱格式与长度校验，去除首尾空白并规范域名；不擅自删除加号后缀或邮箱中的点。验证码绑定邮箱与用途，新码使旧码失效；并发验证只能成功消费一次。

邮件请求带幂等标识，控制同邮箱、来源 IP 和全局额度；队列延迟过长时不发送已过期验证码。邮件服务不可用时展示真实状态，不以开发日志输出代替送达。

错误类别用户处理
未登录／会话过期保存本机副本，提示重新登录；不自动清空编辑器。
无权限或不存在统一资源不可访问语义，避免泄露他人草稿存在性。
冲突进入冲突恢复流程，禁止自动强制覆盖。
限流／正文超限展示等待或大小限制，本地文字保留。
超时／服务异常明确未确认同步，保留请求标识和正文，允许重试。

7 · 数据边界（逻辑模型）

实体最低职责
账号／会话／验证码挑战账号唯一性、笔名、验证码消费与过期、会话撤销。
草稿所有者、标题、当前正文、当前修订、服务端更新时间。
保存修订与请求去重恢复快照、基础修订、mutation_id 及载荷摘要、保存结果。恢复记录不在普通管理员后台暴露正文。

已确认并实现：最近 24 小时保留每次保存，24 小时至 30 天按北京时间自然日保留最后一份；当前正文和独立恢复草稿不清理。历史快照不是公开作品版本，容量阈值、告警与授权恢复支持流程仍待验收。

9 · 验收场景

  1. 真实邮箱收码并登录；过期、错误、重复验证码均不能越权；邮件不可用有明确反馈。
  2. 写入、确认保存、关闭浏览器、重开后正文一致；应用重启后仍一致。
  3. 断网继续输入，显示仅本机暂存；恢复网络正确同步，联网重开可恢复本地待同步副本；完全断网启动不在保证范围。
  4. 提交成功但响应丢失，重试原请求只产生一次保存结果。
  5. 电脑和手机修改同一基础版本，后提交者遇到冲突，自动另存双方内容，可查看和导出；失败不虚报成功，重复请求不重复创建副本。
  6. 旧响应晚到、持续输入、多个标签页不能覆盖新内容或误显示全部已保存。
  7. 登录过期、存储配额不足、正文超限、数据库不可用均保留当前编辑内容并给出可执行提示。
  8. 账号 B 不能读取、保存或恢复账号 A 的草稿；退出及切换账号不暴露本地缓存。
  9. 备份恢复到独立环境，核对已保存正文及修订；记录恢复耗时和可恢复时间点。
  10. 真实电脑及手机验证输入法、粘贴、网络切换、后台再返回；浏览器自动化与后端并发测试覆盖关键不变量。

11 · 本轮确认与技术评审记录

  • A 支持草稿创建、重命名、保存和恢复，暂不提供删除与回收站。
  • 已打开页面断网可以继续写并本机暂存；联网重开恢复。暂不建设完整离线应用。
  • 退出直接保留本机草稿，无确认、无自动删除；自然过期同样保留。原账号重登自动同步；跨账号不转移。
  • 验收补充：退出后原账号能恢复，其他账号不能访问；多标签页恢复不重复另存；恢复期间的新输入不丢失；登录过期不打断输入。
  • 技术方向已确认：Go 模块化单体、MySQL／InnoDB、Nuxt＋Vue＋TypeScript、纯文本、IndexedDB。公开页面服务端渲染，Nuxt 不直连数据库，业务规则归 Go。
  • 通用能力采用成熟方案，把时间留给业务；保留显式 SQL、参数绑定、业务层事务。具体依赖与版本未核实冻结。Gin、sqlc 等仍是候选，不能写成最终选型。
  • 后续公开作品默认关闭搜索引擎收录，作者主动开启；站内公开和推荐分别管理。该能力不属于 A。

本节与更新后的正文替代早期“退出清理”“冲突手动另存”建议。具体参数仍为建议值，尚未实施。

12 · 实现准备：依赖基线与第一条业务链路

在成熟组件优先的原则下，默认采用以下组合；精确版本将在初始化工程时按兼容性选择并写入锁文件，不在本文虚构版本号。

用途默认选择
后端 HTTPGin；业务逻辑不依赖 HTTP 上下文。
数据库访问database/sql＋go-sql-driver/mysql；sqlc 生成显式 SQL 的类型化访问代码。
迁移goose＋版本化 SQL；MySQL DDL 不假定全部可事务回滚。

暂不引入Redis、独立消息队列、富文本编辑器、通用权限平台。

官方资料：sqlc MySQL 教程、goose、Dexie Vue 教程。已核实这些工具具有相应用途支持；尚未完成实际版本组合构建验证。sqlc 的 MySQL 代码生成支持不代表所有数据库分析特性都支持 MySQL。

首先实现的纵向链路

  1. 工程、MySQL 迁移与健康检查，具备真实部署入口。
  2. 邮箱验证码登录、会话与私密资源归属检查；测试邮件不能冒充真实送达验收。
  3. 创建草稿 → 带基础修订和请求 ID 保存 → 重新读取。
  4. 接入文本编辑及本机暂存，然后补冲突另存、原账号恢复及故障验收。

第一条链路完成标准：真实邮箱登录后写下文字，收到数据库保存确认，关闭重开可读；第二账号访问失败；重复保存不重复执行；过期修订不能覆盖新正文。此时不扩展发布、推荐或视觉装饰。
